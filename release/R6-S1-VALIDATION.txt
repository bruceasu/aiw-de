R6-S1 Fix1 - dependency readiness on late dependent creation
-----------------------------------------------------------
Observed user Maven/Failsafe failure:
- R6ResultHandoffIT.completedDependencyResultIsMaterializedAsDownstreamInput
- claimNext(reviewWorker) returned Optional.empty at line 77

Root cause:
- WorkTaskService.create() initialized every task with dependencies as BLOCKED.
- DependencyResolver refreshed dependents only when a predecessor completed.
- In the R6 handoff flow the Review task is created after the Implementation predecessor is already COMPLETED,
  so the completion event occurred before the dependency edge existed and the Review task remained BLOCKED forever.

Fix:
- persist the new task and dependency edges first;
- for dependent-task creation, lock predecessor rows in deterministic TaskId order;
- refresh the newly created task after edges exist;
- if all predecessors are already COMPLETED, transition BLOCKED -> READY immediately;
- predecessor locking closes the concurrent create-vs-complete lost-wakeup race.

Regression coverage:
- R3S1WorkTaskGraphIT.taskCreatedAfterDependencyCompletedStartsReady
- existing R6ResultHandoffIT exercises the same late-dependent flow plus result input materialization.
