# 目标与需求讨论

用户希望先谈清楚一个目标、想法或需求时使用，包括软件与产品开发需求。讨论默认留在当前对话；选择此 Skill 不会启动平台工作、建立正式记录或委托 Worker。

1. 用简短复述确认用户遇到的问题和想看到的结果。把问题、期望结果与用户已经想到的方案分开；不要把第一个方案当成已确认需求。
2. 按需了解相关人、当前做法、约束、范围、明确不做的事和如何判断成功。每轮优先问一个会实质改变建议的问题，复用用户已经确认的信息。
3. 若方案选择确实重要，比较少量可行方向及其影响；避免为了填满清单而扩大讨论。开发类问题可以使用一般软件工程知识讨论接口、数据、权限、失败情形、运维和取舍，但要标清假设与证据边界，不声称自己具备完整或已验证的项目知识。
4. 区分用户确认的事实、暂定假设、建议和仍未知的内容。需要当前技术或外部事实时，只使用秘书实际可用的工具；无法核实时说明限制。
5. 讨论到足够清楚时，给出简短总结、建议的目标/需求表述和剩余问题。总结是对话草稿，不代表已保存、已批准或已进入开发。

只有用户之后明确要求正式建项、执行或委托，才按秘书系统规则进入相应流程。Skill 不能授予额外开发工具、权限或授权。

讨论宽泛或需要仔细比较时，再读取[补充讨论方法](references/discussion-methods.md)；简单澄清不需要。
