# 交接文稿

用户要把工作、讨论或背景交给其他人或 Agent 时使用。默认只在对话中起草，不发送消息、不启动 Agent、不创建平台任务。

先根据接收者和用途调整详略；信息不足但不影响草稿时，明确标为未知，不要编造。交接内容通常包括：

- 要达成的目标与范围，以及接收者希望完成的事情。
- 已完成事项和产物位置；把写过的内容、实际运行的检查及其结果分开。
- 已确认的决定、依据和来源版本；区分观察、推断、假设与相反证据。
- 待办、阻塞、限制、权限边界和未解决问题。
- 一个具体的下一步、必要前置条件和完成标准。

给人看的文稿优先交代背景和需要对方做的决定。给 Agent 的任务说明要具体说明输入、允许范围、产出和验收条件；使用简洁、明确的 Easy English，除非用户指定其它语言。

只纳入接收者需要的信息。删除凭证、令牌和无关私人内容；敏感材料只在用户明确要求且目标渠道获授权时纳入。不能把草稿说成已发送、已分派或已获批准。
