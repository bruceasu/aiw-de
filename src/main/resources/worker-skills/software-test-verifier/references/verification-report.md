# Verification Report

## Metadata

**WP/Increment:** ID  
**Code baseline:** if known  
**Environment:** relevant environment/version  
**Disposition:** one defined disposition

## Requirement-to-verification matrix

| Requirement / AC | Verification method | Evidence | Status |
|---|---|---|---|
| AC-... | test/check | command/result reference | VERIFIED/FAILED/BLOCKED/INCONCLUSIVE/N/A |

## Executed checks

For each relevant command/check:

- name/command;
- scope;
- environment/dependencies;
- result;
- duration or scale only when relevant;
- observed failure summary if applicable.

## Findings

For each material failure:

### VERIFY-### — title
- **Root cause class:** class
- **Severity/impact:** concise assessment
- **Affected IDs:** AC/FR/NFR/WP/ADR
- **Observed behavior:** what happened
- **Expected behavior:** authoritative expectation
- **Evidence:** test/log/output/path
- **Routing:** owner/stage

## Unverified areas

List anything required but not proven, with reason.

## Regression assessment

State what broader behavior was checked and why the scope is sufficient or limited.

## Conclusion

Explain the chosen disposition in terms of acceptance evidence and unresolved blockers.
