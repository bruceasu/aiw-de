# Blockers

Record routine blockers in the owning FD's TODO or Verification. Use
%% NEEDS_INPUT: ... for an unresolved decision or missing evidence that blocks
work. Include the observed facts, actual attempts, unresolved cause or question,
and next action. Continue independent authorized work.

Update the note when resolved, preserving failed attempts that matter. Read
existing blocker notes and reports when resuming or before archive. An explicit
stage limit is a normal requested stop, not a blocker.

Write a separate feedback report only when requested, when a machine consumer
needs it, or when delivery recovery needs substantial evidence outside the FD.
Use the repository's blocker templates when applicable. A Dual evidence policy
or explicit repository requirement retains the Chinese Markdown plus JSON
sidecar contract. Otherwise a concise Markdown report is enough. Preserve
historical reports and links.

Do not edit a foreign/in-flight role's FD or receipts to add feedback. Save
separate evidence when ownership requires it. Feedback does not authorize
tests, retries, rule changes, recovery actions or gate overrides. Preserve the
actual delivery/cleanup state and report partial completion truthfully.
