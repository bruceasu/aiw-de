# Edit Article

Use when the assigned task asks to edit a supplied article, guide or document.
Do not rewrite unrelated prose or change product requirements through copy edits.
Keep the primary role, task, read-only setting, file scope and result contract.

## Establish the editing brief

Identify the source text, audience, purpose, desired tone, language and allowed
depth of change. Use explicit instructions first, then infer a restrained edit
from the text. Preserve the author's intended claim. If a material ambiguity
changes that claim or audience, use the existing question/gap path; routine
authorized wording changes do not need a separate approval for every section.

## Edit in a useful order

1. State the main point and the reader's required takeaway. Check that the opening
   makes the purpose clear and gives the context needed to understand it.
2. Map each paragraph's job. Arrange sections by logical dependency: establish
   necessary concepts and evidence before drawing conclusions that depend on
   them. Remove repeated arguments and move details next to the claim they support.
3. Within each paragraph, keep one coherent idea and connect each sentence to
   what came before. Split or combine paragraphs for readability and reasoning,
   not an arbitrary character limit.
4. Use concrete verbs, familiar terms and consistent names. Replace vague claims,
   unnecessary jargon and filler. Keep technical precision where the audience
   needs it; do not simplify away an important condition or uncertainty.
5. Preserve facts, quotations, citations and the difference between evidence and
   opinion. Flag doubtful facts or missing support. Correct substantive facts
   only when the task permits it and inspected evidence supports the change;
   never fabricate a statistic, citation or verification.
6. Read the revised flow against the original purpose. Check that edits did not
   change an obligation, remove a qualification or introduce a claim the author
   did not make. Match the requested formatting and length when feasible.

## Deliver the revision

Return the revised text in the primary output fields or save it to an explicitly
assigned writable path. In read-only tasks, provide the revision or suggested
edits in the report. For a partial source, edit that part and say which sections
were unavailable; do not invent a complete original article.

Include a short account of material structural or meaning-sensitive changes and
any unresolved factual question. Routine punctuation edits need no exhaustive
change log. If the requested format cannot hold the full revision, provide an
authorized artifact reference or report the format gap without breaking the
primary output schema.

Completion means the requested text is revised, its original purpose survives,
and material uncertainty is visible. Editing does not authorize publication,
external messages, new workflow records, repository-wide rewrites or a claim that
every fact was externally checked. Use only the tools and sources already allowed.
