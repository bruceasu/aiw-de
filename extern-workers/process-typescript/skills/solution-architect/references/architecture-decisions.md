# Architecture Decision Record Pattern

Use ADRs for consequential, difficult-to-reverse, or cross-cutting decisions.

## ADR-[NNN]: [Decision title]

**Proposal lifecycle:** PROPOSED | SUPERSEDES <ADR-ref>

Java Control Plane assigns durable revision status and baseline acceptance; do not claim an ADR is accepted from the Skill output alone.

**Drivers:** REQ/NFR/CONSTRAINT IDs

**Context**
Describe the forces and constraints that make a decision necessary.

**Decision**
State exactly what is being chosen.

**Alternatives considered**
For each meaningful alternative, summarize why it was not selected for this baseline.

**Tradeoffs**
State benefits and costs. Avoid claiming a universally superior choice.

**Consequences**
Include implementation, operations, security, data, testing, and future-change consequences where applicable.

**Risks and mitigations**
List concrete risks and controls.

**Reversibility**
Classify as easy, moderate, or costly to reverse and explain why.

**Traceability**
Reference affected architecture elements and source requirements.
