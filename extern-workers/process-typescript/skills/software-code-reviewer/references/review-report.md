# Code Review Report

## Review metadata

**WP:** `WP-...`  
**Change set:** branch/commit/PR if known  
**Disposition:** one of the defined dispositions

## Findings

Order by severity, then by dependency/impact.

For each finding:

### FINDING-### — concise title

- **Severity:** CRITICAL / HIGH / MEDIUM / LOW
- **Class:** finding class
- **Location:** file/module/component and line/range when available
- **Traceability:** FR/NFR/AC/ADR/WP IDs when relevant
- **Problem:** concrete defect/risk
- **Impact scenario:** how the issue manifests
- **Evidence:** code path, test gap, contract mismatch, or reproducible condition
- **Required correction:** what must change, without redesigning beyond reviewer authority
- **Routing:** Coding / Architecture / Requirements / Planning / Test

If there are no findings, state `No material findings identified`.

## Requirement and architecture conformance

Summarize whether the implementation remains within WP scope and accepted architecture.

## Test/evidence assessment

Summarize strengths and gaps in verification evidence.

## Nonblocking follow-ups

List only useful tracked items. Do not use this section to hide blocking defects.

## Review conclusion

State why the selected disposition follows from the unresolved findings.
