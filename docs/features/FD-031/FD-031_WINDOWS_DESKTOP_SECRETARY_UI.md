# FD-031: Windows desktop secretary UI

**Status:** Open
**Revision:** 4
**Priority:** Medium
**Evidence policy:** Dual

## Problem

用户希望在保留秘书 Web 页面的同时，增加可移动的女性桌面形象：点击进行私人文字对话，复杂工作安排、策略与目标确认通过窗口录入。用户已确认 Windows、2D 角色、拖动、文字聊天、弹窗与托盘菜单的第一版范围。

现有私人服务已经拥有工作、聊天、策略、精确目标预览及回执接口。原启动配对码只能使用一次，无法在不重启 Worker 的情况下为第二个独立界面登录。不得为了新增 UI 复制业务数据库、导入浏览器 Cookie、直接获取平台凭证或绕过既有授权确认。

## Options and decision

- 仅扩展浏览器页面：可复用现有组件，但不能提供本需求的 Windows 人物窗口与系统托盘入口。
- 带浏览器引擎的桌面壳：可复用 HTML，但需要额外运行环境和依赖，超出本轮不下载依赖的预算。
- 采用 Python Tk 窗口与 Windows 原生托盘适配：复用已有 Python 环境、私人服务及数据，窗口代码独立于 Worker，作为本轮实现准备方案。Python 安装需含 Tk。

角色采用内置 imagegen 工具生成的成年女性办公插画，PNG 随项目保存。首版使用单张站立形象和真实请求状态提示；不把拖动或状态文案描述为已完成多姿态动画。

## Solution

### 界面和服务边界

- desktop.py 拥有 Tk 窗口、工作选择、草稿表单、预览确认与状态展示；desktop_win32.py 只负责 Windows 窗口位置和托盘适配。
- desktop_client.py 只连接带显式端口的本机个人服务，复用 /api/work、chat、schedule、policy、goal-preview、goal-submit、goal-receipt、enable、state；不连接平台接口，不打开 SQLite。
- 客户端禁用环境代理和重定向，HTTPS 保持默认证书校验；Cookie 与 CSRF 仅保存在独立桌面进程内存中，私人状态展示移除 csrf。
- 所有服务请求在单次后台线程执行，以队列回到 Tk 主线程更新 UI；同一桌面界面每次只允许一个请求。服务现有锁、业务事务和调度规则不变。
- 人物支持拖动、就近屏幕工作区内边缘吸附、置顶、隐藏/恢复。托盘失败则禁用隐藏。退出 UI 不取消 Runtime、不启动另一 Worker、不自动启用动作申请；等待结果时退出明确提醒核对回执。

### 多界面配对

新增 POST /api/pairing，位于原有 Host、Origin、个人会话与 CSRF 校验之后。仅当前已登录界面的显式操作可生成 24 随机字节的 URL-safe 配对码，返回 code 和 expiresIn=300。新码替换上一枚未使用码，重置该枚码的五次尝试额度；使用仍走原 /api/login 的一次性校验。已有会话不撤销、不续期，原启动码与登录协议保持兼容。

Web 配对卡片使用独立 pairing.js。仅在用户显式生成时读取 /api/state 获得当前会话 CSRF，随后同源 POST /api/pairing；不依赖尚未提交的 Web 改版全局函数，不自动登录、生成或重试，不保存令牌。新增静态脚本路由与卡片内反馈可独立于 Web 改版交付。

Web 在“状态与备份”增加配对码生成、显式显示与复制。桌面“连接与设置”提供相同入口。配对码不进入 URL、日志、启动参数或本地配置，显示到期后清空；没有界面自动请求生成新码。

### 操作与失败恢复

- 工作按标题选择，重名时加本地序号区分；安排版本自动带入。聊天仍绑定私人工作，可显式创建“日常对话”。
- 工作安排继续使用私人版本与整分钟时间；策略载入和保存后确认框重置，已有策略标识锁定，禁止投影不从旧回执推测。
- 目标预览保留服务返回的精确 requestId/projectionJson/digest；修改来源使确认失效，异步预览返回时核对本地编辑版本。提交尝试后只允许查原 ID，不自动重试。
- POST 已返回但随后读取状态失败时保留结果和会话，明确提示刷新/核对，不把它当成未提交。连接失败、冲突或会话失效均不自动重放 POST。
- UI 快照以用户刷新或操作后读取为准，未实现推送同步；Web 仍提供完整资料、正式问题、备份和取消入口。

### 独立设计审阅的补充决策

- D031-01：安排表单在明确选择或重新载入工作时冻结私人记录 ID/revision/正文/Plan 引用/状态并展示。普通状态刷新仅检测版本或内容变化，不更新冻结版本；发现冲突后禁用安排确认，要求用户显式重新载入并核对。提交继续使用冻结版本，服务 CAS 仍负责拒绝提交与响应之间的并发修改。
- D031-02：原目标请求查询独立于新预览。通过现有 state.decisions 中 SELECTED_GOAL 记录提供历史选择，载入原 requestId 与状态/投影摘要用于查询；不从历史入口启用提交按钮。退出重开、重新配对或生成新预览后，仍可选择原 SENDING/UNKNOWN/RECORDED 请求，仅查询原回执。历史 PREVIEWED 也可查看，但不作为重发授权。
- 独立报告为 changes-needed，以上两项已由 Planner 采纳为明确实现要求，新增 1.6/1.7；最终实现 Reviewer 必须核对落实。没有将设计报告改写为通过。

6. 目标原文、摘要和请求 ID 完整保留；修改输入使旧预览失效，提交或超时后不自动换 ID 重发。重开/重配后可从持久决策找回原请求查询，历史选择不会更换当前待确认预览（1.2、1.4、1.7）。
7. 关闭窗口隐藏录入，退出桌面不停止后台 Worker；等待结果时提示后续核对（1.3、1.4）。
8. 新配对入口首次升级须重启服务，文档明确现有平台会话重新确认规则；后续重新配对 UI 无须重启 Worker（1.5）。
