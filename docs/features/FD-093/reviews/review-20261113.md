## 发现

### P2：草稿导入失败后，现有 Refresh 无法恢复，错误原因随后消失

位置：`src/main/resources/static/ui/workflows.js:161–162`、`:188–196`、Refresh 点击处理。

FD 覆盖生成结果校验、执行页面直达及前端错误处理，并要求无效模型结果保留原结果并报告原因。当前 `refreshRun()` 在调用导入 API 之前先写入 signature 与 importAttempted=true。若 read、library 或 definition 任一请求失败，后续轮询与用户点击 Refresh 均会因执行快照未变而直接返回；即使重新打开执行清掉 signature，importAttempted 也不会复位。

此外，在 library/definition 请求完成之前已经置 preparingGoal=null；因此草稿已经保存但后续查询暂时失败时，页面也丢失重试所需来源。下一次 `act(refreshRun)` 会先清掉错误提示，再因 signature 相同返回。结果是生成执行显示 COMPLETED，却没有进入草稿编辑器，原因也不再可见；用户只能整页重载恢复，页面提供的 Refresh 不起作用。

最小修正：让用户显式 Refresh 可重新读取同一来源的幂等草稿导入与 definition；成功取得并打开定义后才清除 preparingGoal、更新 URL。保留可见错误，避免通过自动轮询不断重试无效模型结果。不要重新提交生成任务或引入新状态框架。
