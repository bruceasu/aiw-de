建议：**changes-needed**。预算、后端/工具政策及 UNKNOWN 人工核对提案保持人工 Gate。候选稿诚实说明尚无新增实现，以下均为就绪合同缺口。

- **D029-01 / P1** — `真实工具许可边界`、工作项 2.1～2.5：真实适配器的执行主体、资源隔离和授权检查到实际启动的边界仍未固定。最小修正：针对选定后端列出可信 broker/适配器与非可信模型/项目代码的权限图，固定每次 beginOperation 的授权世代、Lease、参数摘要、单次操作 ID、资源预留和启动回执；说明撤销与开始的线性化点，不能让旧许可在撤销后开启新操作。文件操作需同一次实际访问上的根约束与链接逃逸保护。受控 Git 也可能经仓库配置、hooks、filters、fsmonitor、textconv/外部 diff、pager 等启动程序，须限定动词/参数、隔离配置/环境并禁用或受控处理这些入口。验证命令需要真实资源隔离，命令白名单和工作树不能充当隔离。不能执行安全边界的能力保持未广告/准备阻塞，不能以 permit API 存在代替实际 Runtime 消费。
- **D029-02 / P1** — `计量与未配置行为建议`、`幂等、恢复与 UNKNOWN`、工作项 3.1/3.2/4.1/4.2：账本原则已明确，预留、结算、失联和恢复的故障窗口仍缺封闭合同。最小修正：在用户确定计量政策后，固定各维度单位/精度、准入点和可预留上界；同一事务创建操作意图并预留，available=有效额度−已结算−在途预留，操作 ID 只结算一次。明确失败/取消何时可释放、UNKNOWN 如何保留预留/风险暴露，不能凭超时或丢回执自动归零。说明时间/成本限制是新工作准入限制还是执行硬上限、已在途如何收尾，并与暂停/撤权语义协调；无法承诺的资源测量继续显示 UNKNOWN。外部执行与 DB 不同事务的窗口要逐项列出可核对证据及人工处理结果，重启不能默认重做。
- **D029-03 / P1** — 工作项 5.1/5.2：当前把接合三个新 FD 作为本 FD 完成前提，可能与其消费者形成交付环。最小修正：029 先在既有任务/Runtime 入口独立交付并审查安全基础与实际适配器；027/028/026 各自拥有其新增接入和兼容验证，025 负责整体装配。先行交付不能削减 AC09 的实际调用拒绝、AC10 的可恢复或明确阻塞、AC11 的正式成果要求。
