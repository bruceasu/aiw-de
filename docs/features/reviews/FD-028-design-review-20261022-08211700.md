# FD-028 设计审查

<!-- aiw-data: FD-028-design-review-20261022-08211700.json -->

建议：**changes-needed**。隐私边界仍待用户决定；yield 和回答的安全落地合同还需收敛。

- **D028-01 / P1** — `问题与继续执行`、工作项 1.1/2.2：设计已要求安全收尾才释放槽位，但没有固定 task/attempt/Lease 从运行到等待、再继续的状态和确认原子性。最小修正：采用持久 YieldIntent（opId、task/attempt/Lease、问题来源键、固定 checkpoint/配置引用）；问题可先建 OPEN，但槽与 Lease 仍占用。027 确认该执行和子进程/工具已静止后提交幂等 yield-ack，由正式 execution 所有者 CAS 到专用“已 yield、等待输入”状态并释放 Lease，不能当 COMPLETED。早到回答先存，待安全 yield 且当前控制允许，才以来源问题+暂停任务+固定 checkpoint 创建唯一继续任务。无确认保持待确认/UNKNOWN；迟到 complete、重复 ack、回答与取消竞争有明确拒绝/保留事实规则。029 固定输入/意图原语、027 执行确认、028 问题、026 后续图推进各有唯一所有者。
- **D028-02 / P1** — `问题与继续执行`、`三渠道与身份`、工作项 1.3/3.3/3.4：人类优先与“不同答案拒绝”尚缺精确顺序，Telegram 解绑/重绑后的旧消息身份也未固定。最小修正：回答先以 questionId+requestVersion+渠道消息 ID 记入正式收件箱，定义 OPEN→ANSWERED 的 CAS 以及 APPLIED 的唯一消费者回执；APPLIED 前依既有委托规则决定人类覆盖代理的条件和审计，APPLIED 后只能创建新决定，不静默改写。Telegram 单问题 token 绑定 owner、user/chat、question/version、绑定 generation、到期；解绑原子递增 generation，旧 token 和排队消息失效；重复与冲突返回固定回执。不把普通聊天“可以”作为通用授权。

人工 Gate：私人数据最小投影提案继续等待用户明确确认。审查不允许上传更多上下文或启用真实委托。

交付边界建议：028 先基于既有 plan/task/attempt 独立交付，node executionId 为有验证的版本化可选扩展；026 再消费该服务，避免双方整体交付互锁。暂停中 ANSWERED 可以落库，但 APPLIED 不能绕过执行门禁。

证据范围：Revision 2 FD、相关 Issue 片段及问题/Telegram/运行协议静态搜索；未访问 Telegram、秘书私库、模型或数据库，未运行测试、编译、服务或进程。跨渠道和故障竞态未作运行验证；建议状态名称需与实际 execution 合同对齐。
