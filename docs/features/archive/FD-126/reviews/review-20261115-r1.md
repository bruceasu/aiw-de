## Findings

1. **Windows 缺少 Codex App Server 时，错误被降级为笼统提示。** [`windows_process.py`](../../../../workers/process-python/windows_process.py:22) 抛出 `CODEX_EXECUTABLE_UNAVAILABLE`；[`managed_worker.py`](../../../../workers/process-python/managed_worker.py:46) 将该异常码写入启动状态。Java [`ManagedWorkerProvisioner.java`](../../../../src/main/java/me/asu/aidev/execution/config/ManagedWorkerProvisioner.java:203) 只识别 `EXECUTABLE_NOT_FOUND`，所以该码落入默认提示“Worker 初始化检查未通过”，用户看不到缺少 Codex App Server 及应如何配置。FD-126 验收要求在没有 App Server 时明确显示本机适配器不可用。最小修正：在启动状态映射中识别 `CODEX_EXECUTABLE_UNAVAILABLE`，提示安装已支持的 App Server 可执行文件或设置 `AIW_CODEX_PATH`，并说明可改用已配置的外部 Worker。

2. **执行指南把 Linux cgroup 收尾说成跨平台通用行为。** [`EXECUTION-GUARD.md`](../../../EXECUTION-GUARD.md:69) 无条件声称命令进入专属 cgroup；第 71 行又称所有命令收尾都执行 `cgroup.kill` 并检查 `cgroup.events`。Windows 实现实际使用 Job Object。Linux/WSL 用户说明正确，但 Windows 部署说明与它冲突，可能让操作者错误判断 Windows 的隔离及停止机制。最小修正：将这两处限定为 Linux/WSL，并在 Windows 部分引用 Job Object 的终止和确认行为。
