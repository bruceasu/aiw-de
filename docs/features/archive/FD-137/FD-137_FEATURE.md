# FD-137: 按实际工具结果识别执行停滞

**Status:** Complete
**Revision:** 5
**Review policy:** Independent
**Priority:** Medium
**Evidence policy:** Markdown

## Problem

连续读取不同证据时，现有固定只读轮数仍会提醒停滞。相反，明确被拒绝的写入和反复失败的检查常常未进入重复计数，Worker 可消耗大量模型调用后才退出。

## Options and decision

以原有工具结果和补充输入判断重复。沿用先提醒、后退出的界限，避免额外的评分调用和计数层。

## Solution

移除固定的只读轮数提醒。Python OpenAI 兼容路径将同一读取结果、明确的工具拒绝、相同的命令失败和已确认收尾的 shell 超时纳入重复计数。工具拒绝使用已知错误码，命令失败与超时保留由宿主报告的状态、退出码、输出或完整结果摘要来区分变化。新的工具证据、已消费的人工补充，以及工具确认或可能产生的修改，按原机制中断重复计数。重放同一工具回执或更新自报清单不会算作进展。

连续重复证据达到现有阈值时，先提示用途和实际阻碍。提醒之后仍反复得到相同结果时，用 `MODEL_NO_PROGRESS` 结束。提醒区分读到相同内容和工具失败，诊断只记录工具名、次数和代码。真实效果不明的操作优先使用原中断流程；监控不主动执行、确认或重试工具。

任务声明必需检查时使用 FD-133 回执判断交付。全部必需检查已通过时，避免因最后一个可选命令非零退出再触发重复的自检提醒。普通任务继续使用已有交付提示。

## Scope

首期更新 Python OpenAI 兼容 Worker 的重复识别，受控 host-action 备选运行时同步移除固定只读轮数提示。保留 Worker 现有模型预算、审批、中断和人工重试。

## Acceptance

- 持续读到新信息时继续处理。相同读取、相同失败的写入或命令在提醒后继续重复时才有界退出。
- 失败输出变化或同一批最后得到新结果时不会因旧重复而退出。新人工补充重置判断且不重复累计历史。
- 自报工作清单不会使重复计数归零。未知结果继续核对现场，不自动重放。
- 必需检查仍由现有回执决定，工作流可区分提醒、停滞退出及原始操作失败。
