## Findings

### P1：把最终答复原文当作共享经验，没有生成可复用经验

`KnowledgeService.record` 将 `CompletionReport.summary` 原文存入共享经验表，`TeamMembers.materials` 随后将其标为 `Shared lesson` 注入后续任务。Python Worker 的 `_completion_report` 将完整最终答复直接作为 `summary`，因此实现只是跨成员复制交付结果，没有完成用户要求的“执行后总结可复用经验”。完整答复也可能携带任务中的私有事实或凭据，无法证明既有隐私边界得到保留。

**要求：** 每个完成任务应生成独立、简短的可复用经验字段；只持久化该字段。优先复用现有最终模型回合，避免每个任务额外增加模型调用。生成指引应排除私人事实、原始用户内容、凭据、路径和文件正文。

位置：`src/main/java/me/asu/aidev/knowledge/application/KnowledgeService.java`（首轮 `record` 写入）；`src/main/java/me/asu/aidev/worker/application/TeamMembers.java`（首轮共享资料注入）；`workers/process-python/process_worker.py`（首轮 `_completion_report`）。

### P2：REPAIR_REQUIRED 结果也被保存为共享 lesson，来源状态丢失

首轮写入逻辑只检查 report 是否为空，不检查其 `verdict`，并且记录未保存 verdict。`TaskExecutionService.complete` 允许常规任务携带 `REPAIR_REQUIRED` 完成，因此待修正结果也会被作为正向经验注入后续任务。

**要求：** 按 FD 的“成功完成”条件只共享 `PASS`；若确需保留修复经验，则必须保留 verdict，并在共享资料中明确标记其状态，不能以普通 lesson 呈现。

位置：`src/main/java/me/asu/aidev/knowledge/application/KnowledgeService.java`（首轮写入条件及字段）；`src/main/java/me/asu/aidev/execution/application/TaskExecutionService.java`（完成报告状态校验）。
