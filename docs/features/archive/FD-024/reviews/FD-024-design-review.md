## 草案仍需补充的必要约束

### F1（高）：明确不可逆副作用出现、平台事务未提交时的未知结果处理

位置：Solution 3 的“同一平台事务”、Solution 4 的 outbox/重试描述；Work 1.3、3.2；AC4。

草案正确区分“已准入”和“运行完成”，也说明回执不代表文件副作用回滚。但目前只覆盖“平台成功后响应丢失”等窗口，没有约束**动作已对文件系统等产生副作用，但平台业务事务/回执提交失败**的窗口。单靠同一 requestId 和数据库事务不能证明此时重试安全，且“最多一份动作/消费”的验收可能被误读为任意外部效果恰好一次。

建议在本 FD 先明确底线：固定适配器逐项标注纯数据库变更、任务准入及不可逆副作用；后者必须有可持久识别的执行意图/效果证据或进入 UNKNOWN/NEEDS_HUMAN 对账状态。无法确认效果的请求不得自动重新执行、自动返还额度或换 ID 重试。1.3 的故障窗口表必须包含“效果发生后、业务提交前”和“事务回滚后效果仍在”，3.2 不能把所有既有适配器视为天然同事务原子。实际状态名和实现留给 G2 冻结。

### F2（中）：幂等域不能依赖可被替换的授权 ID

位置：Solution 3 的“平台+稳定 owner/授权身份+requestId”；Work 1.2；AC4、AC7。

“owner/授权身份”尚有歧义：若实现将 grant ID/版本纳入隔离域，重新授权后同一 outbox requestId 可以绕过原回执。预算不清零不能替代动作级去重，尤其是多个额度尚有余额或不限轮数动作。

建议明确：动作幂等命名空间由平台与稳定主体/请求发起逻辑身份决定，不能因授权 ID/版本、Worker ID、凭证、实例或重启变化而创建新的去重空间；这些字段是需校验的请求内容/权限事实。已存在请求在撤权后应允许按限定读取权限取回历史回执，而不得执行旧请求；查询不等于重新授权。具体键结构仍由 G2 定义。

## 已合理列为 Gate 的问题

- **G1** 已正确阻止猜测 owner、真实迁移、切换和清理，并保留原库、在途/未结算预算、固定发布 attempt 和回退限制。实际源库、人工归属和切换窗口尚未知属于真实未决项，不应由评审猜答。
- **G2** 已明确私有 DENY 与平台有效授权如何收窄/同步尚未冻结。这是权限语义的实质决策：仅“停止本地新建议”不足以撤销已经发送但未生效的请求。后续必须定义确认时点、平台可验证的收窄版本以及离线行为，且保留原有 DENY 优先/显式 supersedes 语义；当前保持 gated 是正确的。
- **G3** 已覆盖浏览器到私有 UI 的身份、跨源和旧路由迁移，明确不信任 localhost、不共享平台 session 库。尚无具体交互协议不是当前草案遗漏，只要不将 4.4 提前标为 ready。
- 完整多人账户系统明确不在本 FD 范围；“一个已认证 owner”仍应在 1.2/3.1 写成真正可验证的准入前提，不能将本地 actor 文本当多人隔离证据。
