# FD-022：旧管理写入接口的认证兼容决定

<!-- aiw-data: FD-022-blocker-auth-contract-20261021-01.json -->

状态：**已解决（仅兼容政策决定）**。实现仍须编译和独立评审，不代表运行时通过。

阶段/角色：Worker；来源事件：`FD-022-000003-design-ready`。

事实：静态读取 `ApprovalController` 发现旧 `/api/r7/approvals/{id}/decision`
直接信任请求体 `decidedBy`，未检查人工登录。只保护新代理入口不能封闭这个
旧人工身份冒充通道。未调用任何 API，也未进行越权运行实验。

处理：向用户说明公共 API 兼容影响并提出两个具体选项。用户于
2026-10-21 明确选择“启用代理时，同步收紧旧管理写入 API 的认证（推荐）”。
此前没有重复执行失败命令、扩大网络权限或绕过 Gate。

决定：首次明确启用代理时持久开启旧管理写入认证。要求启用人工控制台登录，
检查会话、CSRF 和当前角色；已验证会话替换旧请求中的操作者身份字段。
既有 Worker 领取、心跳和租约上报保留机器入口；Drain/Offline 属于管理写入。
关闭代理或重启不静默撤回这项 API 认证兼容变更。新实例在从未启用代理时保持
旧 API 行为。

剩余工作：对新增认证边界做有界独立设计反馈，完成编译和全 FD 独立实现评审。
未执行测试、服务、迁移、浏览器或网络请求；不据此声称这些检查通过。

可复用改进：代理权限设计必须枚举现有管理写入口，不能仅审查新增入口。
仓库缺少技能指定的两个 BLOCKER_FEEDBACK 模板；本记录按技能明确要求的
事实、来源、恢复、决定、状态和改进字段编写，未声称使用不存在的模板。
