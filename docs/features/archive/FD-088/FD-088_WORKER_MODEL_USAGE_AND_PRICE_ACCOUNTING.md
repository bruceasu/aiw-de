# FD-088: Worker model usage and price accounting

**Status:** Complete
**Revision:** 10
**Review policy:** Independent
**Priority:** Medium
**Evidence policy:** Markdown

## Problem

Worker 用量和费用仅在部分受控执行中可见，普通任务难以按请求追溯成本。现有价格与预算绑定，不能覆盖新模型、变价、缺价回填和订阅连接。服务商页面更新后，采集器需要及时恢复。

## Options and decision

建立独立的请求用量与内部价格账本，保留既有受控结算和人工核对。采集器独立版本化，后台刷新；失败保留已验证版本。价格未知不阻塞记录，通过可追溯的幂等回填补充估算。自动修复由 Worker 提交候选；Plane 管理员每次先审阅确切候选源码和对应的官方页面快照，再明确批准一次运行。候选按 Plane 进程账户权限运行；Plane 与 Worker 同机，更新本机模块前校验旧版本并保留备份。

## Solution

具体协议、数据及失败处理见 [用量和价格设计](../../WORKER-USAGE-AND-PRICING-DESIGN.md)。本 FD 为实施状态和 Work Items 的权威来源。

- 每次模型调用记录稳定请求 ID、attempt、时间、提供方、模型、连接类别、用量和未知状态；完整保留已知部分，跨重试幂等。
- 内部价格表支持币种、模型、输入／缓存／输出及服务档位、时间窗口和版本。价格计算是估算，不能伪造服务商实际账单。
- Plane 启动后异步刷新一次，此后每日刷新；各来源隔离、校验后原子发布，网络或解析失败保留旧记录。缺价待补，不将未知记为零。
- 判断来源结构改变后创建去重 Worker 修复任务；Worker 核对官方来源并修改独立采集器。Plane 展示候选源码和已保存的对应页面，管理员审阅后按候选与页面摘要批准一次运行；页面或候选发生变化时原批准失效。未经批准不执行候选。验证成功后在本机原子替换，后续采集进程读取新版本。临时网络问题不得触发修复风暴。
- 任务和 Plan 页面展示用量与估算；预算默认仅记录，后续在本 FD 内提供明确可选的预算提醒和控制，不改变历史结算值。

## Scope

OpenAI 和 DeepSeek API Worker 及 Plane；Codex app-server 不可见的用量标记未知。ChatGPT 订阅不按 API 单价表示账单。其他供应商通过适配器扩展，不推断自定义模型的价格。保留先前 Worker 循环和侧栏未提交修改，不把它们作为本 FD 的交付内容。

## Acceptance

同一请求重复上报不重复累计；失败、未知和部分用量不被记为零。价格时间条件及版本可追溯，缺价可按有依据的历史价格回填，参考估算有标记，订阅不被当作 API 实际账单。更新失败不阻止 Plane 或任务；结构变化时仅有一个对应修复任务。候选源码和确切页面快照须经 Plane Owner 审阅，并以摘要绑定一次明确批准；未批准或材料变化时绝不执行，失败重跑须重新审阅批准。候选仍以 Plane 进程账户权限运行，不视为 OS 沙箱；页面清楚说明此风险。用户能在执行与 Plan 视图理解成本覆盖情况与限额状态。
