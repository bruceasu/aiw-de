## 发现

### P1 — 管理员审批和候选执行使用的是旧失败页面，不是 Worker 核对的最新页面

已确认的验收要求是用最新官方页面核对实际价格条件，旧样本仅作诊断。修复任务提示 Worker 获取最新页面并报告 URL 和摘要（`ModelPriceRepairDispatch.java:21-28`），但提交接口 `ModelPriceRepairResults.Submission` 不包含 Worker 获取的页面快照（`ModelPriceRepairResults.java:22-23`）。审阅服务从 `model_price_collection_failure.sample_base64` 提供页面，批准时也保存同一字段（`ModelPriceRepairReview.java:24,134,169-172`）；执行时再把该已批准快照传给候选解析器（`ModelPriceRepairActivation.java:129-143`）。

因此，Worker 即使按要求核对并报告了更新后的官方页面，Plane 也没有保存或展示该页面。管理员实际批准、候选实际解析的仍是内置采集器首次发现结构变化时保存的旧样本。这不能满足“管理员审阅并批准最新页面”的验收，也可能把只适配旧页面的采集器安装到后续定时采集中。

**需要：** 将 Worker 实际核对的页面快照、来源 URL、观察时间和摘要一并交付并持久化；审阅页面应展示该快照，批准绑定其摘要，且候选验证应解析同一快照。旧失败样本继续只作为诊断材料。
