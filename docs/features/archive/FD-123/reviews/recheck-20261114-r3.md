## 结果

未发现该 P2 修复及其直接调用路径仍有缺陷。

- 预览阶段的 `structuralCandidate` 与应用阶段都调用
  `workflowTaskSlot(run.spec, node)`。该函数构造相同的 `WorkflowPlanSpec.Step`，
  因而使用同一条完整指令长度校验；超出 16,384 字符时构造失败。
- `proposalView` 捕获该 `IllegalArgumentException` 并返回 `INVALID`，不会显示
  `READY`。`decideProposal` 在 Plan 追加和 Run 修改之前要求状态为 `READY`，
  因此无效候选不会改变 Plan 或 Run。
- Plan 追加仍有版本条件更新；失败会抛出异常。它与 Run 更新处于确认操作的事务中。
- 首次追加时，旧 Run 的空 `planSourceDigest` 从 Owner 现有的 `source_digest`
  固定到 Run；追加不会改写 Owner 的 source pin。`NativePlanOwners` 随后读取 Run
  保存的初始 digest。
