## 必须纳入的设计约束

### D1 P1：逐动作确定 TASK/PLAN/ALL 范围兼容性，保留精确来源

事实依据：

- AuthorityActions.java:70-108：A01-A04 以 Plan+step 为目标；A02 更改整个 step 的模型约束
- AuthorityActions.java:301-353：A05/A06 操作整个 Plan，A01/A03/A04 从当前恢复/重试任务衍生操作
- PersonalQuestions.java:35-36：问题 Envelope 禁止 taskId/step，问题来源保存在 Projection/Question
- FormalQuestions.java:63-77：来源可能为现有 task 或 workflow graph execution

收敛要求：列兼容矩阵；仅能核对精确来源/影响边界的动作接受 TASK，A01/A03/A04/A11/A12/A19 还需分别核对恢复源、重试源、审批源、成果源或问题源；不能以同 step、同 Plan 或同仓库代替精确 task。A02、A05-A10、A13-A17 等整体对象动作拒绝不适用的 TASK；Fleet/Worker 也拒绝 PLAN。TASK 对无 taskId 的 graph 问题不得猜测来源。父子记录独立保存 sourceTask/question，不能破坏旧 Envelope 固定尝试语义。

### D2 P1：覆盖隐式发布消费与协调启动的平行受理路径

事实依据：

- AuthorityActions.java:383-395：requirePublicationAuthority 从另一 A12_EXECUTE Grant 隐式 consume，调用者包括 A01/A03/A05/A06
- CoordinationService.java:57-89：advance 使用独立托管记录，sourceTask 为 null 时直接 plans.confirm，未经过 ActionAdmissionService
- AuthorityTaskPolicy.java:51-69,96-105：普通任务及发布 Claim 检查当前 Grant；selection/guidance 另有模型 Grant 消费

收敛要求：新 A05 权限期存在时，/coordination START 必须转入同一父权限固定/计数或明确拒绝并要求新路径；不得旁路确认。后续正常托管推进与新的 confirm/repair/retry 分清。隐式 A12 执行需在同事务内核对其自己的当前父权限、范围和硬计数，以原 requestId+父权限/action 去重；不把 request=null 的旧预算消费当作父计数。所有旧 Grant 消费/Claim/模型/发布校验识别父映射或已被替代的 legacy 期，不能靠隐藏调用续用。

### D3 P1：新问答路径和回执需要专用最小读取核对，不能扩大通用 read_scope

事实依据：

- AuthorityActions.java:155-205,231-239：snapshot 包含 Plan spec、所有任务 instruction/report 及审批/发布来源信息
- PersonalQuestions.java:31-46：submit 在原投影写入前调用 readable(PLAN)，继而调用原 admission；validateEnvelope 逐字段核对完整 Envelope
- PersonalQuestions.java:48-54：已选投影还绑定 instance/platformBoot/workerGeneration/workerBoot
- ActionAdmissionService.java:74-78：receipt 目前按 Owner 查找并经通用 read_scope，不检查原 worker_id
- ExecutionGuard.java:73-77：A18/A19 目标判断依赖 boundary.delegated()/principal

收敛要求：固定阶段置于 boundary.as(principal) 的鉴权上下文，完整 snapshot 只用于服务端 digest；机器只得到原 Envelope 和动作必要摘要。新问题请求保存原 projectionJson/digest/question/source/Envelope；仅存在可信父子映射且同 Owner+Worker、精确来源的请求可走专用问题核对，旧 submit/list/state 保持旧 read_scope。A19 继续原 question-replies/正式投影，不能绕过用户确认或加入私人内容。原回执查询可在身份重新启用后按 instance+Owner+原 Worker+requestId 核对原记录，不依赖父有效性或当前 read_scope，也不能返回当前快照；其它 Worker 不可借 requestId 查询。

### D4 P1：区分已受理子能力有效性与新操作剩余额度

事实依据：

- ActionAdmissionService.java:141-149：成功受理先消费再绑定 permit、返回 ADMITTED
- AuthorityTaskPolicy.java:51-54,96-105：执行 Claim/发布要求 grants.current
- AuthorityBudgets.java:64-72：旧 A01 settle 在执行前取消时可释放旧 used_value

收敛要求：parentActive 检查授权期/角色/撤销/到期/替代，parentAdmissible 在 active 基础上追加剩余额度及原子扣次。不得将 used==limit 放入所有子 Grant 的 current，否则最后一次 ADMITTED 将无法 Claim。已受理的最后一次操作可按原 permit 开始；新请求拒绝。父计数只随唯一成功受理增加，不由旧预算 settle、取消、后续失败、查询或 Claim 减少/增加。

### D5 P1：把 Owner 证明链和冲突失败策略写成可实现契约

事实依据：

- AuthorityGrantService.java:128-132：旧 bindTarget 仅首次插入/核对 authority_target.owner，不检查 Plan creator
- CoordinationService.java:28-33：显式托管检查 Plan.createdBy 或已关联发布目标
- ExecutionGuard.java:82-87：policy 创建分别核对已有 authority_target、graph Owner、Plan creator
- V1__initial_schema.sql:9-54：普通 worker/work_task 没有 Owner 列；V12__execution_guard.sql:2-17：execution_policy/context 提供正式归属
- TaskOutputService.java:254-270：发布从 file→bundle.taskId 生成 Plan，createdBy 可能是 personal actor

收敛要求：定义公共 Owner resolver：Plan creator→绑定 actor、execution_policy/context、审批 source task、发布 file→bundle source task及正式发布关联分别核对；多个正式事实冲突时拒绝，不选择宽松来源。对已有 delegated publication 用正式来源+authority_publication_plan/target 关联证明，不能仅看 personal actor 字符串。无可证明任务来源拒绝；不以 repository 认领。无天然 Owner 的 GLOBAL:FLEET/普通 Worker 仅用现有人类确认的 authority_target，机器不得首次绑定；页面说明尚无归属时需人类先处理，而不是把授权表单变回手填内部协议。


## 已合理的设计与实施边界

新增父权限而不在旧精确 target 塞通配符、显式替代权限期并保留历史、固定不计数而在原业务事务计数、未知结果保留原 requestId/Envelope，这些决定与现有代码契约一致。计数属于本次用户明确要求的动作能力上限，不应受 FD-032 record-only 控制。

新增迁移需明确权限期、固定候选、父子关联和唯一计数的键/索引，不推断历史 Owner，不重写旧迁移。新增路由需同步进入 Java AuthorityHttpConfiguration 与 Python platform_client 的封闭映射。固定阶段仍须当前机器身份和 process boot；人类管理仍须当前角色、Owner、CSRF。

Worker 在任何可能送达固定请求的调用之前持久化原 requestId 和选择；未知响应只核对或重试同一对象，取得完整原 Envelope 后才送原 outbox，不覆盖原 outbox 不可变 body。人类创建/替代权限发生未知写响应也须保留原 requestId/expectedPriorId，不通过再次创建权限期隐式归零。

Work Item 1.3 当前合并多个独立机制，应按 Owner/scope 解析、候选固定、硬计数及旧路径兼容、Worker 原请求恢复等结果拆分，并为每项给出依赖和完成证据。UI 与说明独立交付，保留旧协议与其它并发改动。
