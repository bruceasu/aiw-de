## P1：普通重登录/导入替换及失败路径遗留可用令牌文件

Python `Credentials.save` 每次 exchange/import 都写一个新的 READY 文件。`ModelConnections.save` 成功替换 prior 时只更新数据库 credential_file，没有退役 prior 引用；保存失败（例如 label、Owner/身份或 CAS 冲突）也没有清理本次 issued 文件。`OpenAiLogin.callback` 在 exchange 返回后若认证状态已取消/失效，也只标失败，不清该文件。

可复现路径：连接使用文件 A，用户为同一连接显式重登录或导入新令牌，数据库改为 B。A 仍是 READY 并保留 access/refresh/id token。之后 disconnect 或 resetLocalStorage 仅处理数据库当前引用 B，A 不在清理集合中，仍留在凭据目录；与原数据库密文被覆盖/清空不同。这是本轮文件持久化引入的实际生命周期遗漏，不涉及已下载备份或额外安全架构。

最低修复：成功提交替换后退役旧引用；本次新文件未被数据库采用或回调被取消/失败时，清除未采用文件的令牌内容。清理须区分“已提交的新引用”与“未提交文件”，不要在旧文件清理失败后误删已提交的新文件。保留原 CAS 和未知刷新不重发策略即可。
