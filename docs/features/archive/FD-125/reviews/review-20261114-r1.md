## 发现

1. **版本 0 并非不可变历史。** [`TeamMembers.java:78-99`](../../../../src/main/java/me/asu/aidev/worker/application/TeamMembers.java) 的 `skillHistory` 和 `skillVersion(0)` 每次都从当前部署的 `SkillFiles.defaultText(ref)` 重建基线；V53 只保存大于 0 的版本。内置 Skill 更新后，版本 0 内容与摘要会改变，恢复版本 0 也会恢复到新内容，无法还原成员最初使用的文本。应在成员首次使用或首次修订时保存基线内容及摘要，并始终从持久记录读取。

2. **秘书讨论任务没有使用或保存成员 Skill 修订。** [`GoalDiscussionService.java:140`](../../../../src/main/java/me/asu/aidev/goal/application/GoalDiscussionService.java) 为讨论任务调用 `team.attachSkills(requestId, member.skills())`，而该路径只绑定内置文本。新修订仅在 [`TeamMembers.bind`](../../../../src/main/java/me/asu/aidev/worker/application/TeamMembers.java)（line 357）中注入；完成写入 [`TeamMembers.recordSkillUpdate`](../../../../src/main/java/me/asu/aidev/worker/application/TeamMembers.java)（line 116）也只查 `worker_team_task` / `worker_team_assignment`，讨论任务通过 `goal_request.frozen_json` 关联成员，因此更新会直接跳过。Agent Factory 成员被用于许愿池讨论时，其更新不会沉淀，之后的讨论也拿不到新版本；FD 未将此类成员任务排除。应让讨论任务使用成员最新修订，并从其冻结成员记录验证和保存回执；若目标只限 Plan Worker，则需在 FD 明确缩小验收范围。

3. **完成元数据示例可能把提示语当作共享经验保存。** [`process_worker.py:613-617`](../../../../workers/process-python/process_worker.py) 给 `experience` 的 JSON 示例填入字面占位语“Up to three brief reusable lessons, or NONE”，但只明确要求替换 `skill_update`。解析器会把任何非 `NONE` 的字符串保存为经验，因此模型照抄模板时会污染共享经验资料。应明确要求把该字段替换为真实通用经验或精确字符串 `NONE`。
