## 发现

1. **中：LOCAL 代理绕过条件会改变 HTTPS REMOTE 的既有代理行为。** 本次 event revision 7 的实现把 `allow_loopback_http` 原样传给 `PlatformClient._transport(..., direct=...)`（`personal-secretary/platform_client.py`）；但构造器对 HTTPS 不受该 flag 限制，HTTPS 目标会被识别为 `REMOTE`，同时该 flag 仍会安装空 `ProxyHandler`。`personal-secretary/main.py` 在连接档案为默认/LOCAL 且传入 `--allow-loopback-http` 时，会把 flag 传入客户端；若该次启动目标是 `https://...` 且有 REMOTE 客户端证书，HTTPS REMOTE 请求也会绕过环境代理。此行为违反 FD 所述 REMOTE 继续保留既有代理行为，并可能绕过部署要求的 egress proxy。

   **最小修正：** 只在 `allow_loopback_http` 为真、scheme 为 `http` 且 host 是明确 loopback 地址时设置 `direct=True`；HTTPS REMOTE 不论该 CLI flag 如何取值，都使用原默认 opener。当前工作区已在本 Reviewer 发出 finding 后将条件收窄为上述三项，但这个 post-claim 修改不属于本事件审查快照；须由新的 implementation-ready 事件交付后再作通过判断。
