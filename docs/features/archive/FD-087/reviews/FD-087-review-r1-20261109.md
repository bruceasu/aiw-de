## 发现

1. **中：Control Plane 重启后，同一 Secretary 进程不能自动恢复 LOCAL 会话。** 在本次最初检查的实现中，`AuthorityGrantService.session()` 仅在 Agent 的 `worker_boot` 变化时更新 `enabled_boot`；Plane 重启只会改变平台 `AuthorityBoundary.boot`。Secretary 的 `PlatformSetup.check()` 仅在本地 `session_started` 为 false 时 POST `/sessions`。因此 Plane 恢复后，如果 `/connection-state` 正常返回但 `enabled=false`，Secretary 会保留 `session_started=true`，不会发起新会话，LOCAL Plan/Task 操作持续被禁用，界面会提示人工启用。只有重启 Secretary 或先遇到传输错误、再执行状态检查才会恢复。此行为不满足当时 Verification 所述的重连行为，也与 LOCAL 会话自动启用要求不一致。

   **最小修正：** LOCAL 查询发现 Agent 已批准但当前进程禁用时，最多重新 POST 一次 `/sessions` 并刷新状态；服务端仅当 `enabled_boot` 非空但属于旧 Plane boot 时，才为同一 Agent boot 恢复当前平台 boot。保留 `enabled_boot=NULL` 的人工禁用状态，REMOTE 继续要求人工启用。

2. **高：LOCAL 登记请求可能把 Agent 凭据发送给环境代理。** `PlatformClient.register_local()` 和 LOCAL 配对/连接在本次最初检查的实现中使用默认 `urllib.request.build_opener()`，未禁用 `HTTP_PROXY`/系统代理。若代理配置未排除 loopback，登记请求会经代理发出；请求体含持久化的 Agent ID 和高熵 credential，而 LOCAL 使用明文 HTTP。代理可以读取并保存该凭据，破坏 LOCAL 凭据只发往本机 Plane 的边界。

   **最小修正：** 对明确的 LOCAL HTTP 请求（登记、LOCAL 配对和 LOCAL Agent 请求）使用 `urllib.request.ProxyHandler({})` 禁用代理；REMOTE 传输继续使用现有代理行为。
