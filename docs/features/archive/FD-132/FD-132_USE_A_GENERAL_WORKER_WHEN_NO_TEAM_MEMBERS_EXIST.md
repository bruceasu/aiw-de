# FD-132 无团队成员时使用通用 Worker

**Status:** Complete
**Revision:** 5
**Review policy:** Independent
**Priority:** Medium
**Evidence policy:** Markdown

## Problem

默认自动分配在空团队中停在等待成员，未创建 Worker 可领取的任务。成员创建成功但列表刷新失败时，页面也可能只显示刷新错误。

## Solution

自动分配检测到当前账号没有可用目录记录（不计已解散成员）时，沿用已有通用派发。显式指定成员、团队非空但缺少 Skills 或匹配成员暂停，仍按原规则处理。通用文字 Worker 接受工作流提交时固定的额外 Skill 包。页面区分保存中、保存成功、保存已确认但列表刷新失败，以及请求结果待查。

Worker 复用现有执行循环。开工时明确结果和验证办法，工具结果决定下一步。可写任务连续四轮仅执行读取时，在已有活动记录中提示一次，保留原有重复读取判定。模型准备报告成功但最后一次命令未通过时，提醒核对检查是否必要。两类提醒均不代替用户授权或自动重试。秘书在委派时交代结果、限制和完成条件，遇到会改变工作范围的关键缺项先提问。

普通目录直接使用文件工具。创建使用 `write`，已有文件使用绑定摘要的 `edit` 或 `edit_many`。Worker 把可处理的工具错误交回模型，保留效果未知的操作以便核对。模型调用用尽前预留一轮生成实际交付报告。任务页直接打开当前中断的核对和重试入口。

工作流时间线保留步骤报告。直接前序结果走正式交接，更早结果提供有界摘录。Python OpenAI 兼容执行可按需读取已校验的完整交接报告。

## Acceptance

空团队下自动任务应产生 Worker 可领取的任务，所选 Skills 随任务绑定。有团队但暂时无匹配成员时仍解释等待原因。成员保存获得成功响应后，列表刷新失败不覆盖保存事实。

从任务详情重试失败任务时，同步恢复所属工作流的执行状态。调度扫描也会接续已经确认重试、任务已就绪但工作流仍为失败的记录。原执行尝试和结果会保留。

中断后可从工作流或任务详情打开停止确认，并预选当前执行。Plane 能找到与此次尝试对应的本机 Worker 退出记录时，会带入证据路径和摘要。Owner 核对并确认停止后，可在同一页面重试当前步骤。

模型误用创建工具覆盖已有文件时，返回可纠正的失败。已有文件多处修改共享一个文件版本，原文片段都匹配才一次写入。工作流结果累积不占用用户补充的容量，直接前序报告不在派发正文中重复追加。
