## 发现

**P1：已选成员停接单后，简单任务提交会静默丢失成员归属。** `workflows.js` 的 memberOptions 将非 ACTIVE 成员的 option 标记 disabled，同时保留原选项为 selected；简单任务提交却通过 `new FormData(form).get('memberId')` 获取身份。HTML 表单不会提交 disabled 选项，因此用户先选择成员、该成员随后停止接单、目录刷新保留原选择时，提交得到 null，按“未指定成员”启动任务。服务端 forRun 对非 ACTIVE 成员的拒绝被绕过，违背不能自动改派/清空成员和停接单控制的要求。

最小修正：从成员 select.value 显式取得保留 ID 并提交，或明确拒绝该不可用选择；继续由服务端 forRun 检查归属和 ACTIVE，不能改成默认不指定成员。节点编辑路径直接保留 node.memberId，不依赖 FormData，不受此问题影响。目录失败/未知 ID 时同样保持原 ID，不自动改派。
