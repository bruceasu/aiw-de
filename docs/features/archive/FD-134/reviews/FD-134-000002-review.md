## 发现

1. **P1 · 暂停后仍可抢占工作区。** 受控 Python Worker 在准备目录前打开运行通道。等待目录锁时通道没有活动操作，暂停可被确认应用。`DirectoryLock` 每次重试只检查尝试是否取消，原持有者释放后，已暂停的 Worker 会开始占锁，并在第一个受控 Git 或模型操作处等待继续。此时其他任务仍不能使用该目录。让每次短暂的尝试获取及回收锁遵循现有通道准入，并在等待重试时释放通道活动计数。[通道开启](../../../../workers/process-python/process_worker.py#L595) · [暂停回执](../../../../workers/process-python/run_channel.py#L93) · [工作区锁](../../../../workers/process-python/plan_workspace.py#L34)
2. **P2 · 提交阶段的陈旧连接没有提示。** FD 要求连接延迟时明确显示执行状态待核对。`taskProgress` 仅在 `stage` 为空时补上延迟文案。进入 `FINALIZING` 后即使失联，任务详情仍只显示「正在提交任务结果」及最后联系时间。保留已经确认的停止或暂停阶段，同时单独向页面传递陈旧状态。[阶段投影](../../../../src/main/java/me/asu/aidev/execution/run/ExecutionRuns.java#L232) · [任务详情](../../../../src/main/resources/templates/ui/plan-task-detail.html#L15)
