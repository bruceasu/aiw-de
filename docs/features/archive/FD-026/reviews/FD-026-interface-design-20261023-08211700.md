# FD-026 实施接口独立设计反馈

<!-- aiw-data: FD-026-interface-design-20261023-08211700.json -->

建议：**changes-needed**。新增细化已正确复用实际依赖、限制活跃范围修改，并明确单一问题消费者；以下三项仍须写成确定的工程合同。它们是尚未实现图引擎的设计就绪问题，不是现存实现缺陷，也不重开已确认政策或此前五 FD 设计。

1. **I026-01 / P1：祖先循环回跳与父汇合之间缺少明确的出口槽生命周期。** 位置：FD 第 101～102 行及代表场景；相邻 `ExecutionLedger.backjump`。设计既要求父成员绑定具体 activation/iteration/execution，又允许子范围回到祖先循环并创建新 iteration；未明确父 join 如何停止等待旧轮成员、等待最终有效轮出口，以及旧轮如何关闭而不伪造成功/未选。若父成员永远固定第一轮，则不能汇合；若直接查询最新轮，则失去固定来源和并发约束。

   最小合同：编译时将 entry、next、条件子范围、子范围 join 和前向 goto 归一为明确的潜在选择来源，入口有合成来源；dependsOn 是固定数据门禁，不能拿“依赖失败”改写 TAKEN。父 join 对每个必要子范围绑定稳定的逻辑出口槽；循环 activation ID 保持稳定，每轮的实际出口成员及结果保持不可变。回跳事务验证触发 goto/旧轮/目标循环、等待该循环所有实际任务已终态且无 UNKNOWN，在同笔 ledger.backjump 与新 iteration 创建中，将旧轮记为非成功的 CLOSED_BY_BACKJUMP（或等价 REPEATED/TRANSFERRED）并将逻辑出口的待定轮次指向新轮；父 join 持久保持 WAITING，旧失败成员不改 NOT_SELECTED，也不对父 join 发送成功或跳过。触发回跳的控制节点不等待自己的“完成”形成自锁。成功出口只有必要选中成果和所有已启动实际任务都满足后才发布；end 的路径关闭不自动等于范围成功。外围文档槽及已固定祖先输入完全不变。

   新轮依赖只能使用本轮成员及显式固定导入。若后续实现要把上一轮代码结果用于增量修复，必须在回跳转移中登记具名 carry、精确旧 execution/Attempt/提交/摘要，作为新轮明确输入；否则仍按当前限制拒绝隐式旧轮复用。不得用“最新结果”实现修复，也不能将旧轮成功成员直接算作新轮已完成。

2. **I026-02 / P1：未激活子范围 patch 与已冻结父快照的版本选择尚未闭合。** 位置：FD 第 99、104～105 行、D026-02 的当前版本复验；相邻 `QuestionContract.Source` / `SourceResolver.validate`。运行中父 activation 固定旧 specVersion，同时允许修改其尚未激活子范围；未指出父随后进入该子范围时选哪个不可变版本。全局 head 变更若让旧 execution/问题的版本检查失效，会冻结已授权工作；若始终沿旧父整图快照，则补丁不会生效。

   最小合同：分开编辑 head/revision 与每个 activation 的执行快照，记录父 activation 中未绑定子范围的版本绑定槽或等价版本向量；首次进入时持久化所选子版本及完整接口摘要。patch 与首次激活使用同一准入锁/CAS：激活先提交则 patch 拒绝；patch 先提交则该未绑定槽固定新子范围 revision，父现有节点/输入/已选成员不变。补丁只能改变被指定未激活子树内部；除 parent/entry/join/loop 端口外，还固定外部 dependsOn、baseFrom、谓词来源、导入/出口类型及跨边界边，拒绝借内部改写改变对外数据/权限含义。已创建 NOT_SELECTED 决定也属于旧快照历史，不能原位重写；需要明确后续迭代采用的子范围版本，不能靠“此时最新”推断。旧完成/回答验证其来源快照和 execution 控制版本，不与全局编辑 head 简单相等；取消替代则有显式 replacementFor 及槽接管记录。

3. **I026-03 / P1：真实失败的选路、固定依据和恢复状态还不能据此唯一实施。** 位置：FD 第 101、103、105～106 行；相邻 `AgentFactory.prepareAuthorized`、`ConfigurationContract.Intent`、`ExecutionGuard`。当前 Factory 只接受有真实完成 TaskInput 的依赖，并自行固定配置/Skill/知识来源；“单独固定失败上下文”“显式技术重试/替代”尚无具体状态和来源载荷。业务 verdict 不通过、Task FAILED、取消和 UNKNOWN 若都当 success=false，会错误推进；若失败之后已经 SKIPPED 传播，再原位重试也会与不可变选路冲突。

   最小合同：固定来源事实类型及字段语义：COMPLETED 的业务 verdict（包括 REPAIR_REQUIRED/FAIL）仍是正式完成依据；已确认的 FAILED 保存精确 task/Attempt、失败类别和证据摘要；CANCELLED 不当成功，UNKNOWN 只阻塞核对，均不默认 false。明确哪些控制边可消费已确认失败、哪些是必须成功的数据依赖；失败事实不放入 Factory.dependencies。可由图拥有者把已登记失败事实和摘要写入冻结的图输入及平台生成的 Intent.instruction，或窄扩正式来源端口，但必须给出唯一登记/校验消费者，不能使用任意 sourceRef 或伪 TaskInput。

   恢复建议固定为：FAILED_BLOCKED 且尚未发布出口/消费失败路径时，有权限的显式技术重试以 decisionId、expected execution/task/Attempt 版本和已知收尾事实 CAS 为 RETRY_PENDING，保留原输入/配置/业务 iteration，实际新 Attempt 仍由既有 claim/预算机制生成；不清账。若失败路径已消费、输入须改或选择替代，则创建带 replacementFor 的新执行/任务，并原子转移必要输出槽，不撤销历史边选择。旧失败事实保留，恢复成功后只满足该被替代槽；独立分支不重跑。UNKNOWN、未确认终止或旧 Attempt 不能走此入口。源码当前没有可直接据名字复用的通用图重试入口，须由本 FD 明确受控服务/CAS，不能调用已有 forceRequeue 绕过 guard。

可直接落实的接合建议（不另立政策 Gate）：

- `AgentFactory.prepareAuthorized` 是同库纯数据库事务入口；为每个图 execution 持久保存稳定 intentId/intentVersion、原始 Intent 摘要及 preparation generation，BLOCKED 仅按原内容/generation 显式重试。READY 后唯一 task 映射不可另建；新政策/语义确需新意图版本时保留前版本，不把扫描时间或随机 UUID 当新身份。完成事实用精确物理 task+Attempt+正式结果摘要去重，业务槽使用经过 lineage 验证的当前映射。
- `FormalQuestions.consume` 已在事务及目标锁内调用 SourceResolver.apply，再由 FD-028 写 APPLIED。图 resolver 只产生本次图转移/槽更新，暂停或未静止返回 null；纯 ask 返回非空 Application(null)，临时任务返回同一可信 continueExisting 窄端口的后继。不得另一个恢复器也写问题 APPLIED；questionId+answerRevision+execution 是稳定消费键，重放返回原应用结果。SourceFor 必须覆盖正式映射的原任务及真实 lineage 后继，未注册/错 owner/旧被替代执行拒绝，不能回落 LEGACY 消费者。
- `ledger.backjump` 已按 transitionId 幂等，但到限以异常拒绝；图需在回跳/新轮事务之外持久保存相同阻塞转移及唯一额度申请键，恢复仍使用原 transitionId，不因捕获异常新建 ID。图申请不是批准：当前 `FormalQuestions.budget` 是人类审批角色入口，后台图缺口应使用另一个仅平台可调用、验证 owner/真实缺口/固定范围的“提出申请”窄端口，不能冒充 boundary.human；金额生效仍只由 FD-028/A18/ledger 决定。未知用量不自动转成追加授权。

上述建议保留范围快照、初始加三次回跳、暂停准入、真实停止与 UNKNOWN、人类/秘书权限及当前依赖所有权。推荐方案不引入新服务、脚本或授权来源。尚未解决的三个工程合同应由 Planner 固定进本 FD 后再实施，无需让用户重选已确认的政策。
