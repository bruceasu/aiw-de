## 发现

1. **P1 · Plane 完成入口未核对必需检查的操作回执。** `TaskExecutionService.complete` 在关联报告及完成任务前调用的守卫只检查租约、未决操作、交付存在及 Git 结果一致性。`ExecutionGuard.delivery` 接收现有 `commandsRun` 字符串列表，`WorkflowRuns` 则依据 `PASS` 推进。当前只有内置 Python Worker 会把缺少检查的报告降为 `REPAIR_REQUIRED`。外部已认证 Worker 的能力由注册请求声明，Plane 因此缺少独立的必需检查校验。任务详情也直接把列表中自声明的 `checkStatus` 翻译成「通过」。在完成入口按必需配置 ID 核对当前任务与尝试的受控命令记录，确认操作 ID、工具类别、资源、终态、输出摘要及报告的零退出码彼此关联。详情应复用相同的回执匹配。命令结果仍由已认证 Worker 执行和报告。
2. **P2 · 验收说明使表单允许的原任务指令意外超限，并重复派发原指令。** `workflows.html` 的两个输入分别允许 8,000 和 2,000 个字符，`WorkflowRuns.simple` 却把两者与标题分隔符拼入上限为 8,000 的 `Node.instruction`。原来可提交的 8,000 字符指令填入任意验收说明后就会失败。短一些的指令也因为 `instruction(Spec,Node)` 同时写出原目标和含原指令的节点文本，更容易碰到 16,384 字符派发限制。分开保存和派发验收说明，或明确采用统一容量并在提交前核对，同时避免重复派发原指令。
