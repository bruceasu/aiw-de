Recovery requires the exact field set, matches the source attempt and platform instance, and compares the operation ID and fixed operation fields to the platform-provided approved descriptor. 3. **Low-risk command classification — still has a hard gap.** Maven/Gradle, Python, pytest, Go, and Cargo branches now require narrow command shapes, and absolute paths, direct `..` components, Windows drive paths and backslashes in argv are sent to approval. However, the generic `rg`/`grep`/`ls`/`cat`/related branch still accepts arbitrary arguments except for a small exact-token denylist ([execution_guard.py](../../../../workers/process-python/execution_guard.py#L63)). For example, `rg --pre=python` evades the checks for the exact tokens `--pre` and `--pre-glob`, although `--pre` is an execution-capable option. The escape check also examines argv as whole path strings; an option value such as `--pre=../tool` does not contain a standalone `..` path component. These shapes can be classified low-risk without per-operation approval. Restrict these utilities to exact read-only argv patterns, and parse option values that carry paths; otherwise classify them as requiring approval.

4. **Affirmative intent for tracked-file deletion — still has a hard gap.** The parser examines only the first exact-path mention and only the text preceding that mention ([execution_guard.py](../../../../workers/process-python/execution_guard.py#L259)). Thus an instruction that first says “Delete `src/config.yml`” and later says “Do not delete `src/config.yml` until I confirm” is treated as affirmative; the later prohibition is never inspected. The Chinese negation list also omits forms such as `严禁删除`, which then satisfy the positive verb check. Conflicting or unrecognized intent must remain approval-required; inspect all target mentions and fail closed when any negation or ambiguity exists.
