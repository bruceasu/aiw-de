## Findings

1. **[P1] Command approval can disclose credentials in the UI.** `ToolApprovals.containsCredentialArgument` and `redactCommand` recognize only a narrow set of leading flags and URL user/password syntax ([ToolApprovals.java](../../../../src/main/java/me/asu/aidev/execution/guard/ToolApprovals.java#L273)). They miss common forms such as `-Dpassword=...`, `-DapiToken=...`, and `API_TOKEN=...`. The approval view returns that command, and [tool-approvals.js](../../../../src/main/resources/static/ui/tool-approvals.js#L58) renders `binding.command.argv` directly as text. The same filter is also the server-side gate for opening an approval, so these values are not rejected. Use a conservative credential detector/redactor for assignment-style and common tool-specific forms, and ensure uncertain values are withheld from the view.

2. **[P1] The handoff artifact stores an unnecessary Worker lease token.** `_request_approval` serializes the complete `payload`, including `payload.lease.leaseToken`, into `.ai/approvals/<id>.json` ([execution_guard.py](../../../../workers/process-python/execution_guard.py#L268)). The successor recovery path only checks that this token is non-empty; it does not use its value ([execution_guard.py](../../../../workers/process-python/execution_guard.py#L401)). This persists a bearer credential in the shared Plan workspace without a recovery need. Store only the source Worker/attempt identity, or a non-reversible binding, in the local artifact.

3. **[P1] The command classifier treats broad command shapes as low risk.** For package managers, any argv containing `run` or `test` is accepted as low risk; for Maven/Gradle, any argv containing `test`, `check`, or `compile` is accepted ([execution_guard.py](../../../../workers/process-python/execution_guard.py#L49)). For example, `npm run wipe-cache` and `mvn exec:java test` pass these checks despite not being ordinary test/build invocations. Because this classification bypasses the one-time approval request, match only explicitly supported command forms and treat additional goals/scripts/arguments as requiring approval.

4. **[P1] A filename mention alone can authorize autonomous deletion.** Existing tracked files bypass approval when their exact path occurs anywhere in the task instruction ([execution_guard.py](../../../../workers/process-python/execution_guard.py#L212)). The code does not establish that the task requests deletion; a prohibitive instruction such as “Do not delete `src/config.yml`” satisfies the same predicate. Require affirmative deletion intent for that exact target, otherwise keep the operation pending for Owner approval.
