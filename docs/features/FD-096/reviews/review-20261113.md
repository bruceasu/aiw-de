## 发现

1. **P2：空 provider 导致未处理的 NPE。** `ConfigurationController.priceAction()` 对 `input.provider()` 直接调用 `Set.of(...).contains()`；provider 缺失或显式 null 时会抛 NullPointerException，而不是现有 IllegalArgumentException 对应的 422。请求整体为 null 已检查，但字段 null 未检查。请在固定服务商范围检查前明确拒绝 null；action 的 equals 分支已安全处理空值。
2. **P2：后续状态查询失败会隐藏已经确认的动作回执。** `model-usage.js` 的 priceAction 已接到 QUEUED/REPAIR_REQUESTED 后，在 finally 查询来源状态；loadSources 失败会设置 sourceError，renderSources 在该分支直接返回，未展示 actionResult。页面因而无法区分“操作已接受、刷新失败”和“操作未成功”，不满足显式操作回执的目标。请独立保留已确认回执，同时显示状态不可用，不要因查询失败暗示动作未接受或自动重做。

同处回执说明：旧 `dispatch.enqueue()` 按 material 固定任务 ID 去重，已有终态任务也会返回原 taskId；目前页面忽略 taskId，仅显示 REPAIR_REQUESTED。修正文案时应明确可能关联已有任务、不自动重做终态任务，并可使用返回的真实 taskId 提供详情，避免暗示新建或重跑。无需改变旧去重或增加自动重试。

`model-price-status` 仍为 p，而新代码追加 div，属于 HTML 内容模型不合规；可同处改为 div，本报告不把它单独列为执行语义阻塞。
