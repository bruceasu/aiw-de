# FD-038: 吸收宿主 FD 与工程技能方法到平台 Worker 技能库

**Status:** Design
**Revision:** 2
**Priority:** Medium
**Evidence policy:** Dual

## Problem

用户要求比较开发 Skill 与 .agents/skills 的 FD 方法，并把有价值部分吸收到平台库。平台已有 task-methods 覆盖拆分、四维审阅、测试 oracle、诊断及边界，不能再次堆叠同义规则。可补强任务内步骤、交接恢复与证据失效、讨论聚焦以及 Skill 编写。宿主 FD 拥有编排/交付权限，平台 Worker 只执行已分配任务，不能直接搬用同一生命周期。

## Options and decision

采用逐角色方法适配与来源矩阵；不复制宿主 FD CLI、自动交付、外部服务与代理调度。已有覆盖明确保留，只补缺口；复用原 Artifact/REPORT/VERDICT 格式。纯提示/资源变更，无 API/持久化/权限或协议变化，无需额外设计审阅；独立实现审阅仍必需。

## Solution

规范源 src/main/resources/worker-skills，强化各角色 task-methods；目标讨论增加按需参考，共享协议增加有条件加载的 Skill 编写参考。正文 Easy English。工具/测试/网络/代理/发布仍需原授权，Worker 不执行 FD 生命周期或接受自己的交付。

编码记录有验收对应的小型局部步骤，交接保留完成/待办/阻塞、原操作身份与复核后的下一步。这是原报告字段中的派生说明，不是新持久 TODO、权威 WorkItem 或自动重试状态机。需求/讨论聚焦影响决策的问题；规划追踪验收变化和依赖；设计比较现状/局部方案；审阅/验证核对实际修订、独立预期值和有限失败恢复。27 个源入口逐项分类，已覆盖和排除项均有理由。

index.json 声明新增文件，产生新文件集 manifest 版本；旧任务/重试/续行保留冻结字节。历史 software-catalog.json 文本资产不重写（正文与文件集摘要本就独立）；不迁移已存配置。把本次改动精确同步到三语言同名独立部署副本，不覆盖无关文件。同步技能说明与稳定规格，明确这不是运行时步骤状态机或模型效果证明。

## Scope

当前主工作区范围提交：平台文件/索引、Python/TypeScript/Go 对应副本、中文来源矩阵、说明/稳定规格、FD 证据。保留其它任务 Java、模板、秘书/模型/Python/启动器差异。不改 .agents/skills、工具/Schema/调度/CLI，不执行测试、模型、浏览器、迁移、网络、打包或重启。

1. 人能比较平台执行边界与FD方法价值，27个源入口有明确吸收/已覆盖/排除理由（1.1）。
2. 编码有验收对应的局部步骤与真实交接/恢复记录，不伪称持久状态或自动恢复（1.2）。
3. 各角色只取所需；不授予任务外、FD/审批/交付权或默认测试/网络/代理（1.2–1.3）。
4. 入口简短、参考按需且在清单内；原 REPORT/Artifact/VERDICT 和工具权限不变（1.2–1.4）。
5. 三语言改动副本与平台字节一致，新任务新文件集，既有冻结任务和旧文本目录不改（1.4–1.5）。
6. 只报告实际静态/编译检查；未运行模型效果评估或真实Worker/恢复/测试（1.5）。
