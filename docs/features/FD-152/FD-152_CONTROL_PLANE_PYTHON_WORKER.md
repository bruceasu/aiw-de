# FD-152: Control Plane 经理与通用 Python Worker 两期计划

**Status:** Design
**Revision:** 1
**Review policy:** Independent
**Priority:** Medium
**Evidence policy:** Markdown

## Problem

现有 Python Worker 在启动时选择 `coder`、`reviewer` 等软件工程角色，职责与 Plane 的员工定义重合。Agent 工厂保存后只提供一个默认运行配置。工厂会按兼容配置复用进程，同一配置缺少按积压启动多个实例的控制。Skills 分散在 Worker 随包文件与团队成员资料中。

## Options and decision

用户选定从新系统开始。设计以新的执行契约为基线，可复用现有模型适配、租约、工作目录与工具校验。旧安装和数据处置属于独立的部署事项。

通用员工为默认，专业员工按业务需要沉淀为可复用配置。秘书在用户授权范围内代办。经理是 Java Control Plane 的内置角色，负责许愿池、派工选择和异常判断。Plane 按确定规则推进流程，并对经理的建议做权限和状态校验。

## Solution

### 首期

1. **通用任务契约。** Plane 在派发时固定任务目标与验收、员工、Profile 版本、Skill 版本、工作位置和工具授权。Python Worker 注册时声明支持的 Runtime、协议、工具能力和可访问位置。Plane 匹配登记能力、心跳及容量，在领取时复核并分配租约。Worker 开工前验证目标和实际环境。
2. **并行与启动。** 工厂优先复用兼容的在线容量，容量不足时可启动同一种 Worker 的多个实例。已启动和启动中的实例都计入上限。每个任务同时只有一个有效租约。按规范化的工作位置协调写入，同目录及别名共享互斥范围。执行结果或占用状态不明时等待人工核对。
3. **多运行 Profile。** 工厂提供 UI 和 API 管理命名 Profile、启停及默认项。配置包括 Runtime、服务商、模型、推理强度和连接引用。任务或工作流明确指定时采用指定项，有选型条件时由经理从兼容候选选择，其余采用已启用的默认项。指定项不可用时记录阻塞。
4. **平台 Skills。** UI 和 API 支持创建、编辑、查看历史及启停。员工和工作流可以引用 Skill，任务派发时固定版本。停用后停止对新任务选用，已派发任务保留原版本。Worker 随包维护执行与交付协议，工具授权由任务独立给出。
5. **经理的模型调用。** Java 通过本机子进程以有限 JSON 输入输出调用现有 Python 模型适配，使用经理自己的默认 Profile。调用有截止时间，传入候选和必要上下文，返回结构化建议。Java 校验格式、候选、权限和当前状态。纯模型调用使用专用入口。需要读取大量材料、改文件或运行命令时，经理派为带租约的正式任务。模型调用失败时记录原因。
6. **业务流转与详情。** 简单任务的模型回合、工具和交付由 Worker 自主推进。可复用工作流由 Plane 按固定版本与结果推进规则、人工和执行节点，只有执行节点进入 Worker 队列。首期使用已有的文件、搜索和受控命令工具。详情显示实际 Profile、Skill 版本、员工、Worker、工作位置、工具授权及阻塞原因。

### 下一期

- **工具目录。** Plane 提供工具、MCP 服务与 HTTP API 的注册和检索。先接入一个只读业务查询，验证注册、按任务授权、Worker 检索、调用和审计。调用按租约、范围与审批校验，停用后拒绝新调用。凭据由连接配置管理。
- **专业员工。** 将已反复验证的职责、默认 Skills、Profile 偏好和交付要求保存下来，继续在通用 Worker 上执行。任务工具权限按次授予。
- **经理自动恢复。** 分别定义自动重试、暂停派工和重新分配的适用条件、次数及审批边界。结果不明、权限扩大和高影响操作进入人工确认。

第二期依赖首期从派发、领取到交付的验收。首个业务连接的服务、部署位置和授权责任在工具接入前确认。

## Detailed design

以下接口、错误码和持久化边界是设计草案。执行协议拟复用现有 Worker Pull 的注册、领取、心跳和结算语义。公开接口的变更及旧稳定规格中以工程角色为前提的条款，在实施前核对并按新契约更新。

### 调用与模块边界

| 组成 | 拥有的状态与动作 | 复用入口 |
|---|---|---|
| Java Plane | 运行、节点、任务、执行尝试、租约、授权和派发快照。一次状态改变由 Plane 提交并留下记录。 | `WorkflowRuns`、`TaskClaimService`、`WorkerProtocolV1Controller` |
| Agent 工厂 | 保存运行配置、执行主机可启动的 Worker 模板和进程上限，负责启动、登记确认和回收。 | `AgentFactorySettings`、`ManagedWorkerProvisioner` |
| 内置经理 | 根据候选和诊断证据给出派工或恢复建议。Java 负责应用建议和校验权限。 | 现有诊断入口、Python `model_runtime.complete_text` |
| Python Worker | 登记进程能力、领取任务、准备工作位置、运行模型与工具、报告结果和关闭进程。 | `process_worker.py`、现有模型和工具适配 |
| 资源目录 | 保存 Profile 和 Skill 的不可变版本，给派发解析精确引用。 | 现有连接目录、`SkillFiles` 与版本读取机制 |

### 1.1 通用任务、身份和领取

**派发前**，Plane 收到任务目标、验收条件、业务输入、工作位置和授权要求。简单任务使用一个执行单元。工作流执行节点另外提供工作流运行、定义版本、节点编号及前序结果引用。提交幂等键在提交者范围内绑定输入，重复提交相同输入返回原记录，输入变化要求新请求。

**派发时**生成不可变执行快照，至少包含下列内容。等待匹配的任务也保留原始需求和阻塞原因，补齐条件后再形成快照。

| 内容 | 首期契约 |
|---|---|
| 任务来源 | 任务和逻辑节点标识、任务指令版本、输入引用、验收要求 |
| 员工和模型 | 通用员工或明确指定的员工标识、Profile ID 与版本、选型来源 |
| Skills | 有序的 Skill ID、版本和摘要。相同引用去重，同一 Skill 的版本冲突需要调用方选择 |
| 工作位置 | 逻辑位置、目标执行主机或共享存储标识、Worker 上使用的路径、访问模式 |
| 工具 | 本次允许的工具与资源范围、命令许可及授权版本。凭据通过现有连接机制提供 |
| 交付 | 结果类型、验收条件和前序正式交接引用 |

Worker 登记的能力描述包含进程身份与会话、执行主机、协议版本、可运行的 Runtime 与连接方式、可访问的工作位置、工具能力和容量。Plane 只在任务需求都被覆盖时分配租约。能力标签负责匹配，结构化的授权与位置字段负责限定实际动作。位置按受信任的主机或共享存储登记，Worker 自报能力也要经过领取后的实地核验。支持在 UI 直接填工作目录；Plane 用目录与已登记主机的关系查找候选，实际路径、权限和可用性由 Worker 核验。

领取事务同时复核进程会话、能力快照、心跳、接收状态、容量、任务版本和授权，分配一个有效租约。Worker 在领取后用指定 Profile 建立本次模型会话，核验目标目录、操作权限和任务所需工具，再上报开始。准备失败时回传阶段和原因，保留本次尝试记录。心跳、开始、完成和失败沿用有效租约及尝试的校验。迟到或来自旧进程会话的结果只能作为待核对证据。

### 1.2 多实例与目录互斥

首期以每个进程承载一个执行槽为默认。工厂按兼容启动配置维护多个不同的实例，优先使用已在线的空闲槽。定时扫描只统计具备派发条件的积压，扣除可用槽和已预留的启动槽。若一个 Worker 可服务多个候选组，它的空闲槽在一次扫描中只分配一次。新启动量受全局上限及对应启动配置上限约束。

启动路径为 `预留槽 → 启动 → 登记确认 → 在线`。从预留开始计入上限。启动失败或超时记录原因，确认对应进程已停止后释放预留。后续轮询可根据当前需求和失败间隔再尝试。Plane 重启后先核对已有登记、启动记录和活跃租约，再补启动容量。

目录互斥使用真实执行资源的标识。对本机资源由执行主机和规范化根目录确定。对共享资源使用登记的共享位置标识。路径别名、符号链接或 Windows 目录联接指向同一位置时共用一份占用。首期对同目录及重叠目录的写执行串行；纯文本或其他目录的工作仍可并行。需要读取与写入一致的工作树时，读取方使用固定快照或等待写入结束。Plane 负责准入，Worker 在开工前使用现有本地占用机制复核。租约失效后停用新操作，只有确认原进程和未决操作已结束才释放写入占用。

### 1.3 多 Profile 与默认配置

Profile 由稳定 ID 和不可变版本组成。编辑创建下一版，启停和默认指针独立维护。工厂默认以及经理默认均指向已启用的 Profile，可以选择同一个。停用默认项要同时换成另一个已启用项。目录保留选型所需的连接引用和版本，凭据发放继续校验连接的实时状态。

选型顺序为 **提交者明确指定 → 工作流节点明确指定 → 经理在满足条件的候选中选择 → 工厂默认**。提交者与节点约束冲突时要求解决冲突。经理只在任务或 SOP 有额外选型条件时参与纯模型选择；能唯一确定候选时由 Java 直接采用。显式指定的项停用、连接失效或没有兼容执行环境时显示原因。已派发任务在普通配置编辑后仍使用固定版本；凭据撤销与权限收回在开始和调用时生效。

### 1.4 平台 Skills 与任务资料

Skill 目录保存稳定标识、显示名、说明、归属、启用状态和版本。每次保存的新内容带版本号、摘要和变更记录。查看历史可以读取确切版本，恢复历史内容会创建新版本。首期维护可审核的文本说明并复用任务 Skill 文件的读取与摘要核验。

任务、工作流节点及员工可以引用具体版本或当前启用版本。Plane 派发时解析为精确版本并校验访问授权。明确引用缺失或停用的 Skill 时阻塞。已派发任务读取原有快照。Skill 内容作为任务资料传给模型；文件、命令及后续共享工具的权限仍由任务授权决定。

### 1.5 Java 经理与 Python 纯模型调用

Java 以固定可执行文件和参数启动本机 Python。通过标准输入发送一次受限 JSON 请求，通过标准输出读取一次 JSON 结果。日志另行记录。请求包含调用 ID、用途、Profile 引用、截止时间、候选 ID 和必要证据。响应包含调用 ID、建议、简短理由、待核对事项及可用的用量记录。首期允许的建议为选候选项、说明阻塞或请求人工决定。正常业务分支、租约、权限判断直接由 Java 完成。

模型进程按纯模型模式运行，工作目录为临时空目录。该入口无 Worker 注册、任务租约和任务工具。Java 验证响应长度、结构、调用 ID、候选约束和当前输入版本，再提交正式决策。开始调用、结束、超时和校验失败都有记录，敏感字段保持在连接配置或既有授权边界内。超时先请求停止，再核对进程树状态。配置不兼容、模型失败或建议过期时保留原因，允许有权限的人在详情里处理。

需要读日志、检查仓库或跑测试时，经理按现有规则创建范围明确的诊断或执行任务。诊断结果通过正式任务链路回到 Plane，恢复首期保留人工决定。当前纯模型入口实际覆盖的 Runtime、认证方式和 DeepSeek 协议支持需要在实现时逐项对齐。UI 只展示已验证支持当前入口的 Profile。

### 1.6 状态、控制台和接口

| 阶段 | 判定与后续 |
|---|---|
| 待派发或阻塞 | Plane 检查输入、选型、Skill、授权和可匹配位置。详情返回原因码、可读说明和需要补齐的对象。 |
| 已就绪／已领取 | 已有固定快照。领取记录具体 Worker、尝试和租约，已领取仍需准备检查。 |
| 执行或等待输入 | Worker 回报进行中的状态。问题和答复关联到任务及尝试。续接依现有检查点规则。 |
| 成功或失败 | Plane 用当前尝试的正式结算记录推进后续节点。通过结果才满足依赖。失败保留原先记录。 |
| 结果待核对 | 进程终止或操作效果尚未确认时保留原尝试和资源占用。已知不确定的操作禁止自动重放。 |

建议使用结构化阻塞原因，首期包括 `PROFILE_UNAVAILABLE`、`SKILL_UNAVAILABLE`、`NO_COMPATIBLE_WORKER`、`WORKSPACE_UNAVAILABLE`、`TOOL_NOT_AUTHORIZED`、`WORKSPACE_BUSY`、`MANAGER_MODEL_FAILED` 和 `OUTCOME_UNKNOWN`。错误文本面向用户，机器接口同时返回原因码与相关资源引用。

工厂页提供 Profile 列表、编辑、启停、默认项、Worker 启动设置。Skills 页提供搜索、编辑、历史和启停。任务详情按尝试显示实际员工、Worker、Profile、Skills、目标位置、授权、结果及阻塞原因。工作流编辑器在执行节点选择 Profile 约束和 Skills，规则与人工节点使用各自输入。管理 API 提供相同操作，写入校验当前角色、资源归属和预期版本。执行与授权的回执继续绑定原任务、尝试与实际操作者。

建议按以下资源组织 API。路径和 DTO 在实施时与现有控制台及 Worker 协议对齐。

| 接口组 | 操作 | 一致性 |
|---|---|---|
| 工厂 Profile | 列表、读取版本、新建、发布新版、启停、设置工厂或经理默认项 | 同一事务校验旧版本、启用状态与默认指针。并发编辑提示重新加载。 |
| 平台 Skills | 搜索、读取历史版本、新建、发布、恢复、启停 | 修改生成不可变版本。读取具体版本按来源和调用身份校验。 |
| 任务 | 提交、查询状态和执行详情、提交人工决定 | 同一提交键返回原任务，人工决定校验原记录及版本。 |
| Worker Pull | 登记、领取、开始、续约、结算 | 领取提供当前能力摘要，后续调用绑定进程会话和有效租约。 |

**首期数据与上线。** 在新数据环境验证任务快照、租约、目录占用与尝试结算。需要持久化的是 Profile 和 Skill 的版本、任务执行快照、实例与租约关系、经理调用与决策回执。执行记录应能区分冻结配置与当前目录状态。旧环境不在首期迁移范围内，部署或清理旧环境另行确认。

### 2.1 工具注册、MCP 与 HTTP API

Plane 工具条目包含稳定标识、版本、工具种类、连接引用、允许的操作、入参结构、访问范围、审批规则、启用状态。MCP 或 HTTP 连接由管理员登记，凭据按连接授权取用。共享工具入口接受当前任务已授权的工具 ID 和符合结构的业务参数。调用目标、允许动作和凭据来自已审核的连接配置。Worker 可检索本次租约下有效的工具和参数说明。

派发时固定工具引用，调用时复核租约、当前权限和工具状态。执行记录以操作 ID 关联请求摘要、调用结果、任务、尝试和授权。遇到未知结果保留原操作供核对。首个交付只覆盖一个真实只读业务查询，完成从注册、探测可用性、按任务授权、调用到撤销的链路。文件、编辑和受控命令继续在 Worker 本机执行。

### 2.2 专业员工与 2.3 自动恢复

专业员工配置保存职责、可复用 Skills、Profile 偏好、能力要求和交付标准。派发时解析并记录实际配置版本。工具权限随任务确认。一个员工可由不同的兼容 Worker 承载，也可以将通用员工一次成功派工的配置沉淀为专业员工。

自动恢复以确定条件和正式执行证据触发。每项规则定义动作、适用范围、次数限制、停止条件和人工审批点。相同的失败与规则只消费一次相同恢复决策。重试前核对原任务、版本、权限、操作结果和资源是否已释放。权限扩大、发布、删除或未知结果交有权限的人决定。经理的模型输出提供建议，执行由 Plane 按已配置规则核验。

### 阶段依赖与设计核对

- 首期先定任务快照、Worker 协议与占用规则，再落实 Profile、Skills 和经理的纯模型调用。简单任务先验证贯通，然后接入工作流执行节点和最终验收。
- 首期重点核对并发领取、同目录别名、进程未停止、模型超时和建议过期、授权撤销、Profile 与 Skill 的版本行为、进程重启后的实例数量。纯模型桥用可控响应覆盖边界后，再验证真实连接。
- 下一期的首个真实连接及其访问方、数据范围、审批人，在接入前明确。生产的并发上限、启动失败间隔和模型时限由部署条件决定，实施时使用明确配置和对应验收值。

## Scope

首期覆盖通用 Python Worker、能力匹配和并行、多 Profile、平台 Skills、经理纯模型调用，以及简单任务和业务工作流的端到端验证。下一期覆盖共享工具、专业员工配置及经理的受限自动恢复。本 FD 为两期设计稿。

## Acceptance

### 首期

- 同一个 Python Worker 先在指定目录修改 Java 文件并执行获准测试，再做只读文档核对。详情能核对两次任务各自的实际配置和授权。
- 同一种 Worker 可以启动多个实例。不同项目的独立任务可并行，同目录的两项写任务排队。竞争领取时只有一个有效租约，进程数受配置上限约束。
- 售后流程的凭证检查、人工补件或审批由 Plane 推进。只派发资料核对节点，使用随任务提供的数据。
- 新任务可以选用新 Skill 版本，已派发任务继续使用固定版本。指定 Profile 停用、目录不可访问、缺少命令能力或缺少授权时，详情说明阻塞原因。
- 经理的纯模型调用能从合法候选中给出建议。超时或非法输出保留失败记录。实际工具操作有自己的任务和租约，执行结果不明时进入人工核对。

### 下一期

- 只读工具可以注册、检索、按任务调用和审计。撤销或停用后新的调用被拒绝。
- 同一个专业员工配置可在两个兼容 Worker 上用于不同任务。
- 同一故障的恢复有触发条件和次数上限，超出授权或结果不明时请求人工确认。

## Verification

- 设计依据为本次对话，以及工厂配置、进程启动和 Python 模型适配的静态核对。
- 实施后计划执行适用的 Java 和 Python 编译检查、独立复审。复审重点为公开契约、权限、租约与并发。运行验收按独立授权执行。
- 接口验收在新数据环境核对重复提交、并行领取和审计。进程启动器与纯模型桥可用可控响应验证失败路径，真实模型与真实工具连接有单独的端到端证据。
- 当前为设计阶段，尚未实施或执行编译、测试、部署。
