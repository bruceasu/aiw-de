# FD-065: 个人秘书知识库 API 接入

**Status:** Design
**Revision:** 1
**Review policy:** Independent
**Priority:** Medium
**Evidence policy:** Dual

## Problem

用户需要个人秘书基于知识库中的长期资料回答问题，并在用户明确要求时将整理后的笔记保存回知识库。当前秘书只在本地对话记忆中检索，缺少受控的跨服务搜索、正文读取、引用和可靠保存能力。直接复用聊天记忆、文件访问或启动知识库进程会混淆数据所有权和部署边界。

本 FD 的目标实现位于 personal-secretary；知识库 API 的完整字段、错误和安全约束以 [个人秘书知识库 API 交接契约](../../personal-secretary-knowledge-handoff.md) 为唯一跨项目来源。知识库服务端路线已在其自身工作中实现，但运行语义及跨机联调尚未验证，不能将其视为已部署或端到端可用。

## Options and decision

1. **HTTP-only 独立客户端（选定）**：秘书通过 HTTPS、Bearer 凭证调用知识库 API v1.0。两服务独立部署、鉴权和持久化；新集成默认关闭。
2. **MCP 或启动知识库子进程（拒绝）**：会引入额外运行时耦合，违反跨主机独立部署边界。
3. **直接访问知识库数据库、索引或文件（拒绝）**：绕过知识库鉴权、集合授权、版本和来源语义。
4. **把聊天记忆迁入知识库或自动双写（拒绝）**：改变现有记忆所有权，并扩大数据传输范围。

接口兼容性以 API `1.0` 为准：客户端校验必需字段和 `apiVersion`、忽略新增响应字段；服务端拒绝未知请求字段；破坏性更改需新契约版本。不得依赖猜测出的旧接口。

## Solution

在 personal-secretary 增加独立知识库客户端及默认关闭的连接配置。配置只接受 HTTPS 的 API base URL 和受保护的 `publicBaseUrl`；Bearer token 通过既有私密配置机制按 `credentialRef` 读取。客户端校验证书与主机名、不跟随重定向、限定响应大小和请求时限，并把非 JSON 代理响应映射为受控错误。

连接配置或启用时读取一次 `/capabilities`，按服务端声明的能力开放搜索、读取、创建和创建状态查询；不在每次工具调用前重新探测。工具调用使用 API v1.0 的 `/search`、`/documents/{documentId}`、`/notes` 和 `/note-creations/{idempotencyKey}`。工具结果保留服务端来源标题、位置、版本、新鲜度与受保护阅读链接；只接受用户信任的 publicBaseUrl origin，不自动信任 API 返回的任意 origin。

本地持久化创建请求的幂等键、规范化请求体、服务主体/`serviceId` 绑定、状态及结果。写入超时或断连后先按相同 key 对账；只有确认 404 时才以相同 key 和相同正文重发。未知状态必须保留为 unknown，不能误报已保存。凭证轮换不得改变幂等主体；切换知识库时不得重放旧创建请求。

搜索和正文只将当前请求需要的资料加入上下文，并执行契约规定的调用次数与字符预算。资料正文是非可信背景，不能成为系统指令。普通对话不必每次查询知识库；回答应区分资料原文、秘书归纳和外部实时信息。只有用户明确要求保存且 API 返回持久化成功后才能报告“已保存”；只有索引就绪才报告“已可搜索”。

## Scope

**包含**

- personal-secretary 的 HTTPS 客户端、默认关闭的配置、私密凭证引用和连接能力检查。
- 搜索、版本固定正文读取、来源引用、用户明确触发的笔记创建、创建状态对账。
- 创建请求的本地持久化、幂等重放规则、错误映射、超时、受控只读重试及工具/上下文预算。
- 秘书 UI 的连接状态、受控错误、来源链接及无需用户编辑工具 JSON 的配置流程。
- 与 API v1.0 的同一组 request/response fixtures 兼容性检查，以及有真实部署条件时的跨机联调验收。

**不包含**

- 知识库服务端 API 的重复实现或其部署、启动、停止；不启动子进程。
- MCP、共享数据库/索引目录、服务器文件路径或 workspaceId 参数。
- 私库聊天记忆迁移、全量导出、自动双写、每轮自动保存。
- 笔记删除/覆盖、扩大凭证权限、秘书侧上传工具、附件下载或执行。
- 将旧资料声称为实时外部信息，或在没有实际部署与联调证据时宣称端到端完成。

## Work items

- [ ] 1.1 在 personal-secretary 建立默认关闭的连接配置和独立 HTTPS 客户端：安全解析 base URL、读取凭证引用、校验 TLS/响应封装/大小/超时、禁止重定向，并在配置或启用时校验 capabilities。
- [ ] 1.2 实现只读搜索与固定 revision 正文读取工具：按 capabilities 禁用缺失能力；遵守服务端分页、revision/cursor、新鲜度和调用/字符预算；错误与部分结果以受控结构返回。
- [ ] 1.3 实现明确授权的笔记创建和持久化对账：先保存 key 与规范化请求，再 POST；超时后查询状态；仅同 key、同请求体重发；重启后可恢复 pending/unknown/succeeded/failed；服务主体或 serviceId 不匹配时禁止重放。
- [ ] 1.4 接入秘书工具循环与 UI：普通对话不强制查询；答案展示可信来源链接及位置；控制提示和错误；凭证和工具配置不暴露给模型；知识正文作为非可信输入处理。
- [ ] 1.5 使用契约 fixtures 验证客户端兼容和失败恢复；在两服务可用且获准联调时，验收真实搜索、引用打开、笔记保存可见性及丢失响应后的幂等恢复，并记录运行环境与实际结果。

## Acceptance

- 集成初始关闭；未配置有效 HTTPS 地址或凭证时，不发起知识库请求。配置不接受带路径、query、fragment、userinfo 的 baseUrl，不允许跳过证书校验或跟随重定向。
- 认证始终使用独立 Bearer token；401/403 映射成可操作的受控提示，不把登录页面、token、绝对路径、SQL、栈或代理全文返回给模型或日志。
- 搜索支持契约过滤与上限，能分别表示无命中、部分结果、stale/unknown 和服务不可用；无命中不被报告为检索失败。
- 正文读取使用搜索返回的 documentId 与 revision；版本变化、未就绪、不支持内容、cursor 过期按契约处理，不静默切换版本或下载/执行附件。
- 来源链接只允许配置的 publicBaseUrl origin；引用保留服务端标题、位置、revision 和 freshness，能区分资料原文、秘书归纳和实时外部来源。
- 单次请求默认至多一次搜索、三次正文读取，送入模型的资料内容总量不超过 30000 字符；连接超时、单请求超时及只读重试符合交接契约预算。
- 未经用户明确要求不创建笔记。发送前本地记录 key 与规范化请求；相同 key/请求不会产生重复笔记，不同请求复用 key 会受控失败；超时未知时先对账且绝不换 key；进程重启后状态可恢复。
- 只有创建结果持久化确认后回答“笔记已保存”；只有 `indexState=ready` 才回答“已可搜索”。服务端已受理而本地停止轮询时，不宣称取消了创建。
- 原有 conversations.py 本地记忆和文件操作授权保持不变；聊天不全量导出、不自动双写，普通消息可不调用知识库工具。
- 契约 fixtures 覆盖成功、字段校验、401/403、部分结果、版本变更、超时、同键并发/异体和重启对账。真实联调验收应覆盖用户文档所列部署路径；未运行的联调必须标记未验证，不能从编译或静态检查推断端到端通过。

## Verification

- Independent review 必须覆盖凭证处理、来源链接信任边界、保存幂等与重启恢复，因为这些会影响认证、持久化和公开 API 行为。
- 尚未实现或验证。实现阶段按仓库授权默认做静态审查和一次窄范围编译；契约 fixture 与跨机运行联调需在对应任务获准后执行。服务端文档所述编译结果不替代秘书端验证。
