# FD-090: Implement the confirmed Workers page design

**Status:** Open
**Revision:** 1
**Review policy:** Independent
**Priority:** Medium
**Evidence policy:** Markdown

## Problem

按用户已确认方案实现 Workers 页面，使管理者能清楚查看 Worker 当前工作及可用操作。用户于 2026-11-11 要求建立独立 FD；FD-088 的用量、价格采集和计费工作继续由 FD-088 管理。

## Options and decision

在现有 Web Console Workers 页面和 Fleet 查询基础上实施；复用已有视觉样式和任务／执行入口，保留服务器授权、CSRF 和真实状态校验。不得把已归档 FD-003 自动当作此次新方案。

用户已将 `/side` 的完整确认方案带回主对话。采用工作中心列表、详情侧栏和工作台直达，实施顺序是先列表重排及任务关联，再补充后端数据投影。以下记录为本 FD 的确认方案，不再有方案来源待补项。

## Solution

实现入口为 `src/main/resources/templates/ui/workers.html`、`WebConsoleQueryService`、页面控制器及现有工作台。沿用 Web Console 的颜色、排版、间距、控件和交互样式，覆盖现有中／英／日文案、空态、失败和动态状态。

### 工作中心列表

顶部为 `Workers [Agent 工厂] [刷新]`；下方依次是执行中／空闲／待处理／连接异常概览、搜索 Worker／任务／Plan、状态与来源筛选，以及 Worker／当前工作／最近活动／状态／操作列表。默认优先显示待处理、连接异常和执行中的 Worker，同级保持稳定排序。

列表显示名称、工作方法、实际模型、所属 Plan、当前任务、最近动作和更新时间。内部 ID、能力标签放入详情。来源以正式关联记录区分工厂自动生成、外部接入和未知，不能按 ID 命名推断。待处理指人工问题或授权，不能等同于 READY 队列；心跳超时为连接异常，不断言进程已停止。Worker 管理状态和连接状态分别保留。

若沿用最多 100 条快照，明确列表、搜索和筛选的加载范围，不用局部结果冒充全量统计。刷新保留筛选、侧栏选择及编辑值；当前执行发生变化时明确提示。并发 Worker 展示多个工作摘要或数量，侧栏列出可见任务；只有一个当前尝试时自动选中，多个时明确选择，不能静默丢弃并发执行。

### 详情侧栏与完整工作台

点击查看／处理打开侧栏，支持关闭、键盘操作、焦点返回，并可展开完整工作台。

| 内容 | 展示方式 |
| --- | --- |
| 当前工作 | 任务目标、所属 Plan、本次执行状态 |
| 执行过程 | 已记录的模型调用、工具操作、最近结果、待处理问题 |
| 执行配置 | 实际运行时、服务商、模型、思考强度、工作方法与 Skills |
| 资源用量 | 已记录轮数、Token、费用，缺失时显示“未记录” |
| 连接诊断 | 心跳、注册信息、并发占用、能力及权限，保留内部 ID |

从 Worker 进入时携带经服务器核对的任务和 Attempt 自动定位工作台，避免再次寻找。后端继续验证账号／Owner 可见范围，URL 参数不产生权限。配置默认值不能冒充本次实际选择；未知字段明确未知，缺少用量不能显示为零。资源记录依赖 FD-088，有记录才展示。

### 操作范围与确认

- Worker 层：Drain 改为“停止领取新任务”，说明当前任务继续。Offline 改为“标记离线”，不暗示已终止远端进程。
- 执行层：按实际支持提供“暂停本次执行”“继续”“取消本次执行”，状态或权限不支持时解释原因。
- Plan 层：“提前停止计划”进入所属 Plan 的既有确认流程。
- 执行控制请求发出后显示“等待 Worker 确认”，实际回执到达后才显示暂停或取消成功。区分失败、响应未知、等待与已确认；未知响应先核对原请求，不能盲目重发。
- 保留现有授权、CSRF、状态竞争和幂等合同；管理状态变更以服务端实际结果为准，不伪造进程停止回执。

### 后端投影与调度诊断

先核对注册、工厂归属、活动租约、任务／Plan／Attempt 和工作台读取合同；再对实际模型、阶段和最近活动补充有界批量投影，不能仅靠前端猜测，也不能逐 Worker 扫描全部执行记录。每项状态保留数据来源与更新时间，模型文字结束不等于任务完成。

READY 匹配、容量、租约及准入限制保留在“调度诊断：有 N 项任务尚未开始”折叠区；这个任务数与待处理 Worker 数区分。能力帮助收进说明入口，原功能保持可达。

## Scope

范围为已确认的 Workers 页面方案。新 FD 的创建不代表新授权的工具权限、调度算法、模型运行时、数据库迁移或 Worker 生命周期改造；如方案需要这些变更，应在实施前明确其合同及风险。FD-088 的费用计算和采集器安装不并入本 FD。

## Acceptance

- 页面按已确认的顶部入口、四类概览、搜索／筛选、工作列表与侧栏组织；待处理、连接异常和执行中 Worker 优先可见。
- 遵循现有 Web Console 样式，界面文案和新增控件覆盖现有支持语言。
- 展示真实 Worker、任务和执行状态，保留已有可达入口和服务器端操作校验。
- 失败、未知、等待和已停止状态有明确区别，刷新不覆盖用户正在编辑的内容。
- 工厂、外部、未知来源有后端依据；内部 ID 和能力在详情中仍可查看；用量缺失为未记录。
- 从 Worker 到工作台自动定位正确任务与尝试；并发任务可明确选择，账号可见范围不扩大。
- 三层操作范围清晰，等待 Worker 回执不显示执行已暂停／取消，连接异常不等于进程停止。
- READY、容量、租约与帮助保留可达，列表加载范围和概览计数不混淆。
