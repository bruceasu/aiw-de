## Findings

### P1：固定 profile 验证摘要与新任务配置摘要不属于同一契约

`WorkflowRuns.advance` 调用 guard.bindPrepared 时，把 configurationDigest 设为 `hash(run.spec,nodeKey,round,member,references)`。但 `GuardClaimPolicy.canClaim` 的非动态配置任务分支要求 Worker capability 等于 `fixed-profile:<context.configurationDigest>`；Python guarded_preflight 注册的 fixed-profile 却是 `digest(asdict(profile))`。

工厂明确将 general/workspace 设置为 guarded、非 dynamic-config，新统一文件任务也不要求动态配置协议，实际走上述固定 profile 分支。两个摘要的内容与生命周期不同，每个执行/轮次的业务摘要不能匹配静态 Worker profile 摘要。因此即使没有成员和参考资料，正常工作区任务仍会 READY 且无法领取。

最低修复：把统一任务的业务冻结摘要与现有固定 profile 验证契约正确对齐，真实领取使用可由 Worker 证明的 profile/Skill 身份；保留实际 Worker 匹配检查，不能只移除核验。

### P1：guarded SDK 未登记实际资料能力，含资料工作区任务无法领取

WorkflowRuns 对资料非空的任务要求 task-materials-v1，成员备注/经验也会动态触发该要求。`process_worker.WorkerConfig.from_env` 只有非 guarded 才调用 native_run.capabilities 登记 task-materials-v1；guarded_preflight 没有登记它。工厂 workspace 强制 guarded，所以实际能通过共享 SDK Sources 消费资料的进程，也不会被视为支持该协议。

最低修复：在实际支持资料消费的 guarded openai-agents 路径登记该能力，并保留不消费资料的备用 runtime 门禁。不能把含资料任务降级为无能力要求来绕过。

### P1：无 Git 目录的正式提问与续接仍强制依赖提交检查点

ProcessSlot 把 broker.checkpoint 设为 workspace.finalize。PlanWorkspace.finalize 在无 Git/base 时返回 None；`formal_questions.ask` 随后直接读取 result['resultRevision']/['changedFiles']，缺信息时 ask_question 因空值异常，无法创建正式问题。

续接的 verify_checkpoints 也无条件对 resultRevision 执行 ControlledGit rev-parse，旧非位置型 QuestionContract.Checkpoint 要求 base/result commit。仅改 storage namespace 并不能使普通目录可问可续接。

最低修复：让本批普通目录沿真实位置/树摘要交接契约创建与验证检查点，并保留 Git 场景原验证；不能虚构 commit，或仅吞掉提问异常。既有单次操作审批已能在无 Git 时用树摘要，正式提问也需完成直接关联的适配。
