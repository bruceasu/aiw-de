# FD-029: 用户得到可追溯、可恢复且符合授权的交付

**Status:** Open
**Revision:** 3
**Priority:** Medium
**Evidence policy:** Dual

## Problem

动态计划、逐任务配置和多渠道回答增加了输入漂移、重复副作用及越权的风险。用户要求交付可追溯、重启可恢复且真实操作受授权约束；现有 TaskInput、Git 结果、Lease 和有限委托可复用，但不能据其存在断言已覆盖新增的每次工具调用、业务循环和新预算维度。

事实：TaskInput 保存 task/attempt、仓库/基线/结果版本、改变文件、verdict 及摘要；AuthorityBudgets 具有目标/动作累计计数和明确 supplement，不能直接当时间/成本/任务规模计量；个人秘书已规定 UNKNOWN 查询/人工核对、不盲目重放。

## Options and decision

| 选项 | 取舍 |
| --- | --- |
| 提示词要求 Agent 遵守，领取任务即放开所有工具 | 不能满足真实调用边界的 AC09，不采用 |
| 固定输入 + 平台许可 + 受控适配器 + 持久回执/账本 | 采用；复用身份/Lease/委托，每次操作仍受当前范围约束 |
| 首期重建完整 IAM/沙箱平台/自动外部回滚 | 超出范围；必要的可信执行边界仍必须明确，不能以延期豁免 |

先实现跨成果共用的输入、许可、账本及回执合同，具体 Runtime 工具由 FD-027 接入，计划消耗由 FD-026 接入，决定展示/送达由 FD-028 接入。共享机制只在本 FD 拥有。

为避免完整交付循环，本 FD 同时完成现有任务/Runtime 对新许可的真实消费，而非只提供 permit API；FD-027 负责新增动态配置的消费，FD-028 负责正式问题/代理决定的新增消费，FD-026 负责新图消费。它们不能成为本 FD 完成的反向前置。共同的 Lease 安全挂起/继续及目标准入门禁先在本 FD 固定并实现，不另拥有问题/渠道或图状态。

## Solution

### 固定输入与正式成果

任务创建时固定目标、范围/验收、计划版本、配置摘要、Skill/知识版本、上游 task/attempt 与报告/代码引用。沿用 TaskInput；新增必要摘要和配置引用时扩展明确字段，不靠拼接长对话。领取和执行检查引用存在且与固定版本一致；上游更新产生补充或替代，不改写在途依据。

独立工作区固定基线、任务/Attempt 和结果版本；并行改动通过独立集成任务汇合，不共享可写目录。正式交付包含目标范围、resultRevision/基线、修改说明、真实命令及结果、未运行检查、未解决问题和上游来源。没有实际验证不能写 passed；是否独立业务审查由计划/策略决定，本次 FD 工程审查仍遵循工作流要求。

### 真实工具许可边界

候选操作许可绑定平台实例、owner、plan/execution、task/attempt/Lease、工具/动作、资源集合、参数摘要、到期及授权版本/撤销世代。配置只声明需求；实际操作前由平台校验当前身份、任务和授权，再交给已登记的适配器执行，结果保存正式回执。缓存不能把撤销/到期忽略到下一任务才生效。

信任边界为平台和受控 Worker 适配器代码；模型、生成的 Skill/计划、仓库内容及工具参数均不可信。平台许可不能约束脱离适配器运行的恶意宿主管理员，因此受控适配器及其资源隔离是部署前提，不是模型自报能力。操作请求使用封闭 DTO，至少包含 operationId、task/attempt、当前 Lease、toolId、资源引用、参数摘要及 expectedGrantRevision；禁止从模型提供的任意 URL 获取许可或结果。

首期建议工具目录为：指定仓库/固定输入的受限读取与搜索、指定隔离工作区写入/编辑、平台受控的本地 Git 结果操作；验证命令作为独立显式许可、明确 argv/工作目录/资源及隔离策略的适配器。网络、任意 shell、依赖安装、push、发布、部署、删除外部数据、生产/交易系统均无默认许可。

路径须在适配器实际访问时解析并校验，不只做字符串前缀判断；禁止路径穿越、跨根及链接逃逸。进程环境不能继承平台/私人凭证。允许执行仓库测试代码本身也可能访问外部资源，因此“命令白名单”和“独立工作区”不等于完整隔离；所选执行后端必须给出可执行的资源限制，或将相应命令保持不可用并在调度前报缺口。不能只加一个 permit API，却让 Runtime 原生工具继续旁路执行。

上述目录是首期政策建议，尚未获授任何真实操作权限。实际任务还需用户配置工具/资源范围；本 FD 的 auto 不授权生产 Worker 操作任意仓库。

### 已确认的计量与未配置行为

业务回跳按 planId+loopId 累计：初始另计，默认三次回跳。预留/生效/追加/消耗以稳定操作 ID 幂等落库，重启、换 Worker/授权不能清零。追加量和范围来自具体决定；秘书仍需有效委托与适用 policy，撤销后未生效决定不可使用，重复决定不得重复增加额度。

建议提供独立预算维度：执行时间为各 Attempt 的实际执行时长总和（含失败，排除队列/人工等待；并行执行相加）；任务规模为创建的业务 WorkTask 数（含新业务回跳及继续任务，技术 Attempt 不增加任务数）；成本为有明确计费依据的消耗，单位、币种和价格版本由用户配置。无法取得用量或定价不能冒充零费用，须显示 UNKNOWN 并按所选政策处理。计量、预留及并发结算由平台统一执行，事实收尾与新工作准入分开。

2026-10-23 用户确认采用准入阈值：到限停止新派发及推进，在途按已有授权收尾，记录真实消耗并申请追加；不承诺最终消耗绝不超出，不自动取消在途。此前候选的“时间到限立即取消/保证确定上界”没有被采用。并行准入仍须原子计数和有界预留，结束按真实事实结算；UNKNOWN 不自动返还。具体价格/单位和本次获准暴露来自实际用户配置，不在此虚构。

用户选择 A：时间、成本、任务规模的所需上限未配置时，先等待用户配置，不准入自动执行；B（只限制回跳）和 C（统一默认限额）作为比较过的选项保留，不实施。精确数值、成本单位/价格及生效范围是实际计划配置，不是仍需在本 FD 询问的默认值。

### 幂等、恢复与 UNKNOWN

业务转移、问题决定、额度追加、工具操作和回执各有稳定标识和参数摘要。持久化唯一约束保证同一请求同一结果，不同参数复用 ID 报冲突；不会换 ID 逃过去重。执行意图在外部操作前保存，完成后记录真实结果；操作无法与数据库单事务提交时，未结意图为待核对，而非自动重做。

可核对的首期本地成果包括：固定 Git 提交/分支与预期基线、文件内容摘要，以及适配器的有界结果记录。编译/测试执行不天然无副作用；结果丢失不能只因“读不到报告”就重新运行。无法判断的外部效果保持 UNKNOWN，由当前有权限的人类经控制台基于固定 task/attempt、证据和明确结论核对，秘书仅转交；不默认委托核对权限、不自动退款、不自动重试或回滚。

重启恢复读取实例/世代、任务/Attempt、Lease、许可、消耗及回执。过期/失联任务先区分无副作用、已核对和 UNKNOWN，不能按普通 Lease 恢复路径重放未知外部效果。完成和停止确认仍可如实落库，但不会绕过暂停/终止门禁推进下一工作。

### 持久化与 API

沿用 authority、execution、output、workspace 的所有权，不新建第二套委托身份。通过端口把许可/账本/固定输入供 workflow 和 Python 使用；接口保持 `/api/r1/`，人类和机器路由按现有认证闭集区分，操作载荷封闭、限长且无私人策略原文。

新增迁移承载新运行的固定引用、工具许可/意图/结果及维度账本，事务和唯一约束覆盖重复/并发提交。不改旧迁移、不执行真实数据库操作；用户自行删除旧运行库，新运行仍必须可恢复审计。新库不继承旧身份、授权、额度、UNKNOWN 或回执。

### D029-01：确定的执行边界与启动顺序

共享协议为 `aiw.execution.guard.v1`，准备引用、操作和回执均包含协议号及内容摘要。beginOperation 在现有 authority 目标准入锁内核对当前身份、Task/Attempt/Lease、精确资源和授权撤销世代，并原子写入 STARTED 意图及预算预留。该提交是操作开始的线性化点：先提交的开始属于已授权在途，随后撤权阻止新操作但不伪造回滚；先提交撤权则开始被拒绝。适配器不接受可缓存后任意启动的新许可，只立即消费本次唯一 operationId；进程中断后查询该意图，不直接重新执行。

平台/受控 Worker 是可信计算边界，模型和仓库代码不可信。实际项目文件仅由 broker 访问，模型后端不直接取得项目目录或平台凭证。文件工具拒绝绝对/上级路径、链接或重解析点逃逸和受保护元数据；同一工作区操作串行化，文件读取按固定大小返回，写入以明确版本/摘要拒绝并发覆盖。项目命令执行时禁止并发文件工具，防止访问检查与外部修改竞争。

受控 Git 只支持固定的本地状态、差异、暂存、提交及集成动词，参数按任务固定引用构造，不能接收 shell 字符串、任意 option、远程 URL 或发布动词。使用最小环境、空的全局/系统配置、禁用 hooks/fsmonitor/pager/external-diff/textconv；准备阶段拒绝包含执行型 filters、include 或其他未支持配置的仓库。项目工具不能写 .git 及平台元数据，每次 Git 操作前复验配置摘要。Git 配置不能因为“本地命令”而获得隐含执行权。

命令适配器采用单独的 Codex App Server `command/exec` 进程作为受限 argv 执行器，不调用模型；两种模型后端复用该执行器。仅 Linux/WSL 广告该适配器，要求宿主预配置可委托 cgroup v2 根及可执行相应文件/网络权限 Profile。平台不安装 CLI、不修改系统 cgroup 权限或提权。每次操作的可信启动器先进入专用 cgroup 再 exec App Server，后代留在该组；命令使用封闭 argv、固定 cwd、清空敏感环境、明确 timeout/output cap 和专属 processId，按许可配置资源限制。暂停/预算阈值不取消已开始操作；显式取消、Lease 丢失及失败收尾通过 cgroup.kill 并确认 cgroup.events populated=0 后才认定执行已静止。未知或权限失败保留 UNKNOWN、工作区和槽位，不报告已停止。

命令权限 Profile 默认拒绝根目录读取，仅允许精确工作区及必需工具链只读路径，禁止凭证/宿主私库/平台配置/Unix socket，网络关闭。原生 Windows 的 OpenAI 模型/文件工具仍可使用，但不广告该 Linux 命令能力；需要命令的任务只派给兼容 Linux/WSL Worker。实际资源根、工具链和额度由授权配置提供，无可用适配器时准备阻塞而非在领取后失败。新增宿主执行前置是运行配置要求，不授权本次会话执行系统配置或真实项目命令。

### 双模型后端的工具路径与兼容性

OpenAI Agents 仅注册 broker 提供的受控 function tools。Codex App Server 在空目录和专属、由操作者预先配置认证的干净 home 下运行模型线程；不自动读取/拷贝实际登录凭证。其项目读写/命令通过 dynamicTools→item/tool/call→同一 broker。配置关闭原生 shell、托管搜索、apps、multi-agent、无关插件/MCP/Computer Use/环境入口，原生文件能力使用根读取拒绝且无项目根的命名权限 Profile；PreToolUse 拒绝原生工具仅为补充，不能替代 OS 权限。模型传输仍由可信后端处理，项目命令的进程和环境均不接触其凭证。

准备前检查有效配置和可用协议能力：命名 Profile 及生效 ID、无冲突旧 sandbox 设置、实际 source/layer、空项目范围、已关闭的旁路能力、dynamic tool 请求/回执及 thread/tokenUsage 结构。线程策略或关键能力不能确认就明确拒绝；不把未知新字段忽略后当安全设置成功。RPC 只处理当前 thread/turn 的登记工具，未知请求拒绝并终止该次执行。命令执行器使用单独的 command/exec permissionProfile，不将模型线程的权限当作命令权限。

2026-10-23 用户明确要求不限定 Codex CLI/OpenAI Agents SDK 版本，发现兼容问题修改适配层。因此不以字符串版本号作为支持白名单，也不要求安装某个精确 SDK 版本；记录实际版本和协议摘要用于追溯，按关键功能/字段判定并适配接口差异。不能以“兼容旧版”为由放宽资源或授权边界，亦不自动安装、下载、更新或登录。

证据：本机 Codex 0.163.0 的实验 schema 已按用户授权导出至 `.ai/issues/drafts/fd025-029-codex-0.163.0-schema/`，可见 dynamicTools、item/tool/call、tokenUsage、command/exec.permissionProfile 与 activePermissionProfile；网站较新的 legacy read-access 字段未出现在该本机 schema，采用命名 Profile 路径并在实际部署预检，不能声称已运行通过。来源为 [App Server](https://learn.chatgpt.com/docs/app-server)、[权限 Profile](https://learn.chatgpt.com/docs/permissions) 和 [配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

### D029-02：账本、挂起及故障窗口

账本维度 TIME_MS、TASKS、COST_MICROS 采用非负整数，成本单位/价格版本由计划显式配置；LOOP_BACKJUMPS 使用 plan+loopId，默认 limit=3。配置更新保留已结算/在途预留，不清零。新准入条件 available=limit−used−reserved>0 且所需预留足够，意图和预留同事务提交；每个业务任务/操作/追加决定唯一键只生效一次。时间/成本预留来自已批准执行配置中的单次额度，不把模型猜测当新授权；在途实际消耗允许按用户确认的阈值政策超过预留，真实结算后停止后续并申请追加。

TASKS 在业务任务创建时消耗一次；技术 Attempt 不增加任务数，但其实际时间/成本计入。TIME_MS 按各 Attempt 实际执行区间累加，等待/排队不计；暂停中在途执行仍计时。COST_MICROS 用固定价格版本及实际用量计算应用估算，不冒充服务商发票；缺少用量/价格显示 UNKNOWN。用量累计向量需单调，重复报告不重复计费，回退或不一致进入核对，不减历史消耗。

开始提交前失败：没有操作意图，不执行。意图提交后、执行启动前失联：只有可信未启动证据才释放预留，否则 UNKNOWN。执行已开始、结果丢失：保留意图和预留，核对 Git/文件/执行回执；不因超时重做。结果已保存、响应丢失：查询原回执。结束失败或取消仍结算已发生消耗，只有确认未发生部分才可释放；UNKNOWN 不自动退款。实际执行与 DB 没有分布式原子事务，开始提交后进程崩溃无法确定是否执行的窗口明确由有权限的人类核对，不宣称 exactly-once 外部效果。

共享安全挂起新增 TaskState.YIELDING/WAITING_INPUT 和 AttemptState.YIELDED；`prepareYield` 保留 Lease/槽，`ackYield` 在确认该执行及所有工具静止后，以精确 Lease 和 opId 原子保存 checkpoint 引用、终结 Attempt/Lease并释放槽。开始挂起后不再准入工具；未确认不得释放。重复 ack 返回原结果，旧 Lease 的 complete 拒绝；继续任务需当前回答及控制/预算许可，并保留 resumesTaskId。FD-028 拥有问题和继续申请，FD-027 提供真实退出确认，本 FD 不存另一份问题状态。

继续事务同时把旧任务 WAITING_INPUT→CONTINUED，写入唯一 successorTaskId/逻辑输出槽绑定并建立新任务；CONTINUED 是无在途资源的非成功终结，不能当作成果已完成或失败分支已跳过。单向 lineage 不允许环或两个有效后继；当前计划步骤/图 execution 的有效任务绑定与问题 APPLIED 回执在同一事务切换。依赖解析、计划步骤定位和正式输入读取通过同一 lineage 解析器找到当前有效任务，只在续行链最终产生真实完成成果时满足原输出槽；历史任务/Attempt/已固定输入不重写。取消/替代与继续竞争同一源版本，失败者返回当前正式结果而非另建任务。原任务不得永久留在 WAITING_INPUT，也不得为解除阻塞伪写 COMPLETED。

目标准入控制与授权撤销世代分开：pause/预算阈值只关新任务/推进，已领取执行可在当前有效权限内收尾；显式取消/撤权禁止新的相关工具操作。锁序沿用 run/target→worker→task 的既有领取顺序，新增行锁依此放置，禁止从工具结果回调反向持锁。渠道 outbox 在正式记录事务提交后投递，不能用发送成功取代状态提交。

追加沿用现有 owner/个人凭证/有效委托和有限 ActionScope，新增明确的预算追加动作与固定参数（目标、维度/loopId、增加量和累计上限），不复用普通聊天或通用审批扩大权限。秘书政策留本地，平台只接收本次最小决定投影，重查当前世代/到期/范围；未覆盖则交人类。收到相同申请或决定仅产生原增量回执。

### 人类决定、执行上下文及 API 接合

PlanExecutionPolicy 保存 owner/plan、revision/digest、工具和资源范围、获准命令配置、预算/价格版本及有效期，作为明确人工确认的执行政策，不是另建身份系统。配置/计划草稿引用它不自动生效；任务 AuthorizedTaskContext 必须固定真实来源决定、owner/target、政策/配置版本和限制范围。普通 Worker 由当前 task/attempt/Lease 证明执行所有权，owner 从正式上下文取得，不能由请求正文自报；秘书仍使用现有独立个人凭证与有效委托。

人工动作使用当前已认证 owner、CSRF 及动作角色校验；代理动作还须现行 ActionScope 覆盖确切目标/参数和预算增量。工具操作取“原获准范围与当前有效政策”的交集，变更政策不能静默扩大在途范围，撤销/到期阻止新操作。没有政策/来源决定的首期闭环任务不进入可领取状态。旧 Go/TS 未支持新 guard/config 协议时不能领取该闭环任务，不以旧广告能力冒充支持。

Worker 新接口归入既有 `/api/r1/worker-protocol/v1/tasks/{taskId}` 下的 operations（begin/finish/receipt）、yield（prepare/ack）和固定输入/政策读取，延续共享机器边界及精确 Lease 检查，不接受浏览器 cookie 替代。人类政策/预算配置、追加和 UNKNOWN 核对归入 `/api/r1/authority` 的明确方法/路径闭集，保持人类/机器路由分离。DTO 拒绝未知字段、限制大小，平台/私人凭证和策略原文不进入模型上下文或回执正文。
