# 许愿池：从想法到工作流

入口：`/ui/goals`。许愿池将模糊想法整理成可实施需求或可执行流程，再生成工作流草稿。

## 使用流程

1. 新建愿望，保存正文、缺失信息和需要的参考资料。
2. 打开讨论窗口，与 Worker 澄清需求。回复保留在对话中，不自动覆盖正文；确认后由用户更新需求。
3. 保存愿望快照。缺失信息未解决时，可以明确接受并保留“未就绪”标记。
4. 点击“生成工作流草稿”，或保存快照时勾选同时生成。普通只读 Worker 整理流程，实际业务尚未开始。
5. 在统一执行详情中查看整理过程。成功结果经校验后打开 `/ui/workflows` 中的草稿，用户检查和修改，再明确启动业务。

不再使用独立角色配置、步骤分析、应用推荐及准备旧 Plan 操作。对应旧许愿池 API 和系统中的独立推荐设置页已移除，不提供兼容跳转。

## 执行与恢复

重复点击复用原整理任务，不重复调用模型。失败后可查看原始结果，明确选择重新生成；进行中的任务需要先完成或停止。导入请求失败时，点击统一工作流页面的“刷新”重试同一幂等导入，不会重新提交整理任务。

生成只使用快照中已确认的标题、正文、缺项和就绪状态，不自动发送其他附件或私人对话。超过当前整理任务输入限制会直接说明原因，不截断需求。

## 参考资料与附件

附件可选，可以辅助澄清，也可以作为原始需求。讨论时明确选择要外发的资料；上传文件不会自动发送给模型。转换失败或内容不完整时保留原件，由用户核对，不将图片或扫描件自动视为已理解。

用户根据讨论形成的已确认正文是生成草稿的依据。完整知识库接入和附件直接参与工作流整理仍在后续实施范围。

## 保存、删除与权限

快照按原需求版本保存，后续编辑不修改已有快照或运行。愿望可以删除和恢复，已有任务与工作流不会连带删除。请求结果未确认时先核对原状态，不自动重做。

当前操作沿用控制台登录和账号归属校验。需求整理不授予工具、文件或发布权限；工作流草稿不会自动启动业务。
