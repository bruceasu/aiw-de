# AIW 通用 Coding Agent 能力增强需求

**状态：需求讨论稿，供产品、开发和环境维护人员共同阅读。**

## 要解决的问题

一个普通的编码任务经常需要多次运行程序才能完成。例如，Agent 修改 Java 代码后运行测试，发现一个边界条件失败，再根据日志修复并重跑。命令取决于上一步的结果，任务开始前很难列全。AIW 应让现有 Coding Worker 自主完成这个循环，并通过现有任务流程交付代码差异和验证结果。

## 首版要求

1. **编码任务原则上放开 Shell。** Agent 可以在分配给任务的执行环境中运行常规 Shell 命令，包括项目脚本、管道、重定向、构建、测试和调试。用户无需预先登记每条命令或逐条批准。该决定涵盖 Shell 对执行账号可访问的文件、进程和网络的实际影响。
2. **两种 Runtime 都支持这种工作方式。** 使用 Codex App Server 或 OpenAI Agents SDK 的任务都应能完成同一开发流程。允许修改现有 Worker、工具接入和授权逻辑；具体采用 Runtime 自带的 Shell 还是复用现有命令执行器，由实现评审决定。
3. **首版允许通过物理环境隔离。** 若接入 SDK Sandbox 成本较高，可先使用专用机器。部署方应明确执行账号能接触的仓库、凭证、网络和服务，尤其要确认 Worker 自身的凭证是否对命令进程可见。专机的具体配置及其隔离效果需要现场验证。
4. **保留可核对的任务结果。** Agent 应报告实际运行的关键命令、结果和代码变更。任务取消或失去执行权后，应停止其命令，并避免旧任务继续修改后续任务使用的工作区。
5. **专业能力按任务加载。** 在同一个通用 Worker 上组合任务需要的技能、知识和工具。AWS 是首批应用场景。普通编码任务无需加载 AWS 材料；编写 S3 SDK 代码可使用相关技能和文档，访问真实云资源另行授权。

## 当前依据与待验证事项

本地已运行 Python Worker 的配置入口，确认在 OpenAI Agents 模式设置旧开关 `AIW_AGENT_ALLOW_SHELL=true` 会被拒绝。源码显示，Codex App Server 当前也有权限配置校验，受控命令工具接收预登记的命令 ID。现有 Linux 命令执行器已有资源限制和取消回调，可作为实现参考。

尚未实测 AIW 启动的 Codex App Server 能操作哪些文件、实际暴露哪些工具，也未验证专机上 Worker 异常退出后的命令清理。选定实现前，应以实际部署账号和无敏感数据的测试工作区核实这些行为。[原技术研究与源码索引](./AIW_General_Coding_Agent_Capability_Enhancement_Spec.md)

## 如何判断需求得到满足

| 场景 | 可观察结果 |
|---|---|
| 同一普通修复任务分别使用两种 Runtime | Agent 均能编辑文件、运行测试、根据失败输出修复并重跑；用户全程无需添加命令白名单或批准单条命令。 |
| 在专机上中断长时间运行的测试 | 能确认任务停止后子进程已结束；模拟 Worker 异常退出时，能在机器接收下一任务前确认残留已清理。 |
| 分别执行普通编码任务和 Java S3 编码任务 | 普通任务完成时没有加载 AWS 工具；S3 任务可以使用相关专业资料并在没有真实云账号凭证的环境中完成代码验证。 |
