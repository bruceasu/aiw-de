# 个人秘书动作授权

在 `/ui/authority` 的“动作授权”页签中，选择秘书、功能分组和一个动作，设置到期时间及累计次数，再核对并确认。功能分组用于查找动作，选择分组不会一次授予整组动作。

“限制适用范围”可以不填。不指定时，覆盖当前账号现有及以后新增的全部适用目标，这些目标共用本条授权次数。选择计划或任务只会收窄范围；下拉框列出当前账号可用的目标，无需记忆标识。任务选择最多显示最近 100 项。

每位秘书的同一种动作只有一个当前授权期。明确新建授权期会替代旧期（包括同动作的旧精确能力），新期从零计数，旧次数和回执保留。相同原请求重试不会新建一期。次数用尽、到期、撤销或角色变化后，不再接受新操作。撤销不改写历史回执，在途执行仍按既有停止规则处理。

这里的动作次数是实际上限，多个目标共享；受理成功计一次，拒绝和事务回滚不计，相同原请求重放不重复计数。后续技术失败或取消不返还该次动作额度。执行时间、费用等仍遵守部署的计量模式，默认仅记录；不能用“仅记录”绕开人明确设置的动作次数。

## 可以选择哪些范围

| 动作 | 可选范围 |
| --- | --- |
| 重试失败任务、批准/拒绝审批、创建/执行发布、回答工作问题 | 全部适用目标、指定计划、精确来源任务 |
| 追加修复、设置模型、恢复评审及其余计划动作、具体额度追加 | 全部适用目标、指定计划 |
| 调整运行并发 | 平台唯一全局并发对象，需人工确认归属 |
| 排空、离线普通 Worker | 本账号已确认归属的全部普通 Worker，或指定一个普通 Worker 并人工确认其归属 |

指定任务仅作用于该真实来源任务的适用操作，不包括同计划其它任务。步骤级修复/模型/评审不提供任务范围。不能认领其它账号的对象。全局并发在人工登记时核对固定 `GLOBAL:FLEET` 的归属；普通 Worker 可在人工选择指定对象时首次确认归属。机器准备操作不会首次认领这些对象。专用个人秘书身份不能用普通 Worker 排空/离线动作控制。

授权不会直接执行任何业务，也不会自动启用秘书、托管计划或授予工具。计划托管是独立授权。秘书在后续具体操作时选择目标和必要的业务内容，例如修复范围、模型、跳转步骤、发布路径或明确的重试副作用确认；内部版本、状态、摘要和请求身份由平台固定。发布等复合操作若还需要另一种动作权限，两种权限分别核对和计数。

## 机器接口与原请求恢复

平台接口均位于 `/api/r1/authority`，使用已有专用机器认证；人工登记、撤销和选择项查询使用人工登录、角色与 CSRF，不可用机器凭证代替。

| 接口 | 用途 |
| --- | --- |
| 人工 `POST /action-permissions/state`，请求 `{}` | 当前账号权限、动作分组及最小计划/任务/普通 Worker 选择项 |
| 人工 `POST /action-permissions` | 新建一期，字段为 requestId、ownerId、workerId、action、scopeKind、scopeId、maximumUses、expiresAt、expectedPriorId |
| 人工 `POST /action-permissions/{id}/revoke` | 幂等撤销原授权，保留历史 |
| 机器 `GET /action-permissions` | 本账号、本秘书的授权目录 |
| 机器 `POST /permission-actions/prepare` | 用 requestId、permissionId、targetId、可选 step/sourceTaskId、必要 parameters、可选原 projectionJson，固定一个惰性候选 |
| 机器 `GET /permission-actions/{requestId}` | 查询同一个原候选；返回原 Envelope、权限引用及 PREPARED/STALE，不重建快照 |
| 机器 `GET /permission-questions?permissionId=…&planId=…` | 仅在相应有效权限范围内读取适用的正式问题，不扩大通用 read_scope |

`expiresAt` 为 epoch 毫秒，`requestId` 为规范 UUID，`scopeKind` 为 ALL/PLAN/TASK/WORKER。ALL 的 scopeId 为 null；expectedPriorId 是登记时观察到的当前授权期或 null，冲突后须重新读取并明确核对。原候选固定完整具体选择，只返回原信封和最小结果，不输出包含业务正文的完整 snapshot。

准备阶段不执行动作、不计次数。固定成功后仍提交原 `/actions` 或 `/question-replies`，不能修改原 Envelope 或用子能力另造 requestId。正式问答保留选中问题、版本、源任务、原答案投影以及原实例/boot/世代约束；私人聊天不自动投影。授权额度追加使用正式申请的原 UUID。

参考秘书新增本地 `/api/business-permissions`、`/api/business-questions`、`/api/business-action` 和 `/api/business-action-status`。适配模块 `business_actions.py` 先将选择和原请求身份写入私有 decision，再准备平台候选，保存原 Envelope 后才进入既有持久 outbox。结果未知时保留原标识，显式恢复先查询同一候选；旧实例的 STALE 候选不自动重建，已排队请求按原回执核对。此接口适配不改写秘书的其它私人页面或模型逻辑。

旧精确授权在尚未迁入新权限的动作上继续原协议。一旦该秘书/动作进入新权限期，旧同动作能力被替代，之后即使新期到期或撤销，也不会退回旧创建接口另开平行权限。原历史回执仍可由同 Owner、同秘书查询。新增 V18 仅增表/索引、保留旧记录；编译和静态审阅不代表已执行数据库迁移或运行验收。
