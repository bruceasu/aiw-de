## 使用者、问题、目标与非目标

使用者是需要暂时离线、但仍需控制工作流决策权限的人类管理者。目标是在明确授权内处理真实人工卡点，并让人类随时查看、修改、撤销及复用授权，范围外继续由人类决定。

本 Issue 的目标范围包括：自然语言与结构化规则结合的授权编辑、代理人工启停、服务端权限执行与审计、授权查看、常见事项目录，以及本系统内跨项目/计划/代理的授权模板复用。第一个具体业务场景是“多轮未解决后，按用户可编辑授权追加轮次并提升模型能力”。下文区分用户已确认目标和整理者提出的具体规则。

非目标：本次不实现功能，不批准 Issue，不创建 FD/Task/OpenSpec change，不启用运行时代理授权；不自动接管所有确认事项，不假定用户离线即自动启用，不默认授予目录中全部动作的操作权限，也不默认支持跨系统模板导入导出。业务数值由使用者配置，不要求现在固定为统一产品默认值。

## 1. 用户已明确的目标与规则

用户希望在自己不在线时，让一个决策 AI Worker 代理处理流程中原本需要人确认的事项。

1. Worker 只能在用户授权的范围内决定事项。
2. 不在授权范围内的事项仍由人类决定，Worker 不得擅自超越权限。
3. 用户可以主动让这个 Worker 上线或离线。
4. 用户提供的具体示例：经过三轮仍未解决时，可授权追加三轮，并提升 Model 能力。
5. 授权由用户自行编辑，触发条件、轮数、允许的模型等不能作为固定业务规则写死。
6. 需要整理常见的人工确认/授权事项，便于用户逐项编辑。
7. 用户认可自然语言编辑、系统整理为结构化规则并展示供其修改确认的方式；最终按结构化规则校验执行，同时保留原始表达。
8. 人类需要查看当前已授予代理 Worker 的授权。
9. 已生成授权应可作为模板，供其他适用场景复用。模板的复制、绑定及启用语义是下文的设计建议。
10. 2026-10-18 范围确认：首期实现 A01–A17 全部动作的代理支持，保留授权编辑、启停、查看、审计和模板复用；支持能力不等于默认授予实际操作权限。
11. 2026-10-18 身份要求：代理通常由独立 AI Worker 承担；只有具备专门代理标识的 Worker 才能代办，服务端必须认证 Worker 身份，防止冒充。专用身份与具体动作授权分别校验；凭证及认证方案留给 FD 设计。
12. 2026-10-18 独立性确认：同一成果的执行、评审、代理批准由不同 Worker 承担；代理批准者不得参与该成果的执行或评审。即使执行者或评审者后来获得代理资格，也不能批准该成果，但可以代理处理其他符合独立性要求的成果。允许不同 Worker 使用相同模型，模型不同不是独立性的必要条件。

13. 2026-10-18 撤权确认：人类下线代理或撤销授权后，已生成但尚未提交生效的候选决定立即失去执行资格。已经生效的决定保留记录；正在执行的工作按各动作的停止规则处理，撤权不等于自动回滚。

14. 2026-10-18 人工优先原则：用户明确“人类的意见最优先”。代理不能覆盖人工决定；事项已由人类接管时，代理恢复上线或重新获授权本身不构成接回依据。人工指示改变事项或处理归属后，旧代理候选决定不能继续提交生效。此原则不替代操作者身份、权限和现有业务条件校验。

15. 2026-10-18 授权冲突与时间线确认：同一事项的适用授权存在允许/禁止冲突时，原则上按禁止处理并转人工；判断需同时考虑规则生效时间、版本和明确替代关系，不能简单采用最新一条允许。先允许、后撤销或禁止时，阻止尚未生效的代理决定；先禁止、后允许时，只有后来的允许明确解除或替代此前适用的禁止，并满足当前其他授权与业务条件，才可执行。仅新增允许但未声明替代关系时，仍按冲突处理。人类接管后，代理恢复上线不构成自动交回。
16. 时间线依据服务端记录的生效时间与版本；代理提交前重新校验当前规则，审计保留实际决策使用的版本。已生效决定不因后续规则变化自动回滚，继续遵循第 13 项。

17. 2026-10-18 轮次与计数确认：追加执行的一轮定义为“同一步执行一次，再经过独立评审”；评审未通过仍属于已完成的一轮，不以成果通过验收为计数前提。技术失败重试、仅对现有产物重新评审分别计数，并各设可配置上限，不与追加完整执行轮次混用额度。具体限额由用户配置，不写死为统一产品数值。执行中断或失败时，完整轮次额度如何预留、结算与释放留给 FD 设计，不能借此绕过技术重试或完整轮次上限。

18. 2026-10-18 累计额度确认：同一 Plan 的同一步骤始终共享累计额度；完整执行轮次、技术失败重试和仅重新评审仍分别记账、分别受限。更换 Worker、复制或替换授权不能清零历史消耗或自动获得新额度。人类补充额度时明确记录增加量及影响对象，保留历史消耗，不以重置计数代替补充；具体上限仍由用户配置。

19. 2026-10-18 有效期确认：每份授权必须设置到期时间，具体期限由用户配置。到期后停止代办并转人工，代理不得自行续期；尚未提交生效的候选决定不能继续使用已过期授权，已经生效的决定不自动回滚。人类续期或重新授权须明确确认，并保留同一 Plan 同一步骤的历史消耗。

20. 2026-10-18 默认启停确认：代理默认关闭，必须由人类明确启用；进程重启、重新注册或心跳恢复均不能自动开启代理。进程在线状态、人工启用状态和具体授权有效性分别校验，技术恢复在线本身不恢复代理决策权限。

21. 2026-10-18 无法判断时的处理确认：代理无法确定授权是否适用、证据是否充分或动作是否满足业务条件时，统一保留申请、说明原因并转人工；不默认批准，不把“无法判断”当成业务拒绝，不因等待超时自动通过。转人工时保留现有证据和代理建议，供人类独立判断。

22. 2026-10-18 发布范围确认：A12 同时支持代理创建输出文件发布计划和实际执行发布，两者分别授权。仅获得创建发布计划权限，不能实际发布；实际发布仍须满足该动作原有业务条件、当前授权、目标范围及证据要求。本次确认的是产品支持范围，不构成当前环境的发布授权。

23. 2026-10-18 人工待办归属确认：转人工的原申请默认交给原授权人，同时允许具有该事项处理权限的人类管理员接管；无人处理时持续保留待办，不自动交回代理，不因等待超时自动通过。保留原申请身份、当前状态、证据、代理建议和转交原因，人类以自身身份和权限独立处理。具体交接界面、通知及领取机制留给 FD 设计；本次不向任何人发送消息。

24. 2026-10-18 主动交回确认：有该事项处理权限的人类可以主动将尚待处理的申请交回代理。交回后，代理必须基于最新事项状态和证据重新判断，服务端重新校验已认证代理身份、人工启用状态、当前有效授权、事项版本、业务条件及剩余额度；不能直接执行交接前的旧候选决定。交回本身不启用代理、不续期或扩权、不重置历史消耗，也不撤回已生效的人工决定。

25. 2026-10-18 非步骤动作额度确认：发布、删除、调整 Fleet 并发等不属于某一步骤的动作，按“目标对象＋动作类型”共享累计额度；更换 Plan、Worker 或授权不能绕过上限。具体限额由用户配置，人类明确补充额度时记录增加量并保留历史消耗。目标对象需绑定稳定、可校验的业务身份，不能仅靠名称、别名或调用方声明判断；各动作的目标映射、计数结算及并发扣减留给 FD 设计，无法可靠判断时转人工。不同动作分别记账，创建发布计划与实际发布也不得混用额度。

上述第 10–25 项来源于本次 grill-with-docs 讨论及用户的明确答复；用户确认具体规则，不代表整体 Issue 已获批准。

示例用于说明产品能力，不构成当前环境的实际代办授权。上线、授权范围与具体决策是不同概念：上线本身不代表获准决定所有事项，这是由用户明确边界推导的需求解释。

## 3. 建议的业务边界（待确认）

### 3.1 明确授权

- 人类创建、修改、撤销授权；代理只能使用已有授权，不能自行扩权、续期或创建新的授权。
- 授权是用户可编辑、可保存和可撤销的政策配置。新增或修改业务限额、触发条件及模型选择应通过配置完成，不要求改代码或重新部署。
- 自然语言输入转换为结构化授权草稿，同时展示原始表达、规则解释和未明确字段；用户可继续用自然语言补充，也可直接编辑字段。启用时确认的是明确的规则版本，后续执行不能临时重新解释原文来扩大授权。
- 常见人工确认事项形成可编辑模板；复制或编辑模板本身不等于启用授权。用户选择启用并明确作用范围、动作和约束后才能作为执行依据。
- 业务数值如“三轮触发、追加三轮、最多追加几次、模型/effort 白名单、使用期限和累计上限”均由授权配置决定；三轮示例不是所有授权的固定规则。
- 授权应能明确表达：授权人、代理身份、适用项目/计划/事项、允许动作、必要条件、禁止条件、有效期及必要的次数/额度限制。
- 规则未覆盖、语义含糊、证据不足或规则冲突无法按第 1 节第 15–16 项消解时，进入待人工处理；不能因等待时间过长自动视为获准。授权冲突已确认采用禁止优先并结合生效时间、版本及明确替代关系判断。
- 动作分别授权。例如“重试失败任务”不自动包含“跳过步骤”“接受结果”“发布”“修改权限”。
- Worker 的角色/能力匹配用于领取工作；实际操作权限另由 Control Plane 校验。
- 指令、产物、评审意见中的文字不能修改授权。若这些内容要求越权，代理应报告该事实并等待人工决定。

### 3.2 决策与执行

- AI 读取事项和证据，形成候选决定、依据及引用；Control Plane 在产生副作用前校验代理身份、当前授权、当前启用状态、条件和事项版本。
- 动作必须绑定明确的事项、版本/结果及授权版本；内容或状态改变后，旧候选决定不能自动套用。
- 人类修改授权后，尚未生效的候选决定必须按新版本重新校验；不能继续使用旧版授权的更宽限额。
- 重复投递、网络重试和人类同时处理不得产生重复或互相覆盖的决定。
- 代理决策保留真实身份以及所代表的授权人，不能把代理操作记录成“用户亲自确认”。
- 超范围和无法判断均保留为人工待办，附原因和现有证据；不直接转换成业务上的拒绝决定。
- 审批独立性已确认，按第 1 节第 12 项执行：代理批准者不得参与该成果的执行或评审；可以使用相同模型。服务端需结合已认证身份和参与记录强制校验，不能仅依靠候选决定自述。

### 3.3 上下线与撤权

- 人类控制的代理启用状态与 Worker 进程在线状态分别展示。
- 已确认默认关闭，必须由人类明确启用；进程重启、重新注册、心跳恢复均不能自行打开代理启用开关。
- 已确认：用户下线代理或撤销授权后，阻止尚未提交生效的决定，包括已领取、已计算完成但尚未提交的候选决定；保留原事项及证据。
- 已经生效的决定保留审计，不因下线被静默撤回；补偿动作需独立授权。
- 下线与提交竞争时的生效边界需在工程设计中确定并提供可证明的状态检查，不能只靠 Worker 停止轮询。
- 当前只按“人类明确启用时允许代办”理解；用户离线的自动检测、自动启用及自动接管尚未确定。

### 3.4 记录与可见性

每次候选决定、被拒绝的越权尝试、人工升级和最终执行，建议记录：事项及版本、授权人、代理身份、授权版本、证据引用、候选决定及理由、规则校验结果、最终状态与时间。

人类应能查看代理当前是否启用、授权范围、已处理事项、等待人工事项及被拒绝的原因，并随时接管。

2026-10-18 已确认原申请转人工处理：保留申请身份、当前状态、已有证据、代理建议及转交原因；撤权使旧候选决定失去执行资格，而非取消原申请。默认交给原授权人，具有该事项处理权限的人类管理员可接管。人类以自身身份和权限，基于最新事项状态独立决定；代理建议只供参考，不能直接视为人工已确认。无人处理时持续保留待办，不自动交回代理，不超时通过。

### 3.5 授权查看与模板复用（建议交互）

- 控制台提供授权中心，按授权人、代理 Worker、项目/Plan、动作与状态筛选；Worker 详情可查看该代理获授的授权。界面同时展示代理启停与授权启停/失效状态，能回答“这份授权现在是否允许该代理执行”。
- 授权详情包括原始自然语言、当前结构化规则及可读解释、适用对象、版本、有效期、已用/剩余额度、变更记录和关联决策；提供编辑、停用、撤销和另存为模板入口。
- 另存为模板保留可复用的条件、允许动作、限制和原始表达；项目/Plan/Worker 等绑定与时间参数需要明确保留或参数化，不能把缺少目标的规则默认为全局授权。
- 在其他项目、Plan 或代理使用模板时，先形成新的授权草稿，填写参数并展示与原规则的差异；确认并启用后才生效。模板本身不是代理可以使用的授权。
- 模板与实际授权分别有版本；生成时保存来源模板版本，实际授权固定使用已确认的规则快照。修改模板不自动变更已启用授权，已启用授权的修改需要人类明确确认。
- 模板不包含历史决策、消耗计数、运行中租约或身份凭证。对同一任务/Plan 重新复制授权不能自动重置仍适用的累计限额；增加额度需明确授予并审计。
- 删除模板不自动改变已发出的授权；用户从授权中心查看和撤销实际授权。跨不同系统的导入导出尚未确定，不因“可复用”而默认支持。

## 5. 目标验收例（提议，未执行）

1. 人类给指定 Plan 的指定动作授权后，已启用代理可在条件满足时处理，并留下可追溯记录。
2. 相同动作发生在其他 Plan，或所需条件缺失时，服务拒绝执行，事项继续等待人工。
3. 授权过期、被撤销、代理已下线后，即使 Worker 仍运行且持有旧任务/结果，也无法提交决定。
4. Worker 重新注册后不能恢复被人类关闭的代理启用状态。
5. 人类先处理或事项版本已变化时，旧代理提交得到明确冲突，不能覆盖人工结果。
6. 重复提交同一决定不重复执行；同一事项的冲突决定不能同时生效。
7. 无法判断授权是否适用时，生成带理由的人工待办，不能默认通过或超时通过。
8. 授权维护、人工决定与代理决定在记录上可以区分；所有处理都能追溯到有效授权。
9. 修改追加轮数、模型配置范围或累计上限后，后续决定按新配置校验；无需修改源码。已有授权额度按已使用量累计，不因重启、重复消息或编辑而自动重置。
10. 用户示例允许的追加执行和模型升级必须同时满足各自限制；任一条件不满足时，不能部分放宽权限或静默扩大模型范围。
11. 常见事项可逐项编辑和启停；新建、复制或预览模板不会自动发起动作或产生实际授权。
12. 人类可从代理 Worker 或授权中心查看全部已授授权，辨别代理离线、授权停用/过期/撤销/耗尽及当前可用状态，并查看每项决定消耗的额度。
13. 同一授权规则用于其他项目/Plan/代理时，经目标参数确认生成独立授权；原授权保持其记录，复制不会带入凭证、执行记录或重置同一对象的既有累计限制。
14. 修改模板不自动扩展已有授权。详情可追溯到模板来源版本、人工确认版本，以及实际决策引用的规则版本。
15. 自然语言中的模糊字段先提示补齐；未解析或未确认的部分不能成为实际决定的权限来源。
16. A01–A17 每项均提供代理执行支持；只配置其中部分动作授权时，其他动作仍不可由代理执行。
17. 普通 Worker 仅自报代理名称、角色或标识，或冒用其他代理身份而不能通过认证时，服务端拒绝代办；通过身份认证但缺少该动作授权时同样拒绝。
18. Worker W1 执行或评审过某份成果后，即使后来获得代理资格及该动作授权，仍不能批准该成果；未参与该成果执行或评审且通过认证、具备专门代理标识的 W2，可在其余业务条件和授权满足时批准，即使 W1、W2 使用相同模型。
19. 人类接管申请或作出决定后，代理的旧候选决定不能覆盖人工处理；代理恢复上线或重新获授权不会自动接回该申请。
20. 同一事项先获允许、后被撤销或禁止时，旧代理候选决定不能提交生效；先被禁止、后新增允许但未明确解除或替代此前禁止时，仍拒绝代理执行并转人工。
21. 后来的允许明确解除或替代此前适用的禁止后，服务端按新生效版本及其余当前约束重新校验；满足条件才执行，并保留替代关系及实际使用版本的审计记录，不能只凭时间较新放行。
22. 同一步执行后经过独立评审，即计一轮，无论评审是否通过。仅重新评审、技术失败重试分别消耗各自次数，不冒充新增完整执行轮次；任何一类达到其配置上限，不能借用另一类额度继续。技术失败重试不能使后续完整执行轮次超出授权上限。
23. 同一 Plan 同一步骤累计上限为 6 轮且已用 4 轮时，换 Worker、复制或替换授权后仍只剩 2 轮；人类明确补充 3 轮后，上限为 9 轮、已用仍为 4 轮、剩余为 5 轮，并保留补充记录。数值仅为验收示例，不是产品固定值。
24. 缺少到期时间的授权不能启用；到期后，即使代理已生成候选决定也不能提交生效，申请转人工处理。代理不能自行续期；人类明确续期或重新授权后，历史消耗仍按第 18 项累计。
25. 新建代理默认关闭；人类关闭后，Worker 重启、重新注册或心跳恢复均不能自行开启代理；未获人类明确启用时，即使进程在线且授权未过期，也不能提交代理决定。
26. 授权适用性、证据或业务条件无法确定时，保留原申请、证据和代理建议，附原因转人工；不能将该情形记录成业务拒绝，也不能在人工未处理时通过超时默认批准。
27. 代理仅获创建发布计划权限时，可以在满足条件时创建计划，但不能实际发布；实际发布须另有明确授权，并按指定文件、目标、工作区与证据重新校验。仅有实际发布权限也不能隐含取得创建计划权限；两类操作均记录真实代理身份与实际使用的授权版本。
28. 转人工后，原授权人能看到原申请及证据；具有该事项处理权限的人类管理员可接管，无权限者不能处理。授权人离线且无人接管时，申请继续等待；即使代理恢复上线或等待超时，也不能自动接回或通过。
29. 有该事项处理权限的人类主动交回尚待处理的申请后，代理基于最新状态和证据重新判断并提交新候选决定；旧候选决定不能直接执行。交回时若代理未启用、授权已过期或额度不足，仍不能执行；交回不自动修复这些条件，也不覆盖已生效的人工决定。
30. 对同一目标对象、同一非步骤动作，额度耗尽后，即使更换 Plan、Worker 或授权，也不能继续执行；人类明确补充额度后才可在其余条件满足时继续，历史消耗保留。不同目标或不同动作按各自规则校验，不能借用其他动作额度。

必填字段缺失或限制含糊时，应提示补齐或停留在草稿；空值不能默认为无限授权。额度规则需要明确累计口径；预算依赖的消耗数据不可获得时，不能假装已经满足预算条件。冲突授权按第 1 节已确认的时间线与明确替代关系判断；无法消解的允许/禁止冲突按禁止处理并转人工。

### 5. 建议的编辑与运行体验（待设计）

1. 用户用自然语言描述授权，或从目录选择模板，系统整理成包含作用范围、条件、动作和限制的结构化草稿；原文和规则同时可查看和修改。
2. 保存草稿时显示缺失字段、规则解释和授权影响；保存/复制草稿不启动授权。用户启用时确认的是明确规则版本，不能在执行时凭原文产生额外权限。
3. 用户启用具体授权，并控制决策代理整体上线或离线。
4. 代理发现待确认事项后说明判断，Control Plane 按最新授权和事项状态校验；校验通过才执行。
5. 目录与授权页展示已用轮数/次数、当前授权版本、已处理记录和待人工事项。
6. 用户随时停用、修改或撤销；修改不自动重置已消耗额度，旧候选决定需要重新校验。

同一 Plan 同一步骤共享累计额度、人类明确补充增加量且保留历史消耗已确认；其他累计范围、自然语言与字段编辑的具体交互，以及多份授权冲突的提示，是后续设计问题。不要求用户现在为所有事项确定固定业务数值。

### 6. 人类如何查看已经授予的授权

建议设置授权中心，并在决策 Worker 详情提供“获授权限”入口；从项目/Plan 也可筛选相关授权。

| 列表信息 | 人类能确认什么 |
| --- | --- |
| 授权名称、授权人和代理 Worker | 谁代表谁处理事项。 |
| 项目/Plan/步骤等适用范围 | 哪些对象包含在授权内。 |
| 允许动作与限制摘要 | 能追加几轮、能使用哪些模型、必须满足什么条件。 |
| 授权状态与代理启停 | 草稿、启用、停用、过期、撤销或额度耗尽；代理是否在线启用。 |
| 当前可用性及原因 | 例如“授权启用，但代理已离线”或“累计额度已耗尽”。 |
| 已用与剩余额度、有效期 | 这份授权还能做多少、能使用到何时。 |

详情页同时显示原始自然语言、结构化规则及其可读解释，并提供变更历史、决策依据和额度流水。可执行编辑、停用、撤销和另存为模板；这些维护操作由有权的人类发起。界面展示是快照，实际提交仍以服务端当前状态为准。

### 7. 已生成授权如何作为模板复用

建议提供以下流程：

```text
已有授权 -> 另存为模板 -> 选择新的项目/Plan/代理
         -> 填写目标参数 -> 查看规则及差异 -> 确认并启用新的授权
```

| 内容 | 模板和复用时的处理方式 |
| --- | --- |
| 原始表达、允许动作、条件、限额 | 保留为可复用规则；可在新草稿继续用自然语言或字段编辑。 |
| 项目/Plan/任务/代理绑定 | 由用户选择作为明确常量保留或设为待填参数；应用前必须确认目标。缺失参数不能变成全局授权。 |
| 生效/过期时间 | 提示按新场景确认；不能静默延长旧授权或复用已过期的时间设置。 |
| 凭证、租约、决策日志、额度使用记录 | 不进入模板；它们不是可复制的授权规则。 |
| 新授权身份 | 生成独立授权记录，保留来源模板版本及确认记录。 |
| 模板后续修改 | 不自动影响已经启用的授权；需要明确应用修改，并重新确认规则版本。 |
| 模板删除 | 不自动撤销已经发出的授权；实际授权仍在授权中心可查和撤销。 |

例如，将“某编码步骤耗尽后可追加指定轮数并升级到允许模型”的授权另存为“编码任务受限续试”模板，之后为项目 B 的指定步骤绑定另一个代理 Worker，并填写 B 的轮数、模型及累计限制，即可生成新的授权草稿。新授权启用前展示具体影响和与来源规则的差异。

同一任务/Plan 的限额不能靠复制模板、新建授权或换代理自动清零。人类决定追加额度时，要明确记录增加量、影响对象与原因。规则引用了目标环境不存在的模型配置、动作或证据时，应提示不兼容并保持草稿，不能自动替换成更宽的权限。

本轮“复用”按本系统内不同项目、计划或代理理解。跨系统导入导出及模板分享权限是尚未确定的扩展范围。
