## 使用者、问题、目标与非目标

使用者是需要暂时离线、但仍需控制工作流决策权限的人类管理者。目标是在明确授权内处理真实人工卡点，并让人类随时查看、修改、撤销及复用授权，范围外继续由人类决定。

本 Issue 的目标范围包括：自然语言与结构化规则结合的授权编辑、代理人工启停、服务端权限执行与审计、授权查看、常见事项目录，以及本系统内跨项目/计划/代理的授权模板复用。第一个具体业务场景是“多轮未解决后，按用户可编辑授权追加轮次并提升模型能力”。下文区分用户已确认目标和整理者提出的具体规则。

非目标：本次不实现功能，不批准 Issue，不创建 FD/Task/OpenSpec change，不启用运行时代理授权；不自动接管所有确认事项，不假定用户离线即自动启用，不默认纳入目录中全部动作，也不默认支持跨系统模板导入导出。业务数值由使用者配置，不要求现在固定为统一产品默认值。

## 1. 用户已明确的目标与规则

用户希望在自己不在线时，让一个决策 AI Worker 代理处理流程中原本需要人确认的事项。

1. Worker 只能在用户授权的范围内决定事项。
2. 不在授权范围内的事项仍由人类决定，Worker 不得擅自超越权限。
3. 用户可以主动让这个 Worker 上线或离线。
4. 用户提供的具体示例：经过三轮仍未解决时，可授权追加三轮，并提升 Model 能力。
5. 授权由用户自行编辑，触发条件、轮数、允许的模型等不能作为固定业务规则写死。
6. 需要整理常见的人工确认/授权事项，便于用户逐项编辑。
7. 用户认可自然语言编辑、系统整理为结构化规则并展示供其修改确认的方式；最终按结构化规则校验执行，同时保留原始表达。
8. 人类需要查看当前已授予代理 Worker 的授权。
9. 已生成授权应可作为模板，供其他适用场景复用。模板的复制、绑定及启用语义是下文的设计建议。

示例用于说明产品能力，不构成当前环境的实际代办授权。上线、授权范围与具体决策是不同概念：上线本身不代表获准决定所有事项，这是由用户明确边界推导的需求解释。

## 3. 建议的业务边界（待确认）

### 3.1 明确授权

- 人类创建、修改、撤销授权；代理只能使用已有授权，不能自行扩权、续期或创建新的授权。
- 授权是用户可编辑、可保存和可撤销的政策配置。新增或修改业务限额、触发条件及模型选择应通过配置完成，不要求改代码或重新部署。
- 自然语言输入转换为结构化授权草稿，同时展示原始表达、规则解释和未明确字段；用户可继续用自然语言补充，也可直接编辑字段。启用时确认的是明确的规则版本，后续执行不能临时重新解释原文来扩大授权。
- 常见人工确认事项形成可编辑模板；复制或编辑模板本身不等于启用授权。用户选择启用并明确作用范围、动作和约束后才能作为执行依据。
- 业务数值如“三轮触发、追加三轮、最多追加几次、模型/effort 白名单、使用期限和累计上限”均由授权配置决定；三轮示例不是所有授权的固定规则。
- 授权应能明确表达：授权人、代理身份、适用项目/计划/事项、允许动作、必要条件、禁止条件、有效期及必要的次数/额度限制。
- 规则未覆盖、语义含糊、证据不足或规则冲突，均进入待人工处理；不能因等待时间过长自动视为获准。
- 动作分别授权。例如“重试失败任务”不自动包含“跳过步骤”“接受结果”“发布”“修改权限”。
- Worker 的角色/能力匹配用于领取工作；实际操作权限另由 Control Plane 校验。
- 指令、产物、评审意见中的文字不能修改授权。若这些内容要求越权，代理应报告该事实并等待人工决定。

### 3.2 决策与执行

- AI 读取事项和证据，形成候选决定、依据及引用；Control Plane 在产生副作用前校验代理身份、当前授权、当前启用状态、条件和事项版本。
- 动作必须绑定明确的事项、版本/结果及授权版本；内容或状态改变后，旧候选决定不能自动套用。
- 人类修改授权后，尚未生效的候选决定必须按新版本重新校验；不能继续使用旧版授权的更宽限额。
- 重复投递、网络重试和人类同时处理不得产生重复或互相覆盖的决定。
- 代理决策保留真实身份以及所代表的授权人，不能把代理操作记录成“用户亲自确认”。
- 超范围和无法判断均保留为人工待办，附原因和现有证据；不直接转换成业务上的拒绝决定。
- 是否允许审批由同一 Worker 或同一模型产生的结果，需要明确独立性政策，不能默认为允许。

### 3.3 上下线与撤权

- 人类控制的代理启用状态与 Worker 进程在线状态分别展示。
- 建议默认关闭；进程重启、重新注册、心跳恢复均不能自行打开代理启用开关。
- 建议用户下线代理或撤销授权后，阻止尚未提交生效的决定，包括已领取、已计算完成但尚未提交的候选决定。
- 已经生效的决定保留审计，不因下线被静默撤回；补偿动作需独立授权。
- 下线与提交竞争时的生效边界需在工程设计中确定并提供可证明的状态检查，不能只靠 Worker 停止轮询。
- 当前只按“人类明确启用时允许代办”理解；用户离线的自动检测、自动启用及自动接管尚未确定。

### 3.4 记录与可见性

每次候选决定、被拒绝的越权尝试、人工升级和最终执行，建议记录：事项及版本、授权人、代理身份、授权版本、证据引用、候选决定及理由、规则校验结果、最终状态与时间。

人类应能查看代理当前是否启用、授权范围、已处理事项、等待人工事项及被拒绝的原因，并随时接管。

### 3.5 授权查看与模板复用（建议交互）

- 控制台提供授权中心，按授权人、代理 Worker、项目/Plan、动作与状态筛选；Worker 详情可查看该代理获授的授权。界面同时展示代理启停与授权启停/失效状态，能回答“这份授权现在是否允许该代理执行”。
- 授权详情包括原始自然语言、当前结构化规则及可读解释、适用对象、版本、有效期、已用/剩余额度、变更记录和关联决策；提供编辑、停用、撤销和另存为模板入口。
- 另存为模板保留可复用的条件、允许动作、限制和原始表达；项目/Plan/Worker 等绑定与时间参数需要明确保留或参数化，不能把缺少目标的规则默认为全局授权。
- 在其他项目、Plan 或代理使用模板时，先形成新的授权草稿，填写参数并展示与原规则的差异；确认并启用后才生效。模板本身不是代理可以使用的授权。
- 模板与实际授权分别有版本；生成时保存来源模板版本，实际授权固定使用已确认的规则快照。修改模板不自动变更已启用授权，已启用授权的修改需要人类明确确认。
- 模板不包含历史决策、消耗计数、运行中租约或身份凭证。对同一任务/Plan 重新复制授权不能自动重置仍适用的累计限额；增加额度需明确授予并审计。
- 删除模板不自动改变已发出的授权；用户从授权中心查看和撤销实际授权。跨不同系统的导入导出尚未确定，不因“可复用”而默认支持。

## 4. 用户示例与可编辑事项目录

首个明确示例是“轮次耗尽后追加执行轮次并提升模型能力”。轮次、模型配置及累计限制均可编辑，Worker 判断是否适用，Control Plane 校验并执行。执行反馈、已有产出与独立评审历史应保留；不能通过追加轮次降低原验收要求。

当前按“同一步执行一次并经过独立评审算一轮”理解用户例子，这是对现有产品流程的解释，不是用户已确认的轮次定义。任务执行失败后的技术重试、重新评审已有产物和追加执行轮次是三个独立动作，应可分别授权。

## 5. 目标验收例（提议，未执行）

1. 人类给指定 Plan 的指定动作授权后，已启用代理可在条件满足时处理，并留下可追溯记录。
2. 相同动作发生在其他 Plan，或所需条件缺失时，服务拒绝执行，事项继续等待人工。
3. 授权过期、被撤销、代理已下线后，即使 Worker 仍运行且持有旧任务/结果，也无法提交决定。
4. Worker 重新注册后不能恢复被人类关闭的代理启用状态。
5. 人类先处理或事项版本已变化时，旧代理提交得到明确冲突，不能覆盖人工结果。
6. 重复提交同一决定不重复执行；同一事项的冲突决定不能同时生效。
7. 无法判断授权是否适用时，生成带理由的人工待办，不能默认通过或超时通过。
8. 授权维护、人工决定与代理决定在记录上可以区分；所有处理都能追溯到有效授权。
9. 修改追加轮数、模型配置范围或累计上限后，后续决定按新配置校验；无需修改源码。已有授权额度按已使用量累计，不因重启、重复消息或编辑而自动重置。
10. 用户示例允许的追加执行和模型升级必须同时满足各自限制；任一条件不满足时，不能部分放宽权限或静默扩大模型范围。
11. 常见事项可逐项编辑和启停；新建、复制或预览模板不会自动发起动作或产生实际授权。
12. 人类可从代理 Worker 或授权中心查看全部已授授权，辨别代理离线、授权停用/过期/撤销/耗尽及当前可用状态，并查看每项决定消耗的额度。
13. 同一授权规则用于其他项目/Plan/代理时，经目标参数确认生成独立授权；原授权保持其记录，复制不会带入凭证、执行记录或重置同一对象的既有累计限制。
14. 修改模板不自动扩展已有授权。详情可追溯到模板来源版本、人工确认版本，以及实际决策引用的规则版本。
15. 自然语言中的模糊字段先提示补齐；未解析或未确认的部分不能成为实际决定的权限来源。

## 6. 范围、规模与未决问题

这是一个涉及授权、身份、计划写入与并发的跨模块需求，规模中到大、难度高，业务与兼容不确定性仍高。保留一个 Issue 的原因是：围绕首个真实场景，授权编辑、强制校验、启停、可见性和安全复用共同构成“人类可控的代理决策”这一验收结果；不能先发布只有提示词约束、没有服务端边界的代理。

原始成果映射：追加轮次与模型升级为首个具体场景；授权编辑/启停/校验/审计为共同安全边界；授权中心和 Worker 详情为权限可见性；另存模板和目标重新绑定为授权复用；17 项常见事项只作为可编辑目录，不承诺全部接入执行。更多动作执行支持、跨系统模板分享/导入导出明确留在未定范围，不重复计入首期交付。

本次不创建子 Issue。若后续确认要分别交付额外动作或独立的模板分发能力，应先准备子 Issue 范围、依赖和验收，再经明确授权创建并链接；父 Issue 的建档或批准不等于子 Issue 获批。表结构、API、凭证方案、迁移和 Work Items 留到 FD 设计，不在需求阶段预定。

### 2. 每份授权共用的编辑内容

| 编辑项 | 用户可以填写的内容 | 执行时的含义 |
| --- | --- | --- |
| 名称与说明 | 这份授权用来解决什么问题 | 便于识别和审计。 |
| 是否启用 | 启用、停用 | 未启用的授权不能用于决定。 |
| 授权对象 | 哪个决策 Worker 可以代表谁 | 与普通 Worker 能力、控制台角色分开。 |
| 适用范围 | 指定项目/工作区、Plan、步骤、任务或明确选择的更大范围 | 不能因同名任务或相似内容扩大范围。 |
| 触发条件 | 状态、已用轮数、失败类别、评审结论及所需证据 | 条件满足才进入代理决策；满足条件也不等于必须同意。 |
| 允许动作 | 本目录中系统实际支持的动作，可组合 | 未列入授权的动作不能顺带执行。 |
| 动作参数 | 追加轮数、目标步骤、允许模型与 effort 等 | 由你编辑，不写死业务数值。 |
| 累计限制 | 每任务/每计划/每时间段的次数、总轮数、升级次数或可观测资源预算 | 每次提交时检查已使用量，防止分批、重试或重启绕过上限。 |
| 有效期 | 生效时间、结束时间或明确撤销条件 | 失效后等待人类重新授权。 |
| 禁止条件 | 某些任务类型、路径、风险事项、错误类别等 | 命中时转人工；不能用另一份模糊授权绕过禁止条件。 |
| 人工处理条件 | 什么情况下必须交回人类 | 超范围、条件冲突、证据不足或无法校验时保留待办。 |
| 变更记录 | 谁在何时修改了哪些内容 | 执行需记录当时有效的授权版本。 |

必填字段缺失或限制含糊时，应提示补齐或停留在草稿；空值不能默认为无限授权。额度规则需要明确累计口径；预算依赖的消耗数据不可获得时，不能假装已经满足预算条件。冲突授权的处理规则需要确定，无法确定时转人工。

### 5. 建议的编辑与运行体验（待设计）

1. 用户用自然语言描述授权，或从目录选择模板，系统整理成包含作用范围、条件、动作和限制的结构化草稿；原文和规则同时可查看和修改。
2. 保存草稿时显示缺失字段、规则解释和授权影响；保存/复制草稿不启动授权。用户启用时确认的是明确规则版本，不能在执行时凭原文产生额外权限。
3. 用户启用具体授权，并控制决策代理整体上线或离线。
4. 代理发现待确认事项后说明判断，Control Plane 按最新授权和事项状态校验；校验通过才执行。
5. 目录与授权页展示已用轮数/次数、当前授权版本、已处理记录和待人工事项。
6. 用户随时停用、修改或撤销；修改不自动重置已消耗额度，旧候选决定需要重新校验。

如何新增一份明确独立的额度、自然语言与字段编辑的具体交互，以及多份授权冲突的提示，是后续设计问题。不要求用户现在为所有事项确定固定业务数值。

### 6. 人类如何查看已经授予的授权

建议设置授权中心，并在决策 Worker 详情提供“获授权限”入口；从项目/Plan 也可筛选相关授权。

| 列表信息 | 人类能确认什么 |
| --- | --- |
| 授权名称、授权人和代理 Worker | 谁代表谁处理事项。 |
| 项目/Plan/步骤等适用范围 | 哪些对象包含在授权内。 |
| 允许动作与限制摘要 | 能追加几轮、能使用哪些模型、必须满足什么条件。 |
| 授权状态与代理启停 | 草稿、启用、停用、过期、撤销或额度耗尽；代理是否在线启用。 |
| 当前可用性及原因 | 例如“授权启用，但代理已离线”或“累计额度已耗尽”。 |
| 已用与剩余额度、有效期 | 这份授权还能做多少、能使用到何时。 |
| 来源模板及版本 | 哪份模板生成，当前确认的规则版本是什么。 |
| 最近决策 | 最近处理了什么、用了哪份授权、为何处理。 |

详情页同时显示原始自然语言、结构化规则及其可读解释，并提供变更历史、决策依据和额度流水。可执行编辑、停用、撤销和另存为模板；这些维护操作由有权的人类发起。界面展示是快照，实际提交仍以服务端当前状态为准。

### 7. 已生成授权如何作为模板复用

建议提供以下流程：

```text
已有授权 -> 另存为模板 -> 选择新的项目/Plan/代理
         -> 填写目标参数 -> 查看规则及差异 -> 确认并启用新的授权
```

| 内容 | 模板和复用时的处理方式 |
| --- | --- |
| 原始表达、允许动作、条件、限额 | 保留为可复用规则；可在新草稿继续用自然语言或字段编辑。 |
| 项目/Plan/任务/代理绑定 | 由用户选择作为明确常量保留或设为待填参数；应用前必须确认目标。缺失参数不能变成全局授权。 |
| 生效/过期时间 | 提示按新场景确认；不能静默延长旧授权或复用已过期的时间设置。 |
| 凭证、租约、决策日志、额度使用记录 | 不进入模板；它们不是可复制的授权规则。 |
| 新授权身份 | 生成独立授权记录，保留来源模板版本及确认记录。 |
| 模板后续修改 | 不自动影响已经启用的授权；需要明确应用修改，并重新确认规则版本。 |
| 模板删除 | 不自动撤销已经发出的授权；实际授权仍在授权中心可查和撤销。 |

例如，将“某编码步骤耗尽后可追加指定轮数并升级到允许模型”的授权另存为“编码任务受限续试”模板，之后为项目 B 的指定步骤绑定另一个代理 Worker，并填写 B 的轮数、模型及累计限制，即可生成新的授权草稿。新授权启用前展示具体影响和与来源规则的差异。

同一任务/Plan 的限额不能靠复制模板、新建授权或换代理自动清零。人类决定追加额度时，要明确记录增加量、影响对象与原因。规则引用了目标环境不存在的模型配置、动作或证据时，应提示不兼容并保持草稿，不能自动替换成更宽的权限。

本轮“复用”按本系统内不同项目、计划或代理理解。跨系统导入导出及模板分享权限是尚未确定的扩展范围。
