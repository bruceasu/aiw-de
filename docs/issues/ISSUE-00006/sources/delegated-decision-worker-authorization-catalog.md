# 决策 Worker：常见人工确认与授权事项目录（草案）

## 1. 用途与状态

本目录用于让用户选择、编辑和管理可委托给决策 Worker 的事项，属于[需求草案](delegated-decision-worker.md)的配套材料。这里的模板、字段和示例尚未实现为可加载的应用配置，也没有启用任何实际授权。

用户已明确：授权可自行编辑，代理只能在授权范围内决定；范围外仍需人类决定；用户可主动上线或下线代理。用户已提供“原三轮未解决，再追加三轮并提高 Model 能力”的示例。除该示例外，下列事项是待选择的常见候选，不代表用户已同意全部纳入首期。

用户已认可自然语言编辑与结构化规则相结合，并要求能够查看已有授权、将授权作为模板复用。以下授权中心与模板生命周期是实现这些目标的交互建议，尚未实现。

## 2. 每份授权共用的编辑内容

| 编辑项 | 用户可以填写的内容 | 执行时的含义 |
| --- | --- | --- |
| 名称与说明 | 这份授权用来解决什么问题 | 便于识别和审计。 |
| 是否启用 | 启用、停用 | 未启用的授权不能用于决定。 |
| 授权对象 | 哪个决策 Worker 可以代表谁 | 与普通 Worker 能力、控制台角色分开。 |
| 适用范围 | 指定项目/工作区、Plan、步骤、任务或明确选择的更大范围 | 不能因同名任务或相似内容扩大范围。 |
| 触发条件 | 状态、已用轮数、失败类别、评审结论及所需证据 | 条件满足才进入代理决策；满足条件也不等于必须同意。 |
| 允许动作 | 本目录中系统实际支持的动作，可组合 | 未列入授权的动作不能顺带执行。 |
| 动作参数 | 追加轮数、目标步骤、允许模型与 effort 等 | 由你编辑，不写死业务数值。 |
| 累计限制 | 每任务/每计划/每时间段的次数、总轮数、升级次数或可观测资源预算 | 每次提交时检查已使用量，防止分批、重试或重启绕过上限。 |
| 有效期 | 生效时间、结束时间或明确撤销条件 | 失效后等待人类重新授权。 |
| 禁止条件 | 某些任务类型、路径、风险事项、错误类别等 | 命中时转人工；不能用另一份模糊授权绕过禁止条件。 |
| 人工处理条件 | 什么情况下必须交回人类 | 超范围、条件冲突、证据不足或无法校验时保留待办。 |
| 变更记录 | 谁在何时修改了哪些内容 | 执行需记录当时有效的授权版本。 |

必填字段缺失或限制含糊时，应提示补齐或停留在草稿；空值不能默认为无限授权。额度规则需要明确累计口径；预算依赖的消耗数据不可获得时，不能假装已经满足预算条件。冲突授权的处理规则需要确定，无法确定时转人工。

## 3. 常见事项清单

“已有动作”只表示当前源码中存在相应业务入口，**所有事项的代理授权与强制校验机制都需要本需求新增设计**。已有动作原本要求的业务条件继续适用，代理授权不能自行豁免。

| 编号 | 人工确认事项 | 可针对性编辑的授权条件 | 当前动作能力 |
| --- | --- | --- | --- |
| A01 | 轮次耗尽后继续执行 | 何时算耗尽、每批追加轮数、可追加次数、累计总轮数、适用步骤/任务、有效期 | 新增能力。现有步骤固定最多三轮；恢复评审不等于继续执行。 |
| A02 | 提升模型能力 | 允许 profile/model/effort、升级路径或等级上限、适用执行/评审角色、作用范围、消耗限制 | 有 AI profile 目录和任务类型校验；限定到授权范围的升级能力需新增。 |
| A03 | 失败任务重试 | 可重试失败类型、前置修复证据、次数和间隔、是否允许可能重复外部副作用的任务 | 已有计划中当前失败任务的人工重试入口。 |
| A04 | 补正后恢复评审 | 哪些已补正证据、原产物版本、可恢复次数、评审 Worker/配置限制 | 已有 resume-review，只重新评审现有产物。 |
| A05 | 确认并启动计划 | 计划/模板、允许角色和步骤、工作区、资源限制、当前版本 | 已有确认草稿动作；会创建执行任务。 |
| A06 | 跳转流程步骤 | 哪些步骤可跳过、可到达的目标、所需前置证据、是否允许丢弃中间工作 | 已有 Jump；不得推导为验收通过。 |
| A07 | 提前停止流程 | 适用计划、停止原因、已获得的产出、安全停止条件 | 已有 Stop；需遵守租约停止处理。 |
| A08 | 收回剩余委派 | 适用计划状态、收回范围及原因 | 已有 Withdraw；与其他结束动作分开授权。 |
| A09 | 人工标记计划完成 | 可接受的现有产出、必须完成/评审的步骤、人工结束原因 | 已有 Complete；不能把决定伪装成独立评审 PASS。 |
| A10 | 取消计划 | 适用条件、当前活动任务处理方式、可接受的未完成工作 | 已有 Cancel；与 Stop/Complete 分开授权。 |
| A11 | 对工程成果作批准或拒绝决定 | 精确来源任务和 revision、必要的 Gate/证据、独立性要求、允许决定类型 | 现有 Approval API 面向 PASSED Engineering Gate；不能假设其覆盖所有 Flexible Plan 场景。 |
| A12 | 创建输出文件发布计划 | 允许文件种类、目标路径、指定评审证据、作用工作区 | 已有 publication-plans 入口；创建计划与真正发布/执行分别确认授权范围。 |
| A13 | 调整 Fleet 并发 | 可调区间、允许变动幅度、观察到的负载、适用时间段及操作次数 | 已有全局 Fleet scheduling 入口；全局影响必须在授权中明示。 |
| A14 | 让普通执行 Worker 停止接新任务 | 指定 Worker、允许原因、对当前任务的要求 | 已有 Drain。不能据此启用决策代理或修改代理授权。 |
| A15 | 将普通执行 Worker 标记离线 | 指定 Worker、必要证据、当前租约状态 | 已有 Offline。业务影响与安全停止条件继续校验。 |
| A16 | 归档已结束计划 | 哪些计划、满足的结束条件、是否保留当前列表显示 | 已有 Archive；归档不等于删除。 |
| A17 | 安排或撤销延迟删除 | 精确对象、保留策略、可删除关联数据、所需管理权限 | 已有 schedule-delete/undo-delete；可选保留为人工专属项。 |

可按实际需要复制、修改或停用模板；若自定义模板要求系统尚不支持的动作，应显示“待支持”，不能转化为任意 shell/API 调用。模板的展示顺序和编号不代表执行优先级或授权强度。

## 4. 用户场景示例：追加轮次并提升模型能力

这是你提出的例子的一份可编辑草表，数值用于说明该场景，不是产品默认值或当前实际授权。

| 配置项 | 此例中的内容 |
| --- | --- |
| 名称 | 三轮未解决后继续尝试并提升模型配置 |
| 是否启用 | 待你启用 |
| 适用项目/计划/步骤 | 待你填写 |
| 触发条件 | 已完成三轮仍未解决；具体对应哪种状态和评审结论需写清 |
| 允许动作 | A01 追加执行轮次 + A02 提升模型能力 |
| 每次追加轮数 | 3，可编辑 |
| 模型能力升级方式 | 待你选择：更强模型、提高推理强度，或两者均允许 |
| 允许模型配置及最高配置 | 待你指定已批准配置；不能仅凭模型名称或价格推断“更聪明” |
| 配置生效对象 | 待你选择执行 Worker、评审 Worker 或两者；不能影响未授权的其他任务 |
| 最大追加次数/累计总轮数 | 待你填写；不是默认只追加一次，也不是默认无限追加 |
| 使用期限/消耗限制 | 待你填写适用限制及可校验的数据口径 |
| 无可用升级配置、额度不足或证据不足 | 留给人工；其他回退方式需你明确授权 |

代理应结合此前执行和评审记录判断继续尝试是否有依据，并说明理由。追加轮次和模型升级都在授权内时才能执行这个组合决定；无法满足其中一项时，不能静默放宽另一项或扩大作用范围。

当前按“同一步执行一次 + 独立评审”理解一轮，属于待核实的产品解释。技术执行失败后的重试、对现有产物重新评审与追加完整执行轮次应在界面中区分，以免误用限额。

## 5. 建议的编辑与运行体验（待设计）

1. 用户用自然语言描述授权，或从目录选择模板，系统整理成包含作用范围、条件、动作和限制的结构化草稿；原文和规则同时可查看和修改。
2. 保存草稿时显示缺失字段、规则解释和授权影响；保存/复制草稿不启动授权。用户启用时确认的是明确规则版本，不能在执行时凭原文产生额外权限。
3. 用户启用具体授权，并控制决策代理整体上线或离线。
4. 代理发现待确认事项后说明判断，Control Plane 按最新授权和事项状态校验；校验通过才执行。
5. 目录与授权页展示已用轮数/次数、当前授权版本、已处理记录和待人工事项。
6. 用户随时停用、修改或撤销；修改不自动重置已消耗额度，旧候选决定需要重新校验。

如何新增一份明确独立的额度、自然语言与字段编辑的具体交互，以及多份授权冲突的提示，是后续设计问题。不要求用户现在为所有事项确定固定业务数值。

## 6. 人类如何查看已经授予的授权

建议设置授权中心，并在决策 Worker 详情提供“获授权限”入口；从项目/Plan 也可筛选相关授权。

| 列表信息 | 人类能确认什么 |
| --- | --- |
| 授权名称、授权人和代理 Worker | 谁代表谁处理事项。 |
| 项目/Plan/步骤等适用范围 | 哪些对象包含在授权内。 |
| 允许动作与限制摘要 | 能追加几轮、能使用哪些模型、必须满足什么条件。 |
| 授权状态与代理启停 | 草稿、启用、停用、过期、撤销或额度耗尽；代理是否在线启用。 |
| 当前可用性及原因 | 例如“授权启用，但代理已离线”或“累计额度已耗尽”。 |
| 已用与剩余额度、有效期 | 这份授权还能做多少、能使用到何时。 |
| 来源模板及版本 | 哪份模板生成，当前确认的规则版本是什么。 |
| 最近决策 | 最近处理了什么、用了哪份授权、为何处理。 |

详情页同时显示原始自然语言、结构化规则及其可读解释，并提供变更历史、决策依据和额度流水。可执行编辑、停用、撤销和另存为模板；这些维护操作由有权的人类发起。界面展示是快照，实际提交仍以服务端当前状态为准。

## 7. 已生成授权如何作为模板复用

建议提供以下流程：

```text
已有授权 -> 另存为模板 -> 选择新的项目/Plan/代理
         -> 填写目标参数 -> 查看规则及差异 -> 确认并启用新的授权
```

| 内容 | 模板和复用时的处理方式 |
| --- | --- |
| 原始表达、允许动作、条件、限额 | 保留为可复用规则；可在新草稿继续用自然语言或字段编辑。 |
| 项目/Plan/任务/代理绑定 | 由用户选择作为明确常量保留或设为待填参数；应用前必须确认目标。缺失参数不能变成全局授权。 |
| 生效/过期时间 | 提示按新场景确认；不能静默延长旧授权或复用已过期的时间设置。 |
| 凭证、租约、决策日志、额度使用记录 | 不进入模板；它们不是可复制的授权规则。 |
| 新授权身份 | 生成独立授权记录，保留来源模板版本及确认记录。 |
| 模板后续修改 | 不自动影响已经启用的授权；需要明确应用修改，并重新确认规则版本。 |
| 模板删除 | 不自动撤销已经发出的授权；实际授权仍在授权中心可查和撤销。 |

例如，将“某编码步骤耗尽后可追加指定轮数并升级到允许模型”的授权另存为“编码任务受限续试”模板，之后为项目 B 的指定步骤绑定另一个代理 Worker，并填写 B 的轮数、模型及累计限制，即可生成新的授权草稿。新授权启用前展示具体影响和与来源规则的差异。

同一任务/Plan 的限额不能靠复制模板、新建授权或换代理自动清零。人类决定追加额度时，要明确记录增加量、影响对象与原因。规则引用了目标环境不存在的模型配置、动作或证据时，应提示不兼容并保持草稿，不能自动替换成更宽的权限。

本轮“复用”按本系统内不同项目、计划或代理理解。跨系统导入导出及模板分享权限是尚未确定的扩展范围。

## 8. 静态依据与验证范围

- `WorkflowPlanService`：步骤三轮上限、恢复评审、计划确认及人工控制。
- `WorkflowEditorController` / `WorkflowPlanController`：重试、恢复评审、确认、跳转、停止、完成、取消、归档和延迟删除入口。
- `AiProfileCatalog`：已有模型配置目录与 profile/version/runtime 校验。
- `ApprovalService`：针对已通过 Engineering Gate 的独立审批。
- `TaskOutputController`：输出文件发布计划入口。
- `WebConsoleActionController`：普通 Worker Drain/Offline 与 Fleet 并发调整。

本目录基于源码静态观察。未执行这些动作，未启用任何代理授权，也没有运行测试或服务。
