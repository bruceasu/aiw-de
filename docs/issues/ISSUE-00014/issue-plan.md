## 使用者、问题与目标

使用者包括管理 Skill 资源的管理员，以及准备配置、执行任务的平台和 Worker。

目标是让平台任务使用的 Skill 的维护和版本归属集中在平台；多个兼容 Worker 可以使用同一项资源的同一版本，本地副本作为受固定引用约束的派生内容。Worker 同时保留独立部署和指定自备 Skills 目录的能力。这样可以减少平台部署的重复维护，并使任务实际使用的 Skill 可追溯。

收益是需求推论；目前没有版本漂移频次、维护工时或资源占用的运行数据，不量化收益。

## 获取平台 Skill 文件集的工程选项（本轮建议）

- 方法：Engineering Options；局部状态：CONSTRAINED。平台统一管理方向已确认；以下是文件集分发的候选方案，涉及资源合同、Worker 协议和分发鉴权的变化，不是已实现行为或已批准的接口设计。
- 相比把所有文件正文重复塞入任务载荷，建议任务携带固定文件集引用，Worker 按需从平台拉取不可变 Skill 包，并在本地校验缓存。相比实时挂载一个可变共享目录，该方式支持跨机器独立部署并保持任务版本稳定。首期不要求增设独立制品服务或共享文件系统。

### 候选流程

1. 平台登记 Skill 版本时保存完整的声明文件集，保留 `SKILL.md` 和所需 `references/`、`agents/`、`assets/`、`scripts/` 等相对路径；资源清单列明文件路径、字节数与文件摘要，并固定整个文件集的摘要。收录脚本只分发数据，不自动注册或执行工具。
2. 任务准备时固定所需 Skill 的身份、版本和文件集摘要，并确认平台保有该版本；任务载荷提供这些固定引用。包格式、清单的规范编码与具体协议字段由 FD 定义。
3. Worker 的宿主适配器解析引用，先寻找经过校验的受管缓存，也可检查 `AIW_PROCESS_SKILLS_ROOT` 中与该清单完全匹配的内容。仅按目录名命中不足以复用；不得向本轮模型额外暴露清单外的同目录文件。
4. 无精确本地内容时，通过配置好的 Control Plane 地址、既有 Worker 身份及当前任务授权请求精确版本。建议分发入口按任务/Lease 与资源访问范围鉴权；不接受模型指定的任意下载地址，不要求 Skill 自身或模型调用网络工具取得自身内容。具体授权合同仍须由 FD 确定。
5. 下载进入临时位置；核对固定清单与各文件的摘要、大小及路径，拒绝目录逃逸、链接或部分文件冒充完整包。校验完成后原子发布缓存，向本次 Attempt 提供固定的只读资源视图；自备目录也通过校验后的快照或等价机制防止使用期间被改写。缓存的物理实现留给 FD。
6. Runtime 经受控读取机制加载本轮需要的文件，保留相对路径引用。分发完整文件集不意味着把全部文件正文一次性注入模型上下文。Python、TypeScript、Go 遵守同一文件集与引用合同，分别适配自己的 Runtime。

### 版本、失败与权限边界

- 缓存身份包含来源访问范围与文件集摘要，避免同名 Skill 或不同访问范围相互覆盖；平台受管缓存与自备目录的管理归属保持分离，不自动改写用户目录。
- 同名本地内容与任务摘要不符时不采用该内容；可以从平台获取正确版本。无精确本地内容且无法取得平台版本时明确失败，不追随最新版本或回退到未固定内容。
- 本地命中不替代任务授权。获取资源受既有任务期限、取消和租约边界约束，不额外引入无限重试或擅自扩大网络权限。
- 平台保留仍被任务及其续行引用的版本；缓存可在无活动引用时回收，不能删除正在使用的文件集。具体保留与回收策略留给 FD。
- 缓存仅承担受管 Skill 资源分发，不成为任务正文、私有知识或完整提示词的留存入口。
- 现有 `digest` 校验拼接文本；新文件集或包的摘要必须显式定义并通过合同变更引入，不能把既有文本摘要静默解释成压缩包或文件树摘要。

### 待 FD 决定的取舍

清单及包格式、资源合同版本、鉴权与分发入口、缓存布局、只读视图、版本保留及大小限制均待正式设计。平台固定引用的权威性和三语言共同接入是已确认需求；上述技术机制仍为建议。若完整文件集的执行能力或访问范围超出现有授权，返回 Issue 确认，不能借文件分发扩大权限。

## 建议范围与规则（待正式 Issue 批准）

1. 平台统一管理其任务使用的 Skill 身份、版本、内容摘要及来源；同一身份与版本不得静默替换为不同内容。
2. Worker 执行平台任务时，按任务固定的资源引用使用 Skill。缓存和部署时生成的副本是派生产物，不作为平台任务的另一份独立权威来源。
3. 更新资源形成新版本；已经固定输入的任务及其继续执行保留原有版本语义，不自动追随最新版本。沿用既有固定配置合同。
4. Skill 不存在、版本或摘要不匹配、访问范围不满足时，明确暴露失败原因，不静默改用其他版本。
5. 共享管理不合并 owner、repository 或知识的访问边界；引用 Skill 不增加工具、网络、文件或其他操作权限。
6. 声明式 Skill 和任务事实继续分离。首期不因共享资源而引入可自行注册工具或执行任意脚本的能力。
7. 复用并收敛已有目录、资产登记及冻结配置能力；与 ISSUE-00011 / FD-027 的已完成范围保持可追溯关联，不重复声明其交付。
8. 首期同时覆盖 Python、TypeScript、Go 三种维护中的过程 Worker，统一资源归属、按任务引用及版本校验规则。不同语言可以采用适合各自 Runtime 的适配方式，不以已有 Python 路径代替其他两种实现的交付。
9. 接入以实际支持能力为依据；未接入的 Worker 不得领取要求平台资源合同的任务。三语言共同接入是本 Issue 的验收范围。
10. AIW 管理的部署统一切换到平台资源管理；独立部署 Worker 保留显式指定 Skills 目录的能力，沿用 `AIW_PROCESS_SKILLS_ROOT`，不要求依赖本仓库的固定目录布局。
11. 目录选择和平台任务的内容权威分开处理：自备目录可为独立部署提供既有 Profile 允许的 Skills，也可为平台任务提供与固定引用一致的本地内容。平台任务仍校验身份、版本和摘要；同名文件不覆盖平台内容，平台缺失时不自动改用未固定的本地 Skill。
12. 平台托管与独立部署的资源来源须可区分；使用自备目录不自动把其中内容导入平台。具体来源标识及内容取得机制由 FD 设计，不在本 Issue 中预设新增模式参数或协议。

| 场景 | 可观察结果 |
| --- | --- |
| 两个兼容 Worker 执行引用相同 Skill 身份、版本和摘要的任务 | 消费同一受管内容，无需分别维护角色 Skill；结果能追溯固定引用。 |
| Python、TypeScript、Go 分别执行各自支持的任务，引用相同的受管 Skill 版本 | 三种实现均按任务引用消费并校验同一身份、版本及摘要；资源更新、缺失和摘要失配遵守共同规则。仅 Python 接入不构成本 Issue 完成。 |
| 平台登记该 Skill 的 v2，已有任务固定 v1 | 原任务及其续行保持 v1；明确选择 v2 的新任务使用 v2。 |
| Worker 本地没有该版本缓存 | 从受控任务配置或资源分发机制取得精确内容；具体机制留给 FD，不要求预装完整 Skill 库。 |
| 缓存内容损坏，且无法取得匹配版本 | 任务不以错误内容执行，提供明确原因；不得回退到任意同名 Skill。 |
| Skill 或其知识引用超出调用者访问范围 | 共享管理仍拒绝越权访问；获得公共 Skill 不扩大私有知识或工具权限。 |
| Worker 尚不支持受管资源消费合同 | 不被视为能执行相关任务；用户能识别能力缺口。 |
| 三种 Worker 分别单独部署，并通过 `AIW_PROCESS_SKILLS_ROOT` 指定自备目录 | 保留按现有 Profile 从指定目录加载 Skill 的能力；不要求在各语言包中人工维护相同的权威副本。 |
| Worker 指定目录中有与平台任务同名但内容不同的 Skill | 平台固定版本与摘要继续生效，本地内容不得覆盖；不能取得精确内容时明确失败。 |
| 自备目录中存在与平台任务固定引用完全一致的内容 | 可作为本地内容来源；是否采用该来源由 FD 的消费机制决定，采用时仍完成同样的校验。 |
| Skill 引用了包内 `references/` 或 `assets/` 的文件 | 获取后保留声明的相对路径与原始文件内容，Runtime 可通过受控读取取得；清单外文件不被当作已授权输入。 |
| 下载中断或缓存文件集被修改 | 部分包不成为可用缓存；执行前取得与固定清单一致的完整内容，无法取得时明确失败。 |
