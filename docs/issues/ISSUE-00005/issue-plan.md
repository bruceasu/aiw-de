## 问题与目标

New Plan 页面已有 Goal and recommendation 功能，但启用依赖启动配置和内部 AI policy，用户难以理解和操作。用户希望能在系统中随时启用或关闭，并希望先考虑 Control Plane 是否应该直接调用模型，还是统一委托 Worker。

本 Issue 的目标是形成可供用户审阅的配置体验与职责边界决策。当前不把建议当作已批准的架构。

## 备选方案与建议（未批准）

### 方案 A：所有模型推理委托 Worker（建议）

Control Plane 管理系统配置、权限、任务派发、结果校验、流程推进和审计；Worker 管理模型调用、运行环境及执行证据。推荐步骤也作为短分析任务执行。

优点：复用现有任务生命周期、费用及调用管理路径，职责统一；便于切换模型和 Worker。代价：需要可用 Worker，并承担派发与等待延迟。

### 方案 B：Control Plane 直接调用模型

适用于推荐等辅助分析；业务执行仍由 Worker 承担。

优点：可能减少派发环节。代价：Control Plane 需要承担凭据、模型适配、费用、超时、取消及调用审计，并处理与 Worker 路径的一致性。

### 方案 C：按用途区分两种调用路径

可能兼顾交互响应和任务隔离，但增加路由、治理及运维复杂度；需要先明确值得引入第二条路径的场景和证据。

建议优先采用 A，以专用常驻分析 Worker 改善短任务响应。此建议未获用户决策，不作为设计约束或实施授权。

## 拟议规则与验收示例（待确认）

1. 管理员能在系统设置中开关 AI 推荐，保存后无需重启，刷新后仍保持。
2. 页面区分“管理员关闭”“缺少调用配置”“没有可用分析 Worker”等状态；最终原因随调用方案确定。
3. 普通用户不能修改系统级 AI 功能配置；设置变更记录操作者、时间及变更内容。
4. 推荐只生成候选步骤；不自动确认 Plan 或执行候选业务工作。
5. 建议关闭功能只阻止新推荐，已有运行任务继续，排队任务提供单独撤回入口；最终规则待确认。
6. 系统级开关在服务端持久化，与浏览器个性化偏好分离；存储位置和旧配置优先级留待设计。
7. 任一选定调用方案都需关联请求、调用结果与责任主体，并保留权限和审计边界。
