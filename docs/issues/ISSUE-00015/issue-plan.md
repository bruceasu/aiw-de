## 使用者、问题与目标

秘书使用者需要把一次会话及其关联执行过程保存到本机，以便之后查看、分析和留存。当前页面可查看部分已保存的模型交互，但它不是每次模型请求的完整原文，部分历史和内容可能被截断。

目标是由用户主动选择一个会话，将系统实际保存的该会话及关联执行交互导出为本地文件。导出不得重放任务、调用模型或改变原记录。

## 已确认事实与规则

- 用户此前确认希望查看实际发给模型和模型返回的内容，隐藏凭据，不要求展示模型内部推理。见 `docs/FUNCTION-INVENTORY.md` 第 37 项。
- 现有个人秘书界面允许按执行查看模型交互；界面明确说明记录可能不是完整请求原文、工具结果可能含占位信息且可能含私人资料。见 `personal-secretary/ui/app.js` 与 `personal-secretary/secretary_runs.py`。
- 本次用户确认：导出所选会话及关联执行记录为一个本地 JSON；包括已有的模型请求／回复、工具调用／结果、顺序、用量和错误；只使用已保存的数据；隐藏凭据和内部推理；不新增采集或远程传输。

## 范围

- 在秘书会话界面提供用户主动操作的导出入口。
- 一次导出一个所选会话及其可关联的执行记录。
- JSON 按时间顺序保留已有消息、已保存的模型交互、工具调用及结果、用量和错误，并保留会话与执行之间的关联。
- 导出内容仅来自本机已经保存的记录。原始数据缺失、历史截断或工具结果仅有占位信息时，应明确标注，不补造或重放。
- 排除凭据、访问令牌、认证头和模型内部推理内容。导出文件由浏览器下载到用户指定位置，不向 Plane 或第三方上传。
- 导出前提醒文件可能包含私人会话内容。

## 非目标

- 不改变现有日志采集、保留期限或数据库结构。
- 不导出全部会话或其他 Owner 的内容。
- 不尝试恢复未保存的原始 HTTP 请求／响应，也不导出隐藏推理。
- 不生成 Markdown 或额外格式，不增加计划／执行重放、模型调用或网络传输。

## 验收示例

1. 用户从某会话发起导出，得到一个本地 JSON 文件；其中只包含该会话及其关联执行记录。
2. 文件中的消息、模型交互、工具调用／结果按时间排序，并保留它们的执行归属。
3. 记录缺失或截断时，文件明确标出对应情况；系统不声称导出包含未保存的完整原文。
4. 文件不包含模型连接凭据、认证令牌、认证头或模型内部推理。
5. 导出操作不修改会话，不启动模型或工具，不访问网络。
