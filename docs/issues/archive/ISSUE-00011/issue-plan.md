## 使用者、问题与目标

用户无需按每个职业另建常驻进程；平台按任务准备专业能力，兼容的通用 Worker 可先后执行不同专业配置，同时保留现有执行所有权与恢复机制。

## 范围与规则

1. Factory 为 Control Plane 正式模块，负责配置装配、校验和版本保存；智能判断可按需调用 Factory Agent 并复用 Runtime，不要求独立服务或长期会话。
2. 优先复用已有配置，再组合 Skills，必要时生成声明式 Skill；任务事实放上下文或知识材料，重复方法才考虑沉淀 Skill。
3. 采用 Option B：可生成说明、流程、检查清单、知识及输出约定，只能引用已有且获授权的 Tools。Skill 不能自行授权或夹带执行内容绕过授权。
4. Worker 的专业能力来自本次配置，广告真实 Runtime、工具适配器、资源、工作空间及网络条件。配置可由现有 Profile 演进，避免重复体系。
5. 计划节点可延后绑定 Skill，但进入可领取状态前须确定配置版本、执行要求和实际授权；获得 Lease 后才实例化 Agent，已知能力缺口不能留待领取后才发现。
6. 复用 Pull、Lease Ownership、心跳、结果、取消及恢复。进程内、子进程或容器属于隔离策略，不形成职业管理层。

## 已确认：知识归属与独立授权边界（2026-10-22）

- 知识归知识管理职能；配置按权限装配其知识引用与服务。其他职能可生产材料、使用知识，但不因此改变知识治理归属或私人数据边界。
- 业务监测与安全处置分别准备职责、能力与权限模板，分别核对授权，通常由两个 Worker 承担；同属相关分类或同一 Worker 承载过两类任务不合并权限。
- 需求评审配置面向需求，行为审计配置面向实际行为及证据，保留两类对象的区别。

验收目标：已支持职能能装配默认职责、候选权限、能力和知识；没有安全处置授权的监测 Worker 不能处置；未实现职能不冒充已支持。以上为需求目标，不承诺首期全部实现，本轮未运行验证。

- 用户自行删除旧 DB 并使用新库；本轮不删除文件或操作数据库。新运行产生的配置版本、任务、授权和消耗继续可追溯。
- 默认职责、权限模板、能力与知识的具体清单，以及实际工具与资源范围仍待细化；常驻、按需启动和空闲回收继续留待后续讨论。
