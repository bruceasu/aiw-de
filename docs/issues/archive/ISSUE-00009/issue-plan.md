## 4 AI 计划与流程表达

### WF 01 AI 生成初稿

用户应能只提交目标，由 AI 生成包含工作内容、依赖和验收条件的初始计划。手工编排继续保留，但用户不必从零填写步骤和能力。人工是否必须确认后才执行，由现有授权策略及其必要扩展决定。

### WF 02 按需展开与调整

计划可先描述主要工作，再为即将执行的部分展开细节。AI 应能根据新证据提出补充任务、调整后续路径、请求澄清或结束工作。已定义规则足够时直接推进，无需每步重新调用规划模型。

### WF 03 原生条件与跳转

流程应原生支持 task、if/else、goto、ask 和正常结束。goto 应允许前向跳转及向后回跳。分支和跳转应直接可读，不要求通过循环结构间接模拟。最终语法和序列化格式待定。

条件必须有明确依据：确定性工具结果可直接判断；需要专业判断时，由 Agent 提交符合约定的结论及证据。未知或无效结果不能默认按成功处理。

### WF 04 循环与重试

回跳产生新一轮业务任务并保留历史。Worker 崩溃、网络错误等执行故障使用既有 Attempt 和恢复机制，两者不能混为一类。循环和动态展开应受次数、时间、成本或任务规模约束；具体默认值待定。

### WF 05 依赖与并行

无相互依赖的工作应能并行，后续工作在必要输入满足后执行。条件分支未选择的路径不应阻塞汇合；具体汇合规则须在详细设计中明确。

### WF 06 统一修改入口

AI 和人工应通过统一平台能力提交计划变更，记录理由并校验计划版本。重复完成事件不能重复生成后续任务；冲突修改不得静默覆盖。

第一阶段允许调整尚未执行的工作。需要替代在途任务时，应先按取消与替代流程处理，并保留关联。自由修改运行中任务内容延后。

## 5 Agent Factory 与通用 Worker

### AG 01 平台内嵌 Factory

Agent Factory 应是 Control Plane 的正式模块，统一负责装配流程、配置校验和版本保存。需要智能判断时，可按需调用专门配置的 Factory Agent，并复用现有 Runtime。初期不要求独立常驻进程或长期模型会话。

### AG 02 优先复用

装配顺序应为复用已有配置、组合已有 Skills、必要时生成声明式 Skill。任务事实优先放入上下文或知识材料，重复使用的方法才考虑沉淀为 Skill，不要求每项任务生成新 Skill。

### AG 03 采用 Option B

Factory 可以生成说明、流程、检查清单、知识和输出约定等声明式 Skills；只能引用已有且经授权的 Tools。生成的 Skill 不能自行授予权限，也不能通过夹带可执行内容绕过工具授权。

### AG 04 逐任务专业配置

Worker 应能在不同任务中执行不同专业 Agent。专业能力由本次配置表达，Worker 广告其实际 Runtime、工具适配器、资源、工作空间及网络等执行条件。

专业配置可以从现有 Profile 演进，不要求同时维护一套重复体系。Python 的具体改动已识别；其他 Worker 的协议及兼容范围须实施前逐项核对。

### AG 05 调度前准备完成

计划节点可以暂不绑定具体 Skill。进入可领取状态前，必须确定专业配置版本、执行要求和实际授权；获得 Lease 后再创建 Agent 实例。Worker 不应领取后才发现已知的执行能力缺口。

### AG 06 复用执行基础

保留 Worker Pull、Lease Ownership、心跳、结果提交、取消及恢复。进程内、子进程或容器执行属于隔离策略，不形成新的组织层级。不为动态 Agent 引入 Worker Leader 或部门管理层。

## 6 秘书入口与人工交互

### HI 01 秘书为主要入口

用户主要通过秘书提出目标、参与需求讨论、查看进度和收取结果。Telegram 和聊天界面是交互渠道；控制台作为细节查看、审阅和直接操作入口。普通工作不应依赖用户持续停留在控制台。

本项为目标要求，不表示当前个人秘书已接通全部需求讨论或 Telegram 工作问答。新增接入应尊重当前用户侧私人数据边界，只将办理工作所需信息提交平台。

### HI 02 保留需求专业能力

需求讨论与需求分析职责继续保留：前者澄清意图和歧义，后者形成需求规格、约束及验收条件。秘书可组织或转交专业交流，无须额外改写每条专业回复。

### HI 03 统一问题记录

计划中的 ask 节点及执行 Agent 临时提出的问题，应关联具体工作并保存原问题、必要上下文、选项、回答和处理状态。秘书可整理展示，但应保留专业原意和用户原始回答。

不同渠道应处理同一问题，避免重复消费、关联到错误工作，或把一句“可以”扩大为一般授权。正式问题、回答和授权状态由平台管理。

### HI 04 等待与恢复

Agent 需要澄清、确认或补充条件时，应能提交请求并进入等待。等待人类回答期间可以释放 Worker 执行槽。回答作为输入恢复工作，不依赖原 Agent 会话持续存活。

### HI 05 人工控制与进展展示

执行过程中应持续展示进展、成果、问题和关键分支，并允许人插入暂停、终止及回答。无需展示模型内部推理。

暂停应阻止新的派发或推进，并明确显示在途执行情况。中断当前执行通过取消机制处理；终止任务或流程应阻止相应后续工作，且在 Worker 确认前不能显示为已经停止。暂停默认是否等待当前安全结束点、控制按钮如何呈现等细节待定。

终止不自动回滚已发生的外部操作。批准与拒绝必须绑定具体请求和范围，不能仅作为普通聊天文本处理。

## 7 成果与上下文交接

### CO 01 以正式成果交接

任务应携带目标、输入、范围、验收条件和输出约定。下游依据明确成果继续工作，无需继承上游完整对话。复用现有 TaskInput、输出模块及 Git 提交引用。

### CO 02 固定关键输入版本

专业配置、Skills、正式报告和代码等关键输入应可定位版本或内容哈希。上游更新不能静默改变在途任务的依据；受影响工作通过补充或替代任务处理。

### CO 03 简单协作

并行代码修改使用独立工作空间和明确基线，通过集成工作汇合。执行 Agent 可以报告阻塞、请求澄清或建议拆分，由统一平台入口协调跨任务影响。

成果是否需要独立审核由计划和策略决定，小任务不必强制经历所有专业角色。

## 8 授权与可靠性

工具请求与实际授权必须分开。专业配置声明所需工具，平台决定本次操作及资源范围，并在实际调用边界落实。已有任务或委托授权不能直接等同于全部工具操作许可。

AI 的计划、专业配置和报告不能自行扩大目标、权限或预算。已授权范围内可以自动推进；需要扩展时按相应策略处理。

平台重启、Worker 失联和重复事件后，应能依据持久化记录恢复或明确等待处理，不依赖模型记忆。外部操作结果不明时，应核对真实结果，避免盲目重复执行。

## 9 第一阶段验证场景

用户提出：“给 FO API 增加请求幂等控制，完成代码修改和测试，提交结果供我审核。”

平台应支持 AI 生成分析、实现、验证和交付计划；缺少业务信息时经秘书提出问题；按需装配专业配置并由通用 Worker 执行。验证通过进入交付，需要修复则经 if/goto 展开下一轮，达到限制后等待人工决定。

该场景的验收条件如下，属于后续实施验收目标，并非当前测试结果：

| 编号 | 可观察结果 |
| --- | --- |
| AC 01 | 用户只提交目标即可获得 AI 计划初稿，并能审阅或调整 |
| AC 02 | if/else 和 goto 可直接表达路径及回跳，无需循环模拟条件分支 |
| AC 03 | 独立任务能并行，依赖和条件汇合不会误提前或永久等待未选路径 |
| AC 04 | 同一个通用 Worker 可先后执行不同专业配置，保留正常 Lease 语义 |
| AC 05 | 需求或开发中的问题可经秘书送达，回答准确恢复对应工作 |
| AC 06 | 配置的外部渠道可回答同一问题，重复回答不会重复推进 |
| AC 07 | 暂停和终止及时阻止后续推进，在途状态与真实确认一致 |
| AC 08 | 修复创建新一轮任务，执行故障保留独立的 Attempt 处理 |
| AC 09 | 未授权工具及资源访问在实际执行边界被拒绝 |
| AC 10 | 重复事件不重复创建任务；重启后可继续或明确报告阻塞状态 |
| AC 11 | 交付包含代码版本、修改说明、验证证据和剩余问题，符合原目标范围 |

## 10 延后范围与待定项

第一阶段延后：永久专业 Agent 身份、独立长期记忆、Agent 自由通信网络、复杂 Skill 自动发布及晋升体系、独立 Factory 微服务、完整组织层级，以及任意修改运行中任务内容。

后续详细设计需要决定：

1. 流程的最终格式、条件字段、goto 目标与循环轮次的表示方式。
2. 并行汇合、失败分支、流程结束及取消在途分支的准确语义。
3. 专业配置、执行要求和授权与现有协议的最小映射。
4. 配置准备与 AI 规划的调用方式、模型策略及故障恢复。
5. 秘书与目标讨论、问题记录、Telegram 的具体接入方式和信息边界。
6. 暂停、中断、恢复的交互细节及默认行为。
7. 循环、成本、时间及任务数量的默认限制。
8. 当前各语言 Worker 的兼容和迁移范围；最终数据库表与迁移设计。

以上待定项不应提前固化为实现要求。当前授权范围为需求整理与设计讨论，开始编码需另行明确。
