# REQ00001 — Beautiful Web Control Plane 需求计划

批准依据：用户于 2026-10-04 在当前会话明确确认「批准需求，并将 M1 交接到 FD」。需求来源：用户请求与 [Web Control Plane Handoff](../../web-ui.md)。视觉方向已由用户在 2026-10-02 的需求讨论确认。生命周期批准状态以 `issue.toml` 的 CLI 记录为准。

本次批准确定现有需求方向，并仅交接 M1：Mission Control Overview 与共享视觉基础。M2–M4 保留为后续里程碑；其新增能力及未决范围不因本次批准而视为已确定或已授权实施。保留原 REQ ID。用户误发且随后撤回的 plugin 补充不属于本需求。

## 1. 要解决的问题

将现有 R9 Web Console 演进为好看、清晰、可长期使用的工程运维控制台。操作者进入浏览器后，应能迅速知道系统正在做什么、哪些工作在等待、哪里出了问题、哪些事项需要人处理，并沿着同一条上下文找到证据和可执行动作。

当前控制台已经提供真实数据和操作入口。首页已有积压分类、关注 Run 和 pending 审批，Run Detail 有任务表和时间线。需求重点是把分散的状态组织成“现象 → 原因 → 证据 → 可用动作”的体验。以上是静态检查结论，尚未进行浏览器可用性评估。见 [当前能力与差距](current-state.md)。

已确认的视觉方向：**未来战术游戏作为整体界面，机器生命体用于 Worker Fleet 和执行状态。首页有指挥中心的秩序，Worker 有鲜明个性，形成属于 AIW 的视觉身份。** 此确认更新 handoff 中原先的 Nebula 风格提案；保留其可读性、克制动效和工程语义原则。视觉品质和操作体验都属于首期交付。

## 2. 使用者与关键场景

| 使用者 | 场景 | 希望完成的判断或动作 |
|---|---|---|
| 操作者 | 开始工作或创建 Run | 查看当前负载与待办，提交需求并确认创建结果 |
| 操作者 | Run 没有推进 | 区分依赖未就绪、能力不匹配、Worker 容量、Run/Fleet 准入或控制策略限制，定位受影响工作 |
| 操作者 | Run/任务失败 | 关联失败原因、任务、Worker、attempt 与时间，区分租约自动恢复与人工 recover |
| 操作者 | 调整并行度或维护 Worker | 看清占用、限制、排空状态和操作后果，执行已有操作 |
| 审批者 | 工程结果等待批准 | 核对 Run、结果版本、review/verification/gate 证据，再批准或拒绝 |
| 观察者 | 监控执行 | 看懂状态与历史，角色权限与操作入口一致 |

来源：handoff §§6、8、10–17、28–29、38；角色和已有操作来自 [Web Console 指南](../../current/15-WEB-CONSOLE.md)。

“Mission”是展示用语，建议映射一个实际 Run，同时保留 Run ID 与需求上下文。此映射需在设计中明确；不新增 Mission 持久化实体。

## 5. 数据与操作规则

- Worker 权威状态为 `ACTIVE / DRAINING / OFFLINE`。Busy/Idle 可依据租约占用作展示描述，不能替代管理状态。node、健康等级或 Runtime 可用性缺少数据时不得虚构。
- Run 生命周期、控制状态与任务状态分别表达。`RUNNING` 不表示所有任务在执行；`BLOCKED` 不自动表示系统故障；`PAUSED` 是操作控制状态。
- 心跳、capturedAt、容量、会计差值可作为事实。仅加载页面成功不能宣布系统健康，未定义阈值不能宣布 Worker unhealthy。
- 当前完成比例是已完成任务数/当前任务总数；新任务或 repair 会改变分母。它不是 ETA 或整项工程完成度，gate/approval 状态另行表达。
- 汇总与截断列表注明范围；“最近 N 条中筛出的 pending”不能冒充全部待审批总数；单 Run 时间线不能冒充全局历史。
- Web 操作使用现有应用服务权威，Worker 保持 Pull；界面不能表现为 Control Plane 推送派工。
- 降低 Run/Fleet 限制采用自然排空，现有租约继续；pause 按当前规则撤销活动租约。提示必须说明不同后果。
- 租约自动恢复与显式任务失败后的人工 recover 分开呈现。cancel 不可逆；审批绑定具体版本，已决定记录不可改成相反决定。
- 页面展示不是授权依据，服务重新校验动作。过期页面遇到状态竞争时应反馈冲突/失败，不能显示假成功。
- 角色沿用 `VIEWER / OPERATOR / APPROVER / ADMIN`。当前浏览器 action controller 无 Request Repair 操作，不将示意按钮写成已可用动作。
- 可选 `/ui/**` 会话认证不自动保护管理 REST API。本需求不包含管理 API 安全改造。

依据：[工程生命周期](../../current/03-AUTONOMOUS-ENGINEERING-LIFECYCLE.md)、Web Console 指南、状态/查询 DTO、模板与查询服务；源码索引见差距分析。

## 6. 视觉与交互要求

### 整体：未来战术指挥界面

- 首页按当前行动、Fleet/容量、等待原因、人工关注和最近活动组织清楚的指挥区域；任务卡、分组面板、容量仪表和关系线具有真实信息用途。
- 深色分层面板、精细边框、局部切角与青蓝强调色形成战术 HUD 特征；具体色值、轮廓和字体由设计定义。失败/警告/成功保留一致的语义颜色。
- 技术标识选择性使用等宽字体，需求与说明优先可读；长文本保留完整阅读路径。

### Worker：机器生命体

- Worker 有可区分的机械轮廓、核心光或身份标记；同一 Worker 在首页 Fleet 区、Workers 页和执行上下文中的识别保持一致，显示实际 Worker ID。
- 角色特征可以依据真实 capabilities/runtime 等元数据设计；没有角色依据时按身份区分，不宣称 Worker 具备不存在的专业角色。
- 管理状态和工作占用分别表达。例如 ACTIVE 且无租约可用静态待命形态，存在活动租约可用局部核心脉冲，DRAINING 明示停止领取新工作并继续已有执行，OFFLINE 可用暗化形态配状态文字。
- 任务失败、等待或租约问题的提示关联真实对象，不将失败任务自动解释成 Worker 故障。执行反馈不能表现为 Control Plane 推送派工。

### 首期验收边界

- M1 的导航、Overview 各区域、任务卡、容量和关注组件形成完整一致的战术视觉；首页 Fleet 摘要与现有 Workers 页提供机器生命体基础呈现。
- M1 需展示真实数据场景、空态和失败/关注态的视觉效果；不能仅凭改了背景颜色或加了机器人图标认定完成视觉目标。
- 状态除颜色/形象外有可读文字；控件具备清楚的聚焦、提交和失败反馈。装饰不能遮挡数据或动作。
- 动效对应真实状态变化，环境动效可关闭；减少动效时仍能识别身份、状态和下一步动作。
- 窄窗口与长表格不使主要内容和动作不可访问；具体浏览器/尺寸验收矩阵由设计列出。

组合风格是已确认要求；上述形态、组件与状态映射是实现该方向的验收约束和设计建议，尚未通过界面展示或可用性评估确认视觉质量。

## 8. 约束与非目标

保持 Java 21、Spring Boot 4 / Spring 7、Maven、`me.asu.aidev` 及 Worker Pull 权威边界；handoff 指定 R9 Fix1 为接受基线。

优先单应用/单部署产物及现有 MVC/Thymeleaf/CSS/少量原生 JavaScript。HTMX、SSE、WebSocket 是设计选项，功能目标是连续且可靠的监控。来源偏好单向更新用 SSE；设计应说明对现有轮询的改善和复杂度。

可补充浏览器读取投影；领域/schema/调度权威/外部访问能力变化须写清必要性与影响。首期不包含桌面 Companion/pet、中央进程调度器、Worker Runtime 重写、3D/粒子特效、PR/部署/回滚自动化、审批政策编辑或任意配置管理。

全局历史搜索、完整 claim 决策回放、新健康告警规则、外部制品全文/下载不能从菜单草案自动推导为已承诺交付。

## 9. 来源差异、假设与待定事项

视觉方向已按用户最新确认更新为“未来战术游戏整体界面 + 机器生命体 Worker/执行表达”。`docs/web-ui.md` 中的 Nebula 是历史提案，发生风格差异时以本次确认及本计划为准。

1. handoff §10 示意图把 integration 放在 review/verification 之后；当前 lifecycle §§5–6 描述 integration 结果进入最终 review/integration verification。需求采用后者，设计再核对真实依赖，示意图仅为视觉参考。
2. handoff §§8、11 的百分比和 Worker 健康状态是草案；实际代码只有任务完成比例和三种 Worker 管理状态。它们不能自动形成预测/告警规则。
3. handoff §2 记录用户接受 R9 Fix1，旧 release 记录说明生成环境未跑 Maven。属于不同时间/环境的证据；本次引用 handoff 的接受基线，不声称当前工作区重新验证通过。
