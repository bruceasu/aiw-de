# Worker 技能方法吸收说明

FD-038 比较 `.agents/skills` 的 27 个技能入口与平台技能库，按执行角色适配方法。宿主 FD 流程适合管理从规划到本地交付的完整工作；平台 Worker 的优势是固定输入/技能版本、单任务职责、工具准入和正式结果。两者适合互补，不能把宿主权限一同复制给 Worker。

平台此前已有拆分、四维审阅、测试预期值推导、诊断和冲突处理方法。本次补充任务内步骤、交接及证据失效、决策聚焦、验收变化影响和 Skill 内容编写；不是重新导入一套重复流程，也未验证模型产出质量一定提高。

## 来源与去向

表中“已有”表示保留原方法；“增量”表示本次补充；“排除”表示该宿主动作不成为 Worker 能力。27 个入口均分类；重点对比读取 FD 共享 workflow/testing、handoff、writing-great-skills、grill-with-docs、设计及诊断等相关正文，未把所有入口的全部辅助资源当作已逐字审计。

## Worker 如何使用

编码者在原报告/交接的描述字段内记录少量有验收对应的步骤、已完成结果、阻塞和下一步。开始或续行先核对正式任务版本、工作区/代码基线与原操作结论。局部清单是派生说明，不是平台持久 TODO，也不证明每个步骤已被强制执行；不要求每个工具调用产生一份文档。

需求、设计、规划、审阅、验证只加载本角色相关的方法段落。目标讨论直接在原 REPORT 中给澄清建议；它不执行代码、创建流程或批准范围。存在未决项时独立工作可以继续，但不得把受阻验收项标成完成。

Skill 编写参考仅在任务本身涉及 Skill 内容时加载；不会因为发现可复用知识就写入共享库。工厂仍只组装已登记配置，工具与生命周期权限不由提示授予。新文本保留原 Artifact/REPORT/VERDICT 格式，不新增顶层输出字段。

## 资源与验证边界

平台规范源仍为 `src/main/resources/worker-skills/`，新增辅助文件进入显式 `index.json`，本次改动同步到三语言同名独立部署副本。受影响包会有新的 `files-<manifestDigest>`；旧任务、重试与正式续行继续使用原冻结文件，不被本次覆盖。

`execution/software-catalog.json` 保留既有文本资产版本/摘要，原文本合同与新文件集版本分别核对。目录中的旧文本不是新提示全文；支持平台文件集的 Worker 使用 Claim 固定字节。旧独立部署使用更新后的本地副本，版本选择仍依其原合同。

静态路径/摘要/副本检查和离线生产资源编译只能支持结构一致性；未运行模型对照评估、真实 Worker、恢复、工具、测试或发布验证。若要比较方法效果，需要另行授权代表性任务的有界评估，不能凭提示文件更新宣称效果提升。
