# Worker 用量和价格记录设计

状态：设计草案，尚未实现。适用于 Python API Worker 和 Plane；Codex app-server 的内部用量无法观察时保留未知。用户已确认内部价格表、缺价回填及由 Worker 修复采集程序的方向。

## 目标

在任务、Plan、Worker 和时间维度查看模型调用次数、输入／缓存／输出 token 及可计算的估算费用。独立记录未知用量和未知价格，不能将缺失值记为零。ChatGPT 订阅连接记录可观察用量，但不按 API 价格声称其实际账单。现有受控执行计量继续工作；普通工厂任务也需要接入统一统计。

## 调用记录

- 每个模型请求以 attempt 和稳定的请求标识去重，记录提供方、连接类别、模型、协议、请求时间、完成或未知状态，以及提供方返回的各项 usage；不存令牌、密钥、提示词或工具内容。
- 本地摘要请求同样计入；响应未知、缺少字段或连接中断时保留已知部分和未知状态。重试不得重复计算同一请求，不能因为终止或租约丢失而丢弃已确认用量。
- 本地 Worker 与 Plane 之间需使用现有租约身份验证、幂等收据和有界队列；不可假定所有任务都有 GuardBroker 或运行通道。多 Worker 并发上报须保证聚合一致。
- 费用是估算值，须保存计算时使用的价格版本及适用条件；已计算的历史请求不得被每日价格更新悄悄改写。服务商真实账单或账户折扣另行核对。

## 价格更新

Plane 启动后在后台尝试一次，之后每 24 小时执行一次；失败不阻塞启动、任务或已有数据。多 Plane 部署应有数据库协调，避免重复覆盖；设置网络超时和响应大小上限，不发送 API Key、任务或账户内容。

每个来源独立更新：将抓取结果转换为本系统内部价格表，保存来源 URL、抓取时间、内容摘要、解析器版本、适用条件及校验状态；仅在完整校验成功后原子发布新版本。抓取失败、格式变化、解析不完整或价格冲突时保留上一次有效版本并显示更新时间和错误；没有有效价格时显示未知。需要支持人工维护及禁用自动更新。

先支持 OpenAI 和 DeepSeek 的官方价格信息，其他提供方通过独立适配器扩展。不能假定 `/models` 接口有价格：OpenAI 的模型列表只列基本模型信息。官方价格页可能改变页面结构，解析器不能只依赖模型名称或任意一行数字。缺少可验证价格时不发布推测值。

内部价格表至少区分提供方、具体模型或明确的别名规则、币种、计量单位、普通输入、缓存命中输入、输出、服务档位、上下文区间及生效条件；需要时支持缓存写入、区域和其他收费项。每条价格可有生效起止时间，并可指定重复出现的星期、时段与时区，用于峰谷价格；按请求发生时间和请求条件匹配，区间边界必须明确且同一条件不能出现歧义。若无法精确匹配请求的适用条件，应显示估算不完整或价格未知。抓取时间不是服务商宣布的生效时间，不能用于凭空追溯历史价格。

## 缺价与回填

缺少价格时先保存请求、时间和可获得的 token，用量与价格分别标记；估算金额留空，进入待计算队列。新价格发布、修正或人工补录后，按提供方、模型、实际请求时间及适用条件查找匹配项，幂等地重算可回填记录，并记录使用的价格版本、计算时间及依据；多次触发或多个 Plane 并发不能重复记账。

历史价格区间没有依据时，继续显示缺价；如提供当前价格供参考，应单独标为参考估算，并保留原来缺价事实，不能作为当时的确定价格。获取到历史价格或其生效区间后再计算。用量本身未知时补价格不能产生完整费用；订阅连接仍不转换成实际 API 账单。

新账本的估算与既有受控 `execution_meter`、预算预留、人工核对值分开保存。自动回填不覆盖人工确认的实际费用、不释放既有未知预算预留；需要统一核对时应按明确的对账流程处理。结果及其价格版本可追溯，手工修正或价格更正保留版本历史。

## 采集程序自动修复

区分临时网络、限流、来源不可达与页面结构或解析合同变化；临时故障按有界重试等待，不因每次连接失败启动 Worker。当原先正常的来源出现持续且可复现的格式变化时，按来源和失败指纹去重创建一个修复任务，附带来源地址、必要的失败摘要、已保存的公开页面样本、旧解析规则和最后成功版本；不附带密钥、模型请求或用户数据。

Worker 搜索并核对服务商当前官方价格页面，分析新的字段和计价条件，在限定工作区修改对应采集小程序，补充针对新旧公开样本的校验，并汇报来源、代码改动、执行结果及尚未支持的情况。用户授权该修复过程；具体工具和涉及工作区外、不可恢复删除等操作仍按现有 Worker 规则处理。

采集修复不得直接把未校验的数字写入正式价格表。修复结果通过解析、价格条件、旧样本及回填相关检查后，按项目既有交付机制更新程序并原子启用新采集器，再尝试抓取；失败则保留旧版本与未知记录并报告。单来源同一故障只有一个活跃任务，失败或无 Worker 时有界退避并显示状态，不能无限新建任务；新的来源变化可形成新的修复任务。Worker 恢复服务后不自动假定原修复已成功。

依据：[OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、[OpenAI 价格](https://developers.openai.com/api/docs/pricing)、[OpenAI 缓存计价](https://developers.openai.com/api/docs/guides/prompt-caching)、[DeepSeek 价格与峰谷时段](https://api-docs.deepseek.com/quick_start/pricing/)。

## 展示和预算

执行记录按请求、尝试和 Plan 展示用量与估算费用，标出用量缺失、价格过期、适用条件不完整及订阅连接；提供来源和价格版本。不同币种不能直接相加。用户自定义模型无价格时仍可记录用量。

预算在准确记录的基础上作为独立策略：默认仅显示和提醒；用户可选任务或 Plan 的 token／费用限额。预留、并发、单次请求可能超出剩余预算、未知费用和人工继续的处理须明确；不能宣称预留额度是精确的实时计费上限。预算控制不得复用尚未匹配适用条件的估算金额作为确定费用。

## 实施与验证顺序

1. 定义并持久化请求级用量和价格版本，覆盖普通与受控 Worker，保证兼容已有计量记录、租约及重复上报。
2. 实现内部时间段价格表、可独立验证的来源适配器与后台刷新，使用保存的官方页面样本检查解析、格式变化、峰谷条件、失败保留、启动与每日调度。
3. 按请求关联价格版本，对缺价记录进行幂等回填，并在执行记录和 Plan 汇总展示未知值、订阅和币种；不覆盖历史结算值。
4. 实现来源异常去重、Worker 修复任务与验证后交付，验证普通网络失败不会触发修复，旧采集器和旧价格在修复失败时仍可保留。
5. 单独实现可选预算与并发预留，验证未知用量、停止和恢复等边界。

每步需要离线针对性验证；真实服务商、网络和浏览器验证遵循用户的单独授权。现有 `execution_meter`、`execution_budget` 和价格快照不能替代普通任务的请求级记录。
