# Agent 执行与协作改进清单

本清单基于 HelloAgents 本地实现、课程案例及 AIW-DE 当前执行路径。它接续原有 37 项优化，聚焦 Worker 能否交付、用户能否观察和恢复，以及经验能否帮助下一次工作。表中编号用于讨论顺序，正式设计通过后再关联 FD。

已有基础包括简单任务、统一 SDK 工具执行、任务级授权、原尝试恢复、正式交接、成员经验与 Skill 版本。FD-132 的长报告交接和恢复页面已经在本机模拟场景通过，真实 Plane 调度和在线模型仍有待独立验证。此前新闻任务通过实际 Worker 完成 JSON 导出，可作为对照样本之一。 [架构评审](research/hello-agents-architecture-review-2026-11-21.md) · [FD-132 归档](features/archive/FD-132/index.md) · [原功能清单](FUNCTION-INVENTORY.md)

## 执行质量与可恢复性

| 顺序 | 改进项 | 现有基础与拟改动 | 验收要点 |
|---|---|---|---|
| 01 | 完成条件与可核对回执 | 已交付。简单任务可选填验收条件，文件任务可选必需检查。Worker 和 Plane 核对同次尝试的命令回执。详见 [FD-133](features/archive/FD-133/index.md)。 | 编译、离线回归和独立复审通过。真实命令审批及新闻情景待验收。 |
| 02 | 任务详情的当前工作与恢复 | 已交付。任务详情显示最新尝试的阶段、最近结果、联系时间与工作台直达。受控 Python Worker 在工作区准备前开始上报。详见 [FD-134](features/archive/FD-134/index.md)。 | 编译与独立复审通过。初轮定向用例通过，复审后新增断言、浏览器和真实 Worker 待运行。 |
| 03 | 复杂任务的轻量工作清单 | 已交付。受控 Python 文件任务可选用五项清单。任务详情显示本次进度，Worker 在历史压缩后保留当前清单，重试可参考旧清单。详见 [FD-135](features/archive/FD-135/index.md)。 | 编译、14 项离线用例和独立复审通过。实际 Plane、浏览器和在线模型待验收。 |
| 04 | 用任务进展判断重复与停滞 | 已交付。移除固定只读轮数提醒，重复读取或重复已确认的失败先提醒再停止。新证据和人工补充可重置判断。详见 [FD-137](features/archive/FD-137/index.md)。 | 编译、15 条监测用例和独立复审通过。真实 Worker 与浏览器待运行。 |
| 05 | 缩短普通任务的开工路径 | 已交付。通用 Python OpenAI 文字任务可在独立目录开工，保留报告交接和问答续接。任务详情分开显示领取、准备和首次模型耗时。详见 [FD-138](features/archive/FD-138/index.md)。 | 编译、6 条定向用例和独立复审通过。真实耗时对照待验证。 |
| 06 | 提示、Skills 与工具按需加载 | 已交付。SDK 按任务与已授权目录提供工具，Skill 资源随绑定包提供，资料和长结果可按需读取。详见 [FD-139](features/archive/FD-139/index.md)。 | 编译、8 条定向用例与独立复审通过。真实模型使用待验证。 |
| 07 | 运行证据与最小质量对照 | 复用现有用量账本、导出和可控测试。先固定输入、模型、可用工具与通过条件，再比较调用、等待、返工和结果。 | 至少覆盖文字任务、小型代码产物、中断恢复三类。分别记录平台、模型和产物失败。缺失用量保留未知。 |

## 成员协作、知识与产品流程

| 顺序 | 改进项 | 现有基础与拟改动 | 验收要点 |
|---|---|---|---|
| 08 | 一个可复用的「实现 → 验证」工作流 | 已交付。可保存、选择成员并重复执行 JSON 生成与验收示例。详见 [FD-141](features/archive/FD-141/index.md)。 | 验证读取前序正式报告，退回须由用户决定后续操作。语法和调用链静态核对通过，浏览器及模型对照待运行。 |
| 09 | 工作流结构与角色分配 | 已核对。统一页面使用现有角色和人工变更确认。图服务仍供软件交付 API 和恢复调度使用。详见 [FD-142](features/archive/FD-142/index.md)。 | 声明出口、结构确认及实际调用关系已静态核对。 |
| 10 | 项目知识、成员经验按相关性召回 | 已交付。声明项目位置、Skill 和关键词决定共享经验的召回，工作流分发时固定结果。详见 [FD-143](features/archive/FD-143/index.md)。 | 离线编译、相关性和来源授权的定向用例通过。 |
| 11 | 任务复盘与 Skill 演进 | 已交付。经验随正式推进沉淀，Skill 修订绑定任务实际使用的版本及修改依据。详见 [FD-144](features/archive/FD-144/index.md)。 | 离线编译和延迟结算用例通过。旧版本建议不会覆盖新版本，历史与回退继续可用。 |
| 12 | 秘书独立澄清与引用 | 秘书已有本机知识搜索、会话与委派。复用许愿池的需求澄清方法、知识引用和缺项提示，再按用户意图把确定的材料交给 Plane。 | 不委派也能完成一份需求草稿；引用可定位所用资料版本；状态未知的委派可核对且不会重复提交。 |
| 13 | 统一 Python 执行边界 | 先对齐 SDK 各模型连接的状态、工具调用、取消及交付语义。根据 04、06、07 的证据评估是否需要宿主控制更多回合逻辑，再决定是否替换 SDK Runner。 | API Key 和 ChatGPT 连接共用任务与工具语义；协议差异在模型连接处理；Codex app-server 可作为备选。 |

开放式多 Agent 聊天、动态团队协调、向量或图检索、重新实现模型 Runner 都属于后续候选。分别以 08 的协作结果、10 的知识召回结果、13 的运行证据决定是否展开。当前优先用现有调度、SQLite、事件与交接完成第一个可验证的版本。

第 07 项的[离线质量基线](WORKER-QUALITY.md)已交付。固定的文字开工、文件交付和中断重试用例通过，真实等待、模型用量及费用待实测。其余项目依表中顺序逐项设计与验证。
