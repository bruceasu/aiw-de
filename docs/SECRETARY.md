# 秘书工作安排

在 Web Console 导航进入 **Secretary**。新建工作，填写说明后保存；可以发送消息与秘书讨论。
讨论仅提供建议，必须显式保存内容并确认安排。每个工作项有独立消息上下文，进度从真实任务记录读取。

首期支持已由当前控制台用户创建的草稿 Plan、本地站内提醒及进度查询。Plan 在 New Plan
编辑器中准备，保存到秘书后会由秘书托管；原来的确认、跳步、重试和返工入口不能绕过安排。
未托管的旧 Plan 保持原有流程。没有对应 Worker 的工作会等待，不能当作已经开始。

安排时间使用明确日期、分钟、偏移量与 IANA 时区，例如 `2026-10-23T15:00+09:00` 和
`Asia/Tokyo`。偏移必须属于该时区的有效偏移；DST 重叠时间用偏移明确选择。
到期表示协调请求入队；目标分钟内的秒级扫描偏差正常。停机、休眠或扫描延迟错过目标分钟后，
必须重新查看内容、选择时间并确认，不自动补跑。改期可重新确认未触发安排；修改并保存内容会使旧确认失效。

页面展示保存内容及关联 Plan；确认同时核对显示的版本和摘要。旧协调响应及重复确认不会重复委派。
已入队或活动工作不能直接改写；取消后准备新工作及新的草稿 Plan，不沿用旧确认修改执行内容。

取消会阻止新的领取和推进；旧 READY 记录可能保留作为证据。已领取或正在执行的任务显示
STOP_REQUESTED，须到对应 Plan/Task 使用现有停止控制核实结果，不承诺已经停止或回滚。
任务仍可报告真实完成/失败。失败或租约中断的专业动作不会自动重做，应核实原结果后人工处理。
协调本身失败或请求人工时，可在页面明确选择 **Retry coordination only**，只重新请求对未改变
Plan 的只读协调，不重试专业动作。站内反馈不代表外部主动通知；分析由用户自行发起。

新增角色在 `extern-workers/process-typescript` 提供：`secretary`（secretary-chat）和
`plan-coordinator`（plan-coordination）。使用现有 run-role.ps1/run-role.sh，分别选这两个角色，
并显式选择已有 `codex-cli`、`codex-app-server` 或 `openai-agents` 后端。
使用不同 Worker ID；平台禁止同一个 Plan 的协调 Worker 兼任专业执行或评审。start-all 会包含
两个新角色，启动前按现有操作说明准备凭据和运行依赖；本次实现没有启动 Worker 或下载依赖。
Python/Go Worker 本次未增加这两个角色。

数据库 V8 仅新增秘书表，不迁移历史归属。无认证时沿用共享的 `web:local-console`，不是多租户隔离。
到期及每次领取/协调消费会核对当前控制台认证模式、配置用户名和操作角色；改变这些配置使旧授权失效。
升级前备份数据库；Flyway 随原有启动流程向前应用 V8。回退前设置 `aidev.secretary.enabled=false`
停用时间扫描，停止秘书 Worker 并处理在途任务；保留新增表和原始证据，不手工删除或回填记录。
默认应用每 5 秒扫描一次，每次最多读取 100 个到期安排；所有秘书写入通过单机互斥行串行化，
不面向多节点高吞吐。配置扫描间隔不能改变“错过目标分钟须重新确认”的规则。
