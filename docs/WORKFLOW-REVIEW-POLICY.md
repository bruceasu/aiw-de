# Plan 评审策略

flexible Plan 的普通步骤可以自检，阶段成果集中评审，高风险改动独立评审。策略在草稿中明确选择，确认后固定；Worker 的报告和问答回答不能修改它。

| 方式 | 何时推进 | 是否创建 Reviewer |
| --- | --- | --- |
| SELF 自检 | 实际执行完成、报告 PASS | 正常成功时不创建 |
| MILESTONE 里程碑 | 阶段成果评审 PASS | 覆盖上一个评审边界后的普通步骤及本步骤 |
| INDEPENDENT 独立评审 | 本步骤的独立评审 PASS | 对当前步骤创建，保留必要上游背景 |

只有明确标为 LOW 的普通工作可以选择 SELF/MILESTONE。HIGH 或 UNKNOWN 始终要求 INDEPENDENT。风险由确认者结合工作范围声明；平台不声称自动识别所有高风险代码。权限、计费、持久化/迁移、事务、并发、部署或未知影响应保留独立评审。

在 Plan 编辑器中，可逐步选择风险和验收方式，也可明确点击“设置普通阶段评审”：高风险步骤保留独立评审，每段普通步骤以里程碑结束，中间步骤自检。此动作会先要求确认风险声明；不会因缺少评审 Worker 而降低要求。确认执行前的摘要会列出固定策略。

SELF 的 REPAIR_REQUIRED 不等于成功，也不自动派新任务。当前槽可以由有权操作者基于精确 Plan/task 版本请求一次独立评审，或明确授权一轮修正。已进入评审纠错的步骤必须完成受影响范围的独立复查，不能在修正后改走自检。

最终步骤可以按明确的 SELF 策略交付自检结果，页面不会标为独立评审通过。自动完成仍核对实际成果、当前槽、必要评审和未结束资源；既有管理者明确停止/手工结束作为另有来源的控制事实保留，不生成虚假的独立 PASS。

旧规范未提供新字段时，继续解释为逐步独立评审；其读取和重新编码不插入新策略字段，保持既有冻结规范摘要。新字段使用现有 spec_json，不批量改写历史。configured-plan 工厂的既有独立验收门禁保持不变。

升级应先 drain。旧服务不认识新策略，不能在新策略 Plan 仍可领取、执行或待恢复时降级；不得通过删成果、问题或审查记录回滚。此说明不代表真实升级或平台联调已验证，实际证据以 FD-080 为准。
