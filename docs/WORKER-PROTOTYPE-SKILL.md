# 给现有 AI Worker 配置原型制作技能

`prototype` 是可选附加 Skill，不是 Worker 类型、主角色或新进程。既有编码/执行方法可以组合它，继续使用原来的 API 或 Codex 运行方式、代码基线、输出协议和权限。

## 配置步骤

1. 打开 `/ui/configurations`，进入“自定义工作方法”，选择目标仓库和适合任务的基础方法。实际制作文件应选择可写方法，并具备当前仓库的写权限；只读方法不会因勾选 Skill 而变成可写。
2. 在附加 Skill 列表勾选 `prototype`，可补充本次原型要回答的问题、使用者、范围、完成标准以及希望比较的方案。预览并保存工作方法。
3. 点击“用于准备任务”，核对原计划、同一仓库、起始版本和已批准模型，再准备任务。技能随这份固定方法装配给兼容 Worker；不需要部署另一个“原型 Worker”。
4. 若要 Worker 运行或预览演示，原方法需声明对应工具需求，原政策需允许具体命令或预览操作。当前受控命令仍按登记的命令配置执行；勾选技能不自动提供 shell、浏览器或运行服务的权限。

准备成功只表示任务已创建；使用原任务进度和正式交付核对结果。额外 Skill 从平台公共资产目录自动进入现有选择项，本次未增加新的页面、配置 Schema 或 HTTP 接口。

## 两种按需方法

| 任务问题 | Skill 指导的实际产物 |
| --- | --- |
| 状态、规则、API 或数据模型是否合理 | 最小逻辑模型和可交互的文本入口；展示当前状态、可用动作、拒绝原因、重置及退出方式 |
| 页面如何组织、交互如何工作 | 复用现有视觉风格的可运行 UI 原型；需要比较时提供有结构差异的变体、切换和可观察的模拟交互 |

Worker 先明确问题，再制作最小原型，使用内存/模拟数据，提供实际文件位置、单一入口或启动命令、交互/重置说明，并在原报告内给出观察、建议与未验证项。只加载与当前问题相关的 UI 或逻辑参考。

任务没有执行权限时，可以交付原型代码及启动说明，明确标记未运行；没有写权限时应报告缺口，不能声称已制作文件。真实数据库、外部写入、下载依赖、启动服务或浏览器操作均沿用原有授权边界。

原型支持设计判断，不代表生产验收。不会因选中方案而自动合并、发布、删除其它方案或创建分支。推广到生产与清理保留正常任务决策和权限。

## 装配与版本

平台资源为 `worker-skills/prototype/SKILL.md`、`references/logic.md`、`references/ui.md`，显式加入文件清单。目录新增公共 `prototype-v1` 文本资产及摘要；原有九个资产、十一份主方法和配置协议保持。

已有组合链把附加引用加入方法的 protocolSkills 和固定 Skill 集合，SkillFiles 按原规则保存完整文件。原主 primarySkill/角色保持；`index.profiles` 不新增 prototype。已创建任务和原配置不被自动改写；三语言独立部署副本与平台资源保持一致，但动态配置执行仍遵守现有语言/后端支持范围。

本次只增加技能和装配资源。静态/离线编译不证明真实模型、工厂实例、选择页面、Worker 或原型预览已经运行通过；部署更新后新任务才能按正常流程使用它。
