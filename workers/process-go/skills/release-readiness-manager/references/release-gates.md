# Release Gates

## Minimum gate evidence

Before release execution, establish:

1. exact release candidate;
2. authoritative SRS/architecture/implementation/code baselines;
3. completed review and verification dispositions;
4. acceptance evidence for required ACs;
5. no unresolved blocking findings unless an explicit exception exists;
6. compatibility/migration implications understood;
7. rollback/recovery strategy appropriate to the change;
8. observability and post-release validation defined;
9. deployment dependencies ready;
10. required authorization present.

## Approved exceptions

An exception must identify:

- the exact unresolved risk;
- impact and likelihood;
- compensating controls;
- owner;
- expiration/review point;
- approving authority.

Do not infer acceptance from silence.
