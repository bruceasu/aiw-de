# Teach

Use when the assigned task asks for an explanation, learning material or help
understanding a concept. Do not turn every engineering result into a course.
Keep the primary role, frozen task, available sources, tools and result format.
If the request needs a different primary role, report that gap through the
normal task path instead of replacing the assigned responsibilities.

## Choose one learning goal

Use the learner's stated goal, level, prerequisites and available time. If these
are missing, infer a modest level from the supplied question and label that
assumption. Ask only when the missing answer materially changes the lesson;
use the existing question mechanism if available. Do not invent learner history.

State what the learner should be able to explain or do after this unit. Ground
the content in permitted, reliable materials and cite the relevant sources or
code examples. Separate a simplified teaching model from actual system behavior.

## Build the learning unit

1. Start with the goal and connect it to something the learner already knows
   from the supplied context. Name only prerequisites needed for this unit.
2. Explain the central idea in plain language. Introduce terms as they become
   useful; show how the parts connect rather than listing definitions alone.
3. Work through one concrete example step by step. Explain why each decision
   follows from the rule, then show a nearby counterexample or common mistake.
4. Add a short retrieval or application exercise: ask the learner to predict,
   explain, diagnose or produce something without copying the example. Provide
   a separate answer guide with reasoning and useful feedback for likely errors.
5. If real feedback is supplied, diagnose the misunderstanding and adjust the
   next example. Distinguish observed answers from hypothetical learner responses.
   Without feedback, offer the exercise and self-check; do not claim mastery.
6. Give a small next step. Suggest spaced recall or mixed practice when useful,
   but do not create schedules, persistent course state or a learner profile.

## Deliver and finish

Use the primary task's existing output fields for the goal, lesson, worked
example, exercise, answer guide, sources and next step. Make the material useful
as delivered. An optional document or interactive example needs assigned write
scope and any execution/preview permissions; otherwise provide the lesson in
the report. Label runnable examples as unrun unless a permitted check occurred.

Completion means the requested learning unit is delivered and its evidence and
limits are clear. A quiz suggestion is not a measured learning outcome. Do not
install course tools, browse without an adapter, create a teaching workspace,
contact communities or run demonstrations merely because this Skill is selected.
Keep claims about understanding, practice results and system behavior tied to
what was actually observed.
