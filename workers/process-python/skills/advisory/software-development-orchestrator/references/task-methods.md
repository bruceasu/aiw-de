# Coordination and decision routing methods

Use for the assigned advisory coordination question. This package remains non-executable;
no FD runner, CLI workflow, or second scheduler is introduced.

- Start from the goal, confirmed decisions, exact evidence, and unresolved prerequisites.
  Separate discussion dependencies from the authoritative executable DAG.
- Identify the earliest owning layer: requirement, architecture, planning, implementation,
  verification, permissions, or environment. Return the question/action to that owner.
- Distinguish duplicate, already satisfied, deferred, and rejected requests using supplied
  evidence. Preserve original intent and earlier rationale; age is not priority.
- Recommend independent next actions only when their prerequisites are settled.
  Block only the affected scope; do not silently resolve a human policy decision.
- Reuse confirmed answers and prior diagnosis. Do not repeat interviews, convert every
  unknown into a task, or reset test/repair budgets by choosing a different specialist.
- Keep the continuation brief concise: exact current outputs, decision sources,
  missing evidence, next owner/action, and remaining permission/budget.
- A proposed role sequence is not dispatch or DAG readiness. Do not call aiw fd,
  issue commands, Git delivery, external trackers, or another agent automatically.

Check recommendation/source alignment and preserve the existing action-proposal format.
